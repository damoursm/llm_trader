# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository. It documents what is in production now; deep rationale and one-off analyses live in `memory/` and the module files.

## Running the pipeline

```bash
python main.py                # Run once, console output only
python main.py --email        # Run once and send email report
python main.py --schedule     # Start the poll-loop runner (see below)
python main.py --supervise    # PRODUCTION (scripts/run_scheduler.bat): --schedule under an auto-restart supervisor
python main.py --dashboard    # Read-only monitoring dashboard (Plotly Dash via waitress; in-process auto-restart)
python main.py --backfill     # Pre-warm OHLCV caches for the whole universe via Massive/Polygon, then exit
```

**Scheduler (`--schedule`)** ticks on NYSE market days: RTH every 30 min 9:30–16:00 ET, extended ticks 4:00–19:50, and overnight ticks 20:30–03:30 hourly on the overnight venue's Sun–Thu-night calendar. Emails fire at `scheduler_email_times` slots (default 04:00/09:30/16:00/19:50 ET); `scheduler_email_every_tick` overrides → every slot (**this is the live production setting, `SCHEDULER_EMAIL_EVERY_TICK=true`**); empty `scheduler_email_times` → only the 16:00 close. `email_on_problem` (default ON) forces an out-of-schedule email on any broker/LLM/price health problem. Once per market day at/after `eod_maintenance_time` (16:20 ET) the loop runs EOD maintenance off the time-critical path (`enable_eod_maintenance`): forward-return OHLCV cache warm (`data/cache_warm.py`), `simulated_trades` retention (`db/retention.py`), replay materialisation, walk-forward calibration, and auto-refactor. **Since 2026-08-11 the EOD block runs in a BACKGROUND thread** (single-flight guard like the nightly rescore; `runner._eod_work`: cache warm → retention → replay, then walk-forward ∥ ML retrains in parallel) — the 2026-08-10 incident where a >5.5h inline EOD starved the extended+overnight sessions cannot recur; a still-running EOD at the next day's slot is warned and skipped, and `eod_replay_refresh_days` (45) remains the size knob.

**`--supervise`** relaunches the scheduler if the process dies (e.g. the broker-sync watchdog's `os._exit(1)`). A HANG (frozen process that never exits) is NOT caught by `--supervise` nor Task-Scheduler restart-on-failure — both need the process to actually exit; the broker watchdog turns that hang class into an exit. **To STOP a supervised scheduler: kill the `--supervise` parent FIRST (so it can't respawn), then the `--schedule` child.**

`--backfill` is additive (merges into `cache/ohlcv/`, never deletes); add `--backfill-30m` to also warm the 30-min cache. Standalone: `python -m src.data.backfill [--days 730] [--with-30m] [--skip-daily] [--signal-days 90]` — `--days 7300` maps to the `20y` period (Polygon serves 2006+; **the cache is full-depth since the 2026-08-08 deep backfill**: ~5,000 bars for ~950 names, median ~2,265). Weekly is resampled from the daily cache on demand. 30-min depth is Polygon-capped (~120 days).

Logs → `logs/llm_trader_YYYY-MM-DD.log` (7-day rotation). HTML report (when `ENABLE_CHARTS=true`) → `logs/report_YYYY-MM-DD_HHMM.html`. To force a fresh run ignoring caches, delete `cache/news_*.json` and/or `cache/snapshots_*.json`. **The OHLCV cache (`cache/ohlcv/`) and the DuckDB database (`data/llm_trader.db`) should never be deleted casually.**

**Trailing-NaN bar guard** (`cache.trim_trailing_nan_bars`, applied at PARSE time inside `load_ohlcv`; `market_data._trim_trailing_nan_bars` is the alias called first in `_drop_forming_bar`). yfinance appends a NaN-Close row for the still-forming bar (~1% of cached daily frames), and an indicator handed one silently returns a different number (measured to flip `tech`'s sign). Only the trailing bar is trimmed and only on a missing Close; interior NaNs are left alone. The guard lives at the market_data boundary — scoring must never bypass `get_history`. Tests: `tests/test_scorer_contract.py`.

**Intraday operation (no unclosed-bar look-ahead).** The pipeline marks and fills on **live** prices (`_fetch_price` → `fast_info.last_price`); the daily OHLCV feeding indicators is completed-bars-only — `market_data._drop_forming_bar` removes the still-forming current-session bar until the 16:00 close. Open-position NAV is marked to the live price each tick. A **Hybrid** intraday-timing overlay (`src/signals/intraday_timing.py`) affects entry/exit *timing* only: it defers an entry whose 30-min momentum strongly opposes it (`enable_intraday_timing`, default on) and can close on a hard intraday reversal (`enable_intraday_exit`, opt-in → `exit_reason = "intraday_reversal"`). It never changes the daily-signal direction.

**Extended hours (Phase 1 — TRADING, on by default).** `extended_hours_mode` = `off | observe | trade` (default **`trade`**). The runner ticks the full extended day per `extended_windows` (default `04:00-07:00@60,07:00-09:30,16:00-17:30,18:00-19:00@60,19:50-19:50` ET — the `@MM` suffix sets a per-window cadence; a window with equal endpoints is a single slot). The last after-hours tick is 19:50 (leaves a pre-close buffer for order submission). In **trade** mode extended slots are full trading ticks (`_tick_plan` in `runner.py`): ledger entries/exits/marks and broker paper orders happen off-hours too; in **observe** mode they run `run_pipeline(observe_only=True)` (analysis + DuckDB persistence, zero ledger/broker mutation).

**Overnight session (TRADING, on by default).** `overnight_hours_mode` = `off | observe | trade` (default **`trade`**) makes the overnight session (20:00→04:00 ET) a first-class trading period on IBKR's overnight venue — Sun–Thu nights, 20:00–03:50 ET (`market_calendar.is_overnight_session_open`; Fri/Sat/holiday-eve nights have no session). Slots from `overnight_windows` (default `20:30-23:30@60,01:00-03:00@60,03:30-03:30`). Overnight trades carry the harshest terms: modeled spread ×10 (`spread_overnight_multiplier`), sizing ×`overnight_size_multiplier` (**0.25**), actionable threshold bumped +10 pp (`overnight_confidence_bump`, replaces — not stacks with — the extended +6 pp). **Broker overnight** routes to IBKR's overnight venue (`broker_overnight_routing`, default on → contract exchange `"OVERNIGHT"`, LMT-only, cap `broker_limit_cap_bps_overnight` = 150 bp); requires the gateway's API precaution bypasses in `C:\IBC\config.ini` (`BypassOrderPrecautions=yes` + `BypassRedirectOrderWarning=yes`), which IBC re-applies at every launch. A genuinely-refused overnight order counts as `overnight_deferred` (INFO log, resubmitted at the 04:00 pre-market open, not a reject).

**Session classification** (`market_calendar.current_session` → `rth | extended | overnight`) is fixed once per run. `enable_extended_signal_profile` (default **OFF**) governs whether the session changes the SCORE. With it OFF (default) scores are comparable across the trading day: one fixed weight profile every session, `ext_gap` in the active method set in all sessions (reads 0.0 in RTH by design), no session-context prompt block. With it ON it restores the extended signal profile (options-method weight ×0.5, news/gap ×1.25, session-context prompt block). Independent of the flag (gates/sizing, not scores): `extended_confidence_bump` (+6 pp) and `extended_size_multiplier` (×0.5 off-hours sizing). The **ext_gap scorer** (`src/signals/extended_session.py`) is live extended print vs last completed close in ATR units, always 0.0 during RTH, fail-closed on a stale cache.

**Extended trade lifecycle.** `_execution_iso()` returns *now* during RTH, extended-trade-mode, and the live overnight session (real fills); closed-venue nights, weekends, and observe-mode timestamps snap to the next regular open. Every entry stamps `entry_session` (+ its sizing haircut); every close stamps `exit_session`. Costs are session-aware end to end (spread ×4 extended / ×10 overnight via `spread._session_spread_multiplier`; per-leg costs in `_pct_return`, daily-NAV anchors, `_normalize_closed_returns`, `_flip_trade`, live M2M). **Broker off-RTH:** `reconcile.sync()` forces a marketable LMT outside RTH (IBKR rejects MKT there) — extended gets `outsideRth=True`; overnight routes to the venue.

**Session-split evaluation:** every perf surface accepts `session=` — the dashboard's Entry Performance and Returns tabs carry an RTH/Extended/Overnight toggle, trade tables show a `Session` column, and the perf breakdown adds per-session rows once any non-RTH trade exists.

## Architecture

### Pipeline flow (`src/pipeline.py`)

`run_pipeline()` is the single entry point. Steps execute in sequence:

```
0.  Universe construction   — Static watchlist (always included, never gated) + dynamic discovery (trending, screener,
    macro→holdings, catalyst/analyst/earnings expansion, related-company peers). Discovery gate drops junk tickers
    (is_valid_ticker), exotic security types (is_exotic_security — preferred/warrants/units/rights/OTC foreign; ADRs +
    class-shares kept), and microcaps below the OBSERVATION floor (discovery_min_price $1 / discovery_min_dollar_volume
    $1M — kept LOW so penny/thin names keep accruing performance data). See Two-tier liquidity below.
1.  News & sentiment feeds  — RSS (CNBC/Seeking Alpha/Yahoo) + press wires (GlobeNewswire/PR Newswire) + FDA/MedWatch +
    per-ticker Google News — all fetched FRESH every tick (never cached) for fast catalyst reaction — plus NewsAPI,
    per-ticker yfinance news, Polygon (Benzinga) + Finnhub, Alpha Vantage (off by default), StockTwits (off by default),
    8-K filings, Google Trends, Reddit, Quiver alt-data, analyst ratings, EPS surprises, short interest, Massive ticker
    events. All normalised to NewsArticle; merged pool URL-deduped.
2.  Market snapshots        — Polygon/Massive batch primary (real-time full-market on the Stocks Advanced plan →
    price_source="live") → yfinance per-ticker fallback → deterministic grouped-daily close fallback (one Polygon call,
    price_source="prev_close"). Indices/futures/OTC route through yfinance. (Execution prices come separately from
    tracker._fetch_price, IBKR-first.)
3.  Smart-money + macro     — Insider/congressional trades, options flow, SEC filings (13D/G, Form 144, 13F, Form 4),
    plus market-context fetchers (FRED, COT, VIX, MOVE, DIX, breadth, credit, bond/global macro, sector rotation, etc.).
3X. Regime & timing layers  — Macro Regime Filter, Market Mode, Catalyst Timing — gate BUYs, adjust thresholds, tweak weights.
3#. Per-ticker scorers      — News sentiment, sentiment velocity, technical, trend strength, momentum, money flow, pattern
    recognition, IV rank/expression, PEAD, cointegration, cross-sectional rank, ext_gap (off-hours), broker advisor,
    trend-predictability (kaufman/adx × long/short), plus the 2026-08-11 PROMOTIONS (user-directed — the methods
    validated at their best version by the 20y Gate-4 sweeps + forward-panel gates, now WEIGHTED in the combine:
    mom_12_1 0.15 / hi52 0.15 / st_reversal 0.12 (v2 fixed-scale since 2026-08-10, epoch-registered) / ml_ohlcv 0.12
    (§ML methods) / rsi2_rev 0.10 / dloc_rev 0.10 — all join coherence, sources_agreeing and the Price-Trend family
    vote; the per-side win-rate machinery governs them like every weighted method), plus 5 remaining PANEL-FIRST
    methods at weight 0 (Tier-2 squeeze / iv_term / avwap; Tier-3 resid_mom / vol_profile). Each returns [-1, +1].
3B. Broker advisor group    — src/signals/broker_advisor.py (enable_broker_advisor, default OFF — needs broker_mode != off).
    Scores IBKR short-borrow state: hard/expensive-to-short is a squeeze tell → BULLISH (one-sided; never bearish).
3M. Massive technicals      — Massive/Polygon server-side RSI+MACD composite scored as the `massive` method (weight 0.15),
    run alongside our own `tech`. enable_massive_tech (default on), massive_tech_max_tickers default 0 (uncapped).
3F. Fundamentals overlay    — Massive/Polygon ratios (P/E, P/B, EV/EBITDA, ROE, ROA, D/E, yield, mkt cap) → <fundamentals_context>
    prompt overlay (§28), NOT a scorer. Plus capped per-ticker enrichment (short interest, short-vol, net margin, YoY rev).
    Directional factors f_value/f_quality/f_growth/f_short_squeeze in the signals panel + small additive combine overlay
    (fundamental_factor_weight 0.08). enable_fundamentals (default on).
3G. Corporate actions       — Massive/Polygon dividends + splits → <corporate_actions_context> §29 mechanics overlay +
    directional factors f_split / f_dividend (signals panel + additive overlay corp_action_factor_weight). enable_corporate_actions (default on).
4.  Signal aggregation      — aggregator.py combines per-ticker scores into a TickerSignal; sector_pairs.py finds opposites.
5.  Recommendations         — claude_analyst.py → BUY/SELL/HOLD/WATCH; DeepSeek auto-fallback; rule-based last resort.
6.  Performance tracking    — tracker.py + daily_nav.py: paper trades, M2M updates, path-faithful daily compound.
7.  Charts + email          — charts/, email_sender.py.
```

**Two-tier liquidity.** A name clearing the observation floor but below the higher **TRADE floor** (`trade_min_price` **$5** / `trade_min_dollar_volume` **$5M**, `enable_trade_liquidity_gate`) is **OBSERVE-ONLY** — fully scored + persisted to the `signals` panel but gated out of actionable trades by **Gate 4** (`pipeline._is_tradeable`, fail-closed via `is_liquid`, `gate_diag.dropped_untradeable`). The pinned watchlist bypasses the DISCOVERY gate only (`pipeline`'s Section-F `_protected` set), **NOT Gate 4** — a pinned thin name is scored and persisted but stays observe-only. Pinning a thin name gets it analysed, not traded.

For deeper detail on any step, see the module file or `memory/project_signals.md`.

### Data flow design

**Two tiers of data:**
- **Per-ticker signals** scored `[-1.0, +1.0]`, combined in `aggregator.py` into a `TickerSignal`. News sentiment is the *level*; sentiment velocity the *rate of change*. Trend strength (ADX/DMI + Donchian) measures trend *quality*, distinct from momentum (return *size*). A continuous `coherence_factor` ∈ [0.45, 1.35] (magnitude-weighted fraction of active methods agreeing with the combined direction) dampens confidence when methods disagree.
- **Macro context** (FRED, COT): not per-ticker. Passed as structured prompt blocks; the LLM applies regime overlays.

**Score-sign convention** (the invariant the combine, IC, and inversion depend on — see the `aggregator.py` docstring): EVERY method's score sign is the predicted direction of the STOCK (`+` = up/bullish, `−` = down/bearish, position-independent); mean-reversion/contrarian methods bake the reversal INTO the sign; `|score|` = confidence.

**Cross-family agreement + tape confirmation** (`src/signals/agreement.py`). The flat `sources_agreeing` count treats correlated methods as independent voters, so `METHOD_FAMILIES` rolls the weighted methods into 7 independent INFORMATION families (Sentiment / Price-Trend / Rel-Strength / Volume-Flow / Options / Smart-Money / Event-Arb). Per-family magnitude-weighted votes (`family_vote_threshold` 0.05) are counted at the family level against the combined direction, exposed to the synthesis prompt, folded into confidence via a breadth factor ∈ [1±`family_agreement_factor_span` 0.12] (an opposing family drags 1.5× as hard as an aligned one helps), and stamped on new trades (`families_at_entry`). Win-rate-filtered methods excluded from votes; inverted methods vote with their corrected sign. **Tape confirmation** (`enable_tape_confirmation`) is the score-independent half: a raw price/volume state composite from cached daily OHLCV (20d range position + up/down-day volume share + last-bar RVOL → ∈ [-1,+1], + = bullish) that qualifies agreement rather than joining the combine: confidence × `1 + 0.08×(tape × direction)`, plus a prompt line and panel persistence as the `fam_net`/`tape` pseudo-methods. `enable_family_agreement`/`enable_tape_confirmation` default ON. Tests: `tests/test_family_agreement.py`.

**Weighting stack** (multiplicative, then normalised across active methods): hand-set `_BASE_WEIGHTS` → market-mode profile → **win-rate adaptive** (`enable_adaptive_weights` ON — tilts by each method's solo win rate from the trade ledger, Bayesian-shrunk) → **IC-informed adaptive** (`enable_ic_weights` ON but confidence-gated — tilts by reliability-adjusted IC = ICIR over the unbiased signals panel, only for methods whose mean-daily-IC t-stat `|ICIR|·√n_days ≥ ic_weight_min_t` 2.0; a method below the gate keeps base weight) → OpEx max-pain boost → extended-session overlay. Cached `ic_weight_cache_seconds`.

**Buy/sell split combine** (replacing the single normalised pool). Each `_BASE_WEIGHTS` method's inversion-corrected view (`eff`) decomposes into a BUY component `max(0, eff)` and a SELL component `max(0, −eff)`, both ∈ [0,1]; each side is weight-averaged over the methods HOLDING that view only (its own camp — abstainers and the opposing camp don't dilute a side). `combined_buy_score` = the bullish camp's conviction, `combined_sell_score` = the bearish camp's, and **`combined_score` = their DIFFERENCE**. Direction fires on the difference clearing `buy_sell_diff_threshold` (0.15). Camp SIZE is judged by the machinery built for it (coherence, Gate 1b `sources_agreeing`, family agreement), not by re-diluting the score. Both side scores are persisted per ticker (`signals.combined_buy_score`/`combined_sell_score`), ride the sighted prompt (`buy_score=`/`sell_score=`), and are IC-monitored as `cmb_buy`/`cmb_sell`. The 6 corp-action/fundamental `f_*` factors and the 4 trend-predictability methods (`kaufman_long`/`kaufman_short`/`adx_long`/`adx_short`) are additive overlays OUTSIDE the split, landing on the DIFFERENCE. The 4 trend methods are active only in their trend CONTEXT (`*_long`=uptrend, `*_short`=downtrend), each raw signal ×a **learned orientation** ∈ [−1,+1] (`trend_predictability.calibrate_trend_orientation`: +1 = continuation, −1 = reversal, magnitude = confidence, shrunk toward a continuation prior by signal-days). Single symmetric weight `trend_method_weight` 0.10. Tests: `tests/test_buy_sell_split.py`.

**Win-rate HARD filter** (`enable_winrate_method_filter` ON, `aggregator.winrate_filtered_methods`). Any `_BASE_WEIGHTS ∪ INVERTIBLE_OVERLAYS` method whose GROSS solo win rate (`compute_solo_method_gross_winrate` — the pure directional hit rate `sign(score)·(exit−entry) > 0`, before fees) is `< winrate_filter_threshold` (0.50) over `≥ winrate_filter_min_trades` (10) attributed trades is DROPPED from the active pool: weight → 0 (survivors renormalise), excluded from coherence / `sources_agreeing`, and hidden from the synthesis prompt's per-ticker score lines. Inverted methods are exempt; a method below `min_trades` keeps full weight; `build_signals` suppresses the filter for any run where it would empty the book. The dropped method is still scored + persisted + trade-attributed, so it can re-earn its place. The 5 remaining PANEL-FIRST methods (weight 0: squeeze/iv_term/avwap/resid_mom/vol_profile) stay out of the candidate set; the six 2026-08-11 promotions are IN it (starting "unproven" → full weight until `winrate_filter_min_trades` accrues). Overlay filter/inversion is carried by `aggregator._overlay_factor(method)` (0.0 when filtered, ±1.0 otherwise — filter beats inversion; fail-soft).

**Per-SIDE win-rate filter + weighting** (`enable_side_winrate_filter` / `enable_side_adaptive_weights`, both ON). A method's bullish and bearish calls are separate skills. Each camp is filtered and weighted on ITS OWN record: `compute_solo_method_gross_winrate(side="buy"|"sell")`; `aggregator.side_filtered_methods(side)` drops a method from one camp when its side win rate is `< winrate_filter_threshold` over `≥ winrate_filter_min_trades` side views; `side_weight_multipliers(side)` scales survivors by demonstrated side skill (Bayesian-shrunk toward 50% by `side_weight_prior_n` 10, clamped `side_weight_min/max_multiplier` 0.5–2.0). Guard: the per-side filter is suppressed for a camp it would EMPTY (a structurally single-direction book is a far larger bet than a filter should place). Tests: `tests/test_side_winrate_filter.py`.

**Stream-separation invariant.** The per-side filter reaches **coherence, `sources_agreeing` AND family agreement**, not just the combine — `aggregator` applies `_side_ok(method, eff)` when building `method_score_map_eff`, keyed on the method's own effective sign, so all four see the same book. Correct by design and NOT changed: the synthesis prompt applies only the GLOBAL filter (the LLM picks direction), and `broker_view` charges no modelled borrow (it re-anchors on real fills).

**Method inversion** (`inverted_methods`, `INVERTED_METHODS` in .env, `aggregator._inverted_methods`). A method whose RAW score is reliably anti-predictive net of beta across horizons is sign-flipped in the combine (its weight negated) and lifted off the IC floor to base weight. The signals panel keeps the RAW score so the inversion stays re-validatable. `coherence_factor`/`sources_agreeing` read each method's RAW (pre-inversion) score (a documented, accepted inconsistency for an inverted method); the cross-family agreement votes on each method's EFFECTIVE/corrected sign. **Automatic inversion** (`enable_auto_inversion` ON, `tracker.calibrate_method_inversion`): a method is auto-inverted only when TWO bars clear — (1) its gross solo win rate is significantly below 50% by a one-sided exact binomial at `inversion_alpha` (0.05) AND the finding REPLICATES on the independent panel arm (`inversion_require_replication` ON), and (2) the FLIPPED view itself clears `winrate_filter_threshold` (ties count as losses on both sides). Evidence floor `inversion_min_trades` (30). Candidates are `_BASE_WEIGHTS ∪ INVERTIBLE_OVERLAYS`. Inversion is strictly PER-METHOD, never per-FAMILY. Manual pins in `inverted_methods` are supported, unioned in, and always win; auto-detection is fail-soft. **Arm B — the signals PANEL** (`tracker.panel_inversion_evidence`, `enable_inversion_panel_arm`): reads `simulated_trades` through `compute_directional_perf`, scoring each method on its EXCESS over `combined_score` at the same horizon (`inversion_panel_horizons` default `1d,3d`) to control for shared holding-period edge decay; cached 6h; abstains if the `combined_score` yardstick is missing. **Currently `INVERTED_METHODS=` is empty and the detector selects nothing.** Tests: `tests/test_auto_inversion.py`, `tests/test_panel_inversion_arm.py`, `tests/test_overlay_inversion.py`.

**Market-relative WEIGHTING** (`src/analysis/market_relative.py`, `enable_market_relative_weighting` ON). An absolute win rate cannot separate "this signal works" from "the market went up," so the per-side adaptive weighting reads MARKET-RELATIVE hit rates from `compute_directional_perf` (thousands of observations per method vs the ledger's ~100), falling back to the absolute ledger basis when the panel is unavailable. The neutral point is the MEASURED baseline (`_measure_baseline`, observation-weighted, ≈48%), not 50% — the cap-weighted index beats its typical constituent. Scope: weighting and inversion use this basis (signal-quality decisions where beta is a confound); the hard filter, sizing, edge blend and all P&L reporting stay ABSOLUTE (the book is outright long/short). **The HARD FILTER judges on PROMOTION LOGIC** (`enable_market_relative_filter`, rebased 2026-08-12 user-directed): a weighted method is dropped only when the promotion statistic itself — market-neutral per-day IC (`compute_directional_perf` `both`-side ICIR) — is SIGNIFICANTLY negative (`t = |ICIR|·√n_days ≥ ic_weight_min_t` 2.0) at EVERY horizon judgeable with ≥ `market_relative_min_obs` (200) rows; no judgeable horizon → kept at full weight (unproven ≠ disproven — the same bar to lose weight as to earn it). The 2026-07-27→08-12 point-estimate rule (hit rate net of benchmark < literal 50%, no significance test) zeroed 14/27 weighted methods on the live window incl. hi52/mom_12_1 and was retired for judging on a different statistic than the promotion basis. Inverted methods exempt; every dropped method is still scored, persisted and IC-tracked. Dashboard method table shows Rel win % / vs base / Rel n beside the absolute Win rate %. Tests: `tests/test_market_relative_weighting.py`.

**Per-method HORIZON SKILL — three states** (`src/analysis/method_horizons.py`, `enable_method_horizons`). Measured over the solo-method simulation (`simulated_trades`) gated at `buy_sell_diff_threshold`, giving ~1,500–3,300 observations per method (vs the ledger's ~100). A method is judged good over a particular HOLDING PERIOD across 1/3/5/10 days. **PROVEN** (significant >50% at some horizon) keeps full weight; **DISPROVEN** (significantly <50% at every judgeable horizon) is dropped by the filter; **UNPROVEN** is scaled by `unproven_weight_multiplier` (0.5) rather than zeroed. Multiple comparisons across horizons are NOT alpha-corrected (horizons are correlated); the guard is profile coherence. This basis SUPERSEDES the trade-ledger filter when available (`aggregator.horizon_disproven_methods`), because the ledger is selection-biased. CLI `python -m src.analysis.method_horizons`. Tests: `tests/test_method_horizons.py`.

**Scorer-version epochs** (`src/signals/method_epochs.py`). Method scores are persisted on every trade and every scored ticker, then fed back into live decisions. When a scorer is FIXED (its OUTPUT changes, not merely refactored), stored history was produced by a function that no longer exists. `METHOD_SCORER_EPOCH` maps a method → the UTC INSTANT its current implementation went live; `score_is_comparable(method, when)` gates `compute_solo_method_gross_winrate` + `_hypothetical_trades_for_method`; `epoch_for(method)` gives date-granular consumers the day after a mid-day change; `confidence_is_comparable` / `CONFIDENCE_EPOCH` do the same for confidence. Fail-OPEN. Applied at three choke points: `signal_panel.build_panel` (masks superseded scores/confidence to NaN — every panel-reading analysis inherits it), `simulated_trades.load_sim_trades` → `_drop_superseded_scorer_rows` (drops superseded long-format rows), and `compute_macro_eval` category bundles. Register **categorical changes only** (the output means something different), not refinements. Effect: a freshly-fixed scorer falls below `winrate_filter_min_trades` and keeps FULL weight ("unproven," not "disproven"). **Whenever you change what a scorer OUTPUTS, add the instant here (or let auto-refactor derive it — below).** Tests: `tests/test_method_epochs.py`, `tests/test_simulated_trades.py`.

**Replay** (`src/analysis/replay.py`). Where the epoch mask achieves comparability by discarding evidence, replay REGENERATES it — faithful for the OHLCV-derived methods (`schema.REPLAYABLE_METHOD_COLUMNS` = tech, vwap, momentum, money_flow, trend_strength, iv_rank). The join must be **run-exact** (`restore_replayed` keys on `generated_at`) and **time-aware** (each row's own `generated_at` decides visible history, the signal-date bar existing only for a run at/after the 16:00 ET close — `replay.visible_history`, mirroring `_drop_forming_bar`). `build_panel` overwrites replayable superseded scores from the materialised `signals_replay` table, and the epoch mask then SKIPS those restored cells (`enable_panel_replay_restore`). Also recovers market-condition context (`schema.REPLAYABLE_CONTEXT_COLUMNS`: `atr_pct`/`bb_width_pct`/`vol_ratio`/`tape_score`) and the `movement_factor` confidence component (the one component not weight-dependent). `pattern` and `sector_momentum` are EXCLUDED (live registry / current-time sector fetch); everything else (news, sentiment, options, insider, pead, massive) needs an unstored point-in-time feed and stays masked. Two split guards refuse rescaled rows: `_scale_is_consistent` (`_SPLIT_GUARD_LO/HI` 0.67/1.5, needs a live price) and `_series_is_intact` (`_MAX_PLAUSIBLE_ATR_PCT` 1.0, for tickers with no priced row). No-look-ahead is enforced by adversarial probes (`tests/test_replay.py`). Materialised by EOD maintenance (`enable_eod_replay_refresh`, `eod_replay_refresh_days` 45) or `python -m src.analysis.replay --write`; `--validate` prints the fidelity table — **run it after any scorer change.** The 2026-08-05→11 "length mismatch" restore failure is FIXED (2026-08-11): a double-materialise had duplicated one day's run-exact keys because `materialize()` derived its DELETE boundary from `CURRENT_DATE` hours after the INSERT window was computed — the DELETE boundary now comes from the staged frame's own min day, DELETE+INSERT run in one explicit transaction, `restore_replayed` dedupes on the exact key (newest `replayed_at` wins) and enforces a post-merge length invariant. Regression-pinned in `tests/test_replay.py`.

**Walk-forward calibration** (`src/analysis/asof.py` + `walkforward.py`, table `weight_history`). A backtest applying today's weights to all history measures a configuration that could not have existed. `analysis_asof(date)` installs a point-in-time cutoff honoured at the same three choke points the epoch mask uses (`signal_panel._load_signals`, `simulated_trades.load_sim_*`, `tracker._load_trades`), so the weighting stack recomputes seeing only strictly-earlier rows. The ledger filter keys on the EXIT, not the entry (a trade closed after the cutoff leaks its outcome); open trades are excluded. `analysis_asof` flushes every layer's TTL cache on entry AND exit (without the flush, a walk silently reuses one calibration). `walkforward.materialize` stores one row per step; `backtest.run_backtest(walk_forward=True)` is the DEFAULT and resolves the weight set per signal date via `weights_for_date` (latest calibration strictly before it; a row predating every calibration is SKIPPED). Kept current incrementally by EOD maintenance (`enable_eod_walkforward`, `walkforward_eod_days` 3). Tests: `tests/test_walkforward.py`.

**Automatic database refactor** (`src/analysis/code_version.py` + `refactor.py`, tables `code_versions`/`refactor_runs`, `enable_auto_refactor`). Mechanises the "stored history must reflect current code" rule. Detection: every method maps to its module(s) (`METHOD_SOURCES`, all 42 mapped — `unmapped_methods()` must stay empty, a test asserts it), fingerprinted by **normalised AST** (comments/formatting/docstrings don't move it; a changed constant or reordered branch does). Repair runs in DEPENDENCY ORDER: (1) DATA — regenerate replayable scores via `replay`; (2) EPOCHS — derived from `code_versions.first_seen_at`; (3) WEIGHTS — re-walk `walkforward`; (4) DERIVED — `backtest`. A replayable method is REGENERATED (false positive costs only CPU, detector can be liberal); a non-replayable one can only be MASKED, which withholds real history, so masking is opt-in (`refactor_auto_epoch`, default **OFF**) and reported. Fingerprints advance only on FULL success. Wired into EOD after the walk-forward. CLI `python -m src.analysis.refactor --check|--apply`. Tests: `tests/test_refactor.py`, `tests/test_code_version.py`.

**The one genuine limitation is circularity, applying only to DERIVED values:** method scores don't depend on the weights (replaying + calibrating weights from the result is sound), but `combined_score`/`confidence`/gate outcomes DO (replaying those with today's weights is a BACKTEST — inspect, never re-calibrate the same weights from it). `signals` is never overwritten: it records what actually happened and stays the audit trail.

**Significance tests are dependency-free by rule** (`src/analysis/stats.py`). scipy is not a declared dependency, so a `try/except` around `scipy.stats` would make the except branch the only one that ever runs (every method UNPROVEN). Exact binomial (`binom_p_less`/`binom_p_greater`, log-space) and Welch's t-test (`welch_t_test`) live in-tree, and the call sites deliberately do NOT wrap them in a bare except. Degenerate input returns NaN ("no verdict"), never 0.0. **General rule: an optional import guarding a verdict the system ACTS on is an invisible off switch, not a graceful fallback.**

**Silent channels.** The project configures **loguru** sinks only, so `logging.getLogger(__name__)` in `src/` yields a handler-less logger that discards everything — use `from loguru import logger`. `tests/test_inert_settings.py::test_no_module_logs_into_a_silent_channel` scans `src/` so it can't recur. **The unifying rule (unread setting, unreachable import branch, sinkless logger): a mechanism whose failure mode is indistinguishable from normal operation must be verified mechanically, never by review.**

**Confidence-component isolation** (`src/analysis/confidence_components.py`). The six ingredients of the confidence formula (`raw_confidence`, `coherence_factor`, `movement_factor`, `volume_factor`, `family_conf_factor`, `tape_conf_factor`) are persisted verbatim on `TickerSignal` and the `signals` panel (`schema.SIGNAL_CONFIDENCE_COMPONENT_COLUMNS`, forward-collected) so each multiplier's contribution can be measured. For every scored ticker, six variants are reconstructed — `raw` alone and `raw × exactly one factor` (never stacked) — and evaluated against the direction-oriented forward return: an ungated Spearman IC per variant + a Low/Medium/High conviction-banded win%/return table. Entry-side (every scored ticker) and exit-side (signals-panel rows re-scored on an already-open position). Dashboard Entry + Exit Performance tabs. `python -m src.analysis.confidence_components [--source entry|exit]`.

**Multi-timeframe technical signals** (`src/signals/multi_timeframe.py`, `enable_multi_timeframe_signals` ON). The 8 OHLCV methods (`multi_timeframe.TECHNICAL_METHODS`: tech, vwap, momentum, money_flow, trend_strength, iv_rank, pattern, sector_momentum) are each computed on **30-min** (yfinance, `cache/ohlcv_30m/`, capped by `intraday_30m_max_tickers`), **daily**, and **weekly** (resampled from daily). Every OHLCV scorer takes an optional `df=`/`interval=` (`df=None` reproduces the legacy daily output bit-for-bit). `build_signals` feeds `combined_score` a per-method renormalised blend (`blend_timeframes`, weights `tf_blend_30m/1d/1w` default 0.20/0.60/0.20; a 0-score timeframe abstains; revert with `tf_blend_1d=1.0`). The daily score stays in each `*_score` field; 30-min/weekly ride `TickerSignal.timeframe_scores` → panel `*_30m`/`*_1w` columns. Pattern keeps a per-timeframe library (`cache/patterns_30m/`, `cache/patterns_1w/`). 30-min history is yfinance-capped at ≤60 days and 429-prone; the 30-min IC category fills slowly (paid Polygon 30m is the drop-in upgrade). Tests: `tests/test_multi_timeframe.py`.

**Macro Regime Filter** (`macro_regime.py`): hard pre-filter after the LLM runs. Reads VIX, MOVE, bond internals, global macro, FRED, breadth, credit, DIX; computes a weighted composite regime (PANIC|RISK_OFF|CAUTION|NEUTRAL|RISK_ON) that raises the confidence threshold. **BUY entries are blocked entirely during PANIC**; **RISK_OFF takes a size haircut** (`enable_regime_size_haircut`, `risk_off_size_multiplier` 0.5, `regime_size_multiplier`, Step 3a of the sizing chain) rather than the BUY ban. `macro_regime_exit` closes longs in PANIC (and RISK_OFF only when the haircut is disabled — a guard forbids any regime both admitting longs on entry and closing them on exit). **Fails CAUTIOUS, not open:** below `macro_regime_min_inputs` (3) available feeds, a permissive verdict is forced to at least CAUTION. Regime input coverage surfaces as a Data-Quality source-health entry. Tests: `tests/test_regime_haircut.py`. Regime validation/history harnesses: `src/analysis/regime_performance.py`, `regime_history.py` (the bands are historically correct — the market has simply been calm; PANIC/RISK_OFF/RISK_ON rarely fire in live data).

**Market Mode Switching** (`market_mode.py`): adjusts the aggregator's weight profile by market structure. TRENDING (low VIX, healthy breadth) → up-weight `tech`/`news`, down-weight `vwap`/`put_call`. CHOPPY (high VIX, mixed breadth) → the reverse. Computed from VIX, breadth, highs/lows, McClellan before `build_signals()`.

**Catalyst Timing** (`catalyst_timing.py`): event-driven layer computed BEFORE LLM synthesis (Step 4.5) → prompt `<catalyst_timing_context>` §26. Three mechanisms: (1) Earnings Blackout removes tickers within 2 days of earnings (with a post-release exemption when `days_since_report ≤ 1` — the PEAD/gap trade); (2) OpEx Amplifier boosts `max_pain` weight during OpEx week; (3) 8-K + Insider Buy WATCH elevation. Enforcement stays mechanical post-synthesis. Tests: `tests/test_catalyst_prompt.py`.

**8-K filings, Google Trends, Reddit, analyst ratings, EPS surprises, short interest are treated as news** — all return `List[NewsArticle]` and are scored by the same DeepSeek sentiment pipeline. **Smart money signals** (insider trades, options flow, SEC filings) return `List[InsiderTrade]` and combine into a single `insider_score` per ticker.

**Method attribution** (`tracker.py`): every new trade stores the raw method scores (the full set in `tracker._ALL_METHODS`) at entry plus `methods_agreeing` and `dominant_method`. `get_performance_for_email()` returns:
- `performance_table`: breakdown rows (trades, win_rate, compound_return, avg_return, wtd_avg_return, best, worst) grouped total → asset (Stocks/ETFs/Commodities) → direction (Longs/Shorts) → session (RTH/Extended/Overnight, shown once any non-RTH trade exists) → method (≥2 attributed trades). Includes open trades at their live M2M `return_pct`.
- `trades_svg`: inline SVG (equity curve + per-trade bars), no kaleido/Plotly dependency.
- `portfolio_metrics`: from `compute_portfolio_metrics()` → `daily_nav.compute_compound_return()` (path-faithful daily walk). Keys `compound_inception`, `return_1w`/`return_2w`/`return_1m`. Overwrites `stats["compound_return"]`.
- `solo_method_perf`: "what if only this method had decided" per closed trade with stored scores.
- `llm_perf`: per-LLM-engine stats over every recommended trade (executed or not), scored on the engine's full recommendation stream, deduped to the engine's last call per (ticker, day), anchored at the rec-time snapshot price, marked through the same cost model. A **split guard** (`_build_pseudo_trades`, `tracker._SPLIT_GUARD_LO/HI` 0.5–2.0) discards a snapshot outside the band vs its own day's cached bar (reverse-split ETFs otherwise invent split-ratio returns). Rule-based fills are stamped `tracker.RULE_FILL_MODEL` (`"rule-based (fill)"`) so they show as their own row rather than inheriting the model's name, and are ranked LAST in the top-N email (sort key `(action_rank, is_fill, -confidence)`) so a saturated aggregator-confidence fill never displaces a real LLM call.
- `method_eval_stats`: per-method directional accuracy + conviction bands (Low 0.10–0.35 / Medium 0.35–0.65 / High 0.65+).
- `method_order_by_winrate`, `attributed_count`.

Legacy trades without `methods_agreeing` are excluded from method rows but included in total/asset/direction rows.

### Performance calculation

Two engines side by side, both rooted in the *real* observed prices stored on each trade.

**STANDING RULE — a calibration may only fit data the CURRENT code produced.** Two mechanisms enforce it, both to be considered whenever a scorer or the confidence formula changes: **Panel side** — `signal_panel.build_panel` masks superseded method scores (`METHOD_SCORER_EPOCH`) and confidence + components (`CONFIDENCE_EPOCH`) to NaN. **Ledger side** — calibrations reading trade fields gate explicitly: `method_epochs.score_is_comparable` (win-rate filter, adaptive tilt) and `confidence_is_comparable` (`calibrate_side_threshold`, `calibrate_confidence_sizing`). Both fail OPEN on a bad timestamp. Satisfy the rule by RESTRICTING each calibration to comparable data, never by rescoring history onto the current formula (a retrofit was measured and rejected twice — today's weights are calibrated FROM the panel, so rescoring the past would feed future info into live sizing/gating). The Bayesian shrinkage every calibration carries makes the smaller clean sample safe.

**Self-calibrating parameters.** Frozen constants are replaced by values learned from the system's own tables through one idiom (documented prior → evidence → Bayesian shrinkage → clamps → fail-soft to the static setting), all reported to the calibration registry (`src/performance/calibration.py` → `gate_diag["calibrations"]` → the Data Quality tab). Current set: per-session real-fill costs, the derived horizon cost hurdle (`spread.effective_cost_hurdle_pct`), the engine-relative actionable threshold (`analysis/threshold_calibration.py`), the calibrated exit-confidence floor (`analysis/exit_floor_calibration.py`), breadth sizing, the expected-edge sizing blend (`performance/edge_sizing.py`), the predictability sizing tilt (`performance/predictability_sizing.py`), and the edge-decay time-stop window (`analysis/horizon_edge.py`). Universe **provenance** is stamped per run (`signals.universe_source`). Risk guardrails (liquidity floors, exposure caps, wipe guards, order-cap ceilings) and the calibrations' own meta-parameters stay fixed.

**Per-trade `return_pct` (buy-and-hold, cost-aware) — `tracker._pct_return()`**

```
cost_in  = _one_side_cost(entry_price, asset_type)            # half-spread + commission
cost_out = _one_side_cost(exit_or_current_price, asset_type)
BUY  : eff_entry = entry × (1 + cost_in);   eff_exit = exit × (1 − cost_out)
       return_pct = (eff_exit − eff_entry) / eff_entry × 100
SELL : eff_entry = entry × (1 − cost_in);   eff_exit = exit × (1 + cost_out)
       return_pct = (eff_entry − eff_exit) / eff_entry × 100
```

**Per-trade cost attribution** (`sim_per_trade_cost_attribution`, ON). Each sim leg is charged the best-fitting cost by a four-tier hierarchy (`spread.resolve_leg_cost` / `resolve_trade_leg_cost`): (1) the leg's OWN realized cost if it FILLED (commission + execution-vs-decision slippage, sanity-banded to ±2%); (2) else the tick(run) average of trades that filled (≥`sim_cost_tick_min_legs` 3); (3) else the time-of-day PERIOD average (`rth | premarket | afterhours | overnight`, ≥`session_cost_min_legs`); (4) else the modeled `_one_side_cost`. Ledger purity is preserved — every sim trade still assumes it fills; only the COST is sourced more precisely. Both return engines resolve through the one shared `resolve_trade_leg_cost` (threaded into `_pct_return` and `daily_nav`), so they charge identical per-leg costs. `false` → the flat/session override. Tests: `tests/test_per_trade_cost_attribution.py`.

**Short borrow carry** (`enable_short_borrow_cost` / `short_borrow_annual_pct` 3.0%). A direction-asymmetric HOLDING cost (SELL legs only), so it bypasses `_one_side_cost`: `spread.borrow_cost_fraction(action, days, trade)` charges per **calendar** day, subtracted in `_pct_return(borrow_cost=…)` and per-day in the daily-NAV walk. Prefers the broker's real fee (`trade["borrow_fee_pct"]`) over the blended setting.

**Direction-scoped parameters** (`config.settings.directional(name, direction)`): resolves `{name}_long` / `{name}_short` when set, else the shared `{name}`. Every override defaults to None (inert). Splits are justified where the asymmetry is STRUCTURAL or a threshold SWEEP is stable across a wide band — never a single point estimate. Prefer a shrunk per-side calibration where the quantity can be measured.

**Hard adverse stop** (`enable_adverse_stop`, `adverse_stop_pct_long` 8% / `adverse_stop_pct_short` 20%). Caps a single position's loss on the cost-adjusted M2M return, and only when the LLM review HELD (like `trailing_stop`/`mechanical_exit`), so it never overrides a macro/flip close; `exit_reason = "adverse_stop"`. The split runs OPPOSITE the "stop shorts tighter" prior because shorts against this book tend to RECOVER — a stop helps longs and hurts shorts. The short side is −20% (a runaway guard) rather than disabled.

**Per-side actionable threshold** (`tracker.calibrate_side_threshold`, `enable_side_threshold_calibration`). Gate 1 is the highest-leverage parameter, so this is the most conservative split: MEASURED, Bayesian-shrunk by `side_threshold_prior_n` (40), capped at `side_threshold_max_adjust` (+0.04), and it can only TIGHTEN. Evidence is whether confidence DISCRIMINATES on that side (`Spearman(entry confidence, realised return)` per direction, scaled by `side_threshold_rho_ref` 0.30). Surfaced in `gate_diag.threshold_adj_buy/sell`. Pin with `actionable_threshold_adj_{long,short}`.

**Per-side horizon ramp** (`tracker.calibrate_horizon_ramp`, `enable_horizon_ramp_calibration`). `horizon_expiry_floor_mult` resolved per DIRECTION and MEASURED: the gap between what `horizon_expired` trades returned and that side's other exits (negative → tighten, positive → loosen). Bayesian-shrunk by `horizon_ramp_prior_n` (30), clamped ±`horizon_ramp_max_adjust` (30%), floored at 1.0. Tests: `tests/test_directional_params.py`.

**One-way cost** (`spread._one_side_cost`) = **half-spread + commission**. Half-spread is price-tiered and asset-type-aware (`_dynamic_half_spread`). The commission term (`_commission_fraction`) is a deliberate **fee ceiling, not a best estimate** — the pricier all-in plan is the default (`ibkr_fixed`: max($1.00, $0.005/share); `ibkr_tiered`: max($0.35, $0.0035/share); `none`: spread-only), capped at 1% of trade value, then × `commission_buffer` (1.5) to cover SEC/TAF/venue fees. Unrecognized model names fall back to `ibkr_fixed`. **Real-fill calibration** (`sim_use_real_fill_costs`, ON): once ≥`sim_real_fill_costs_min_legs` (10) actual **LMT** fills exist, `calibrate_sim_costs()` measures the average all-in one-way cost from them and installs it via `spread.set_real_cost_override()`. A **sanity band** (`sim_real_fill_cost_sanity_pct`, 2.0%) discards a leg whose measured one-way cost lies beyond ±2% (a stale `model_price`, not brilliant execution) before averaging — applied to both the flat override and the per-session split. Source is LMT-only (`repo.fetch_filled_lmt_legs`); MKT fills ignored. Residual bias: the sample is only filled legs (~13% fill rate), so it understates the intended-trade cost — floor at `max(measured, modeled)` if that matters. The pipeline calls it before the tick's normalize/M2M/entry steps so a run uses one cost basis throughout.

**Path-faithful daily compound — `daily_nav.compute_compound_return(trades)`**

Per-trade walk: (1) load OHLCV closes for the ticker; (2) build chronological marks `(entry_date, eff_entry)` → every cached close strictly between → `(exit_date or today, eff_exit)` — entry/exit anchors apply the same `_one_side_cost`, intermediate marks are raw closes; (3) per adjacent pair `r_d = sign × (mark_d − mark_{d−1}) / mark_{d−1}` (`sign = +1` BUY / `−1` SELL — path-faithful, so a volatile short's daily compound legitimately differs from its buy-and-hold `return_pct`). Portfolio: group `(date, daily_return, weight=position_size_multiplier)` by date → per-day return `Σ(r·w)/Σ(w)` → compound sequentially. **Deterministic given the database** (same DuckDB + same `cache/ohlcv/*.json` → bit-identical output). Time-window variants filter by `entry_date >= today − N days` before aggregating; the cost basis is always from the full ledger.

**Summary statistics — `tracker._compute_segment_stats()`** (for any slice: All / Stocks / ETFs / Commodities / Longs / Shorts / per-method):

| Metric | Formula | Notes |
|---|---|---|
| `trades` | `len(trades)` | |
| `win_rate` | `100 × count(gross win) / len(trades)` | **GROSS** — `tracker.is_gross_win`: `sign(action) · (exit − entry) > 0` on raw prices, before spread and commission (a flat round trip is not a win, but is not charged the spread either). See the win-rate convention below. |
| `compound_return` | `daily_nav.compute_compound_return(trades)` | Path-faithful daily walk. |
| `avg_return` | `mean(t.return_pct)` | Equal-weighted. |
| `wtd_avg_return` | `Σ(t.return_pct · t.position_size_multiplier) / Σ(t.position_size_multiplier)` | Capital-weighted. |
| `best` / `worst` | `max` / `min(t.return_pct)` | |

Open trades' `return_pct` is the live M2M (and their live mark drives the gross win test) so they contribute to every metric. Compound uses the daily walk; every RETURN metric uses per-trade `return_pct` (these can diverge for shorts, by design).

**THE WIN-RATE CONVENTION (standing directive, 2026-08-06): every win rate in the system is GROSS; costs are measured by the RETURN metrics only.** A win rate asks one question — did the position move the way it was supposed to, on raw prices. Spread and commission are judged by `avg_return` / `wtd_avg_return` / `compound_return`, which stay fully cost-adjusted. The reason for the split: a cost-adjusted win rate silently answers *two* questions ("was the direction right?" and "was the move bigger than the round trip?"), and the second is an execution property — it moves with the spread model, the venue and the session, so the same signal scores worse for being traded in wide markets, and every cost recalibration rewrites the win rate of history that did not change. Canonical helpers live in `tracker`: `gross_return_pct(trade)` (direction-aware, uses the exit price when closed and the live mark when open), `is_gross_win(trade)` (`None` when prices are unusable — such trades leave BOTH numerator and denominator, so a data gap can't masquerade as a bad signal), and `gross_win_rate(trades)`. Applies to `_compute_segment_stats`, the method/category/convergence/dominant breakdowns, `_solo_stats`, `_eval_stats` accuracy, every A/B eval row (hold-prompt, blind-synthesis, ML/long-horizon arm), the breadth and confidence-recalibration **sizing** calibrations, `broker_view` (real fills — gross of the real commissions it reports separately), `source_performance`, `pattern_registry`, `confidence_calibration`, `regime_performance`, `policy_eval` and the equity chart. `compute_solo_method_gross_winrate` already worked this way and is unchanged. Panel/simulated-trade surfaces (`simulated_trades`, `exit_panel`, `method_horizons`, `market_relative`, `signal_panel` IC) were already gross by construction — their forward returns are raw price moves with no cost model. Pinned by `tests/test_gross_winrate_convention.py`, whose decisive case is a right-direction trade whose move was smaller than the round trip: a WIN with a negative return, both in the same stats dict.

**Hypothetical solo & eval stats — `tracker._flip_trade()` / `_hypothetical_trades_for_method()`.** If a method's sign matches the actual action → use the trade verbatim; if it disagrees → `_flip_trade()` returns a same-ticker/same-dates dict with action inverted and `return_pct` re-derived, and the daily-NAV engine walks the real OHLCV closes in the opposite direction. Conviction bands (`_eval_stats`): Low 0.10–0.35, Medium 0.35–0.65, High 0.65+ on `|method_score|`, each reporting `trades`, `accuracy`, `avg_return`, `compound_return`.

**Sizing chain (`record_new_trades`).** compressed confidence ramp (`confidence_size_span` 0.5 → max 1.5×; LLM confidence measured ~uninformative) × **agreement-breadth tilt** (`breadth_sizing_enabled`, self-calibrating via `tracker._breadth_calibration`, set-size-normalized `frac = n_agreeing / len(attribution set)`; breadth was the strongest entry-time discriminator) × **expected-edge blend** (`edge_sizing_enabled`, `performance/edge_sizing.py`, ridge model whose say grows with closed-trade evidence, inert below 20 closes) × **predictability tilt** (`enable_predictability_sizing`, `performance/predictability_sizing.py`, sizes up forecastable-direction names, self-calibrating from the unbiased signals panel, never a gate) → **regime size haircut** (Step 3a, RISK_OFF ×0.5) → correlation-aware haircut (scale-down vs same-direction open peers, hard skip at the correlated-exposure cap) → `extended_size_multiplier` (×0.5 extended / ×0.25 overnight).

**Exits (`monitor_open_positions`, `enable_llm_hold_review` + `enable_pinned_hold_review`, default on).** The pipeline's `_build_hold_reviews` re-judges every LLM-opened position on EVERY tick with the SAME synthesis AND sentiment engines that opened it (mapped from `llm_synthesis_model`/`llm_sentiment_model`), on freshly refetched news + prices — an apples-to-apples same-engine comparison. `hold_reviews[ticker]` is that opener-pinned `Recommendation`; this monitor consumes it. **Latency overlap** (`enable_hold_review_overlap`, on): the review pipeline runs CONCURRENTLY with main Steps 4–5 (`pipeline._HoldReviewBranch`), joined before the monitor runs; provenance-safe (forced-engine calls don't write the run meta / sentiment tallies). Reasons: `macro_regime_exit` (long in PANIC — engine-independent), `llm_signal_flipped` (opener now calls the opposite direction), `llm_confidence_loss` (opener's same-direction conviction fell below `max(absolute, relative × the LLM entry confidence)`) — **OFF since 2026-08-03 (`enable_llm_confidence_loss_exit=false`): the only exit rule the post-exit forward returns condemn.** Per-reason `exit_forward` (the "persistently positive mean ⇒ exits too early" test): `trailing_stop` −8.13/−15.68 @1d/5d (excellent), `horizon_expired` −0.49/−0.93 (correct), `llm_signal_flipped` +0.28/+0.44 (~neutral), **`llm_confidence_loss` +1.50/+2.24 (money left behind; +0.80% median next day, 62% of exits kept running, n=45)**. It had already been patched twice for the same fault (the two-tick confirmation, and `signal_decay_confidence_floor_relative` 0.65→0.55) — the tell that the RULE, not its tuning, is wrong: LLM confidence is measured ~uninformative about forward returns, so its DRIFT is not evidence. **Not a zombie risk:** this is the IN-WINDOW half of a test whose PAST-WINDOW half (`horizon_expired`, same conviction test on a ramped floor) is measured CORRECT and still fires, so a decayed position closes at its horizon instead of before it (a test pins exactly this). No review this tick (opener engine failed) → hold. The `llm_confidence_loss` floor is nudged by:
- **Exit-conviction consensus** (`enable_exit_conviction`, `analysis/exit_conviction.py`): breadth of the raw signal methods' oriented exit scores (LLM + aggregator excluded); consensus-exit raises the floor, consensus-hold lowers it. Evidence-throttled (`span_eff` from `exit_conviction_span_prior` 0.03 → cap 0.10).
- **Edge-decay time-stop** (`enable_edge_decay_exit`, `analysis/horizon_edge.py`): raises the floor once held past the realized edge-positive window (`calibrate_edge_horizon` → `edge_days`; bounded by `edge_decay_floor_cap` 0.08 × evidence strength). Emitted as the `edge_decay` exit method.
- `signal_decay_confidence_floor_relative` is 0.55 (only catches conviction collapse; freed trades stay governed by flip/trailing/mechanical/horizon/macro exits).

Additional monitor-level exits, firing ONLY when the LLM logic above HELD: **`trailing_stop`** (`enable_trailing_exit`) — once MFE arms past `trailing_arm_pct` (3%), close on give-back ≥ `trailing_give_back_frac` (0.5) of the peak. **`mechanical_exit`** (`enable_mechanical_exit`) — **OFF SINCE 2026-08-02, DELIBERATELY. Do NOT "fix" its threshold.** Closed when the raw signal methods' `exit_method_consensus` was confidently exit (≤ −`mechanical_exit_threshold` 0.35). Two independent measurements condemn it: (a) the consensus is **ANTI-PREDICTIVE** (IC −0.066 / hit 46% at 3d AND 5d — it averages ~21 mostly-1-day methods, the same horizon mismatch that broke the weighted entry combine at 5d); (b) **it cannot fire at that threshold anyway** — the consensus is a MEAN of ~21 near-zero scores, so its whole observed range is `[−0.26, +0.32]` over 23,387 held-days (0.000% fire rate; 4 hits in 328 live closes, all thin-method tickers). It was inert BY ACCIDENT, which was quietly protecting the book; lowering the bar to make it fire (≤−0.10 fires ~5%) would wire in a rule that exits wrong ~54% of the time. Turned off explicitly so the protection survives a future threshold tweak. Exits do NOT depend on it — `horizon_expired` (30%), `trailing_stop` (29%), `llm_signal_flipped` (22%), `llm_confidence_loss` (14%) and `adverse_stop` (2%) are ~99% of live closes. **Note the flag coupling:** `enable_ml_exit_model` is named explicitly in the `_escores` build condition in `monitor_open_positions`, because `ml_exit` reads `_escores` and would otherwise die silently once the conviction/edge-decay/mechanical flags were all off. **`ml_exit`** (`enable_ml_exit_model`, ARM trades only) — the learned exit-timer (`src/analysis/ml_exit_dataset.py`, see ML methods) closes an `ml_arm`-stamped trade when its hold-conviction ≤ −`ml_exit_threshold` (0.35); no minimum hold (measured harmful, `ml_arm_min_hold_days` default 0). **`method_horizon`** (`exit_methods.method_horizon_days`) — a position's target hold is the conviction-weighted average of its own PROVEN methods' measured best horizons; emitted as a score (0 inside the window, increasingly negative past it) and it PARTICIPATES in `exit_method_consensus`. The aggregator's `combined_score`/`confidence` is **no longer consulted for LLM-opened trades**; it survives as the `signal_flipped`/`signal_decay`/`confidence_loss` backstop only for legacy/rule-based-opened trades (`enable_signal_decay_exits`). `enable_pinned_hold_review=false` → cheaper fallback; `enable_llm_hold_review=false` → revert to the aggregator monitor.

Exit harnesses (dashboard Exit-Perf tab): `analysis/exit_forward.py` (post-exit forward returns — a persistently positive mean = the rule exits too early), `analysis/monte_carlo.py` (exit-timing-vs-random), `analysis/policy_eval.py` (close-rule comparison).

**SEQUENTIAL exit-policy simulator** (`src/analysis/exit_policy_sim.py`). `exit_policy_eval` is MYOPIC (per position-day) and so cannot evaluate a rule that spans days — a minimum-hold window is exactly that. This runs **close-once** policies over the simulated held-position dataset (`ml_exit_dataset.build_exit_dataset`): walk each position's days in order, realise it at the first EXIT, aggregate the realized returns. **The headline metric is `EXCESS`, not `mean_ret`** — on a decaying book the raw return of any rule mostly reflects how long it holds, so fixed-day controls (`p_fixed_day`, exit on day N regardless of signal) trace return-vs-hold with ZERO information and `add_excess_vs_matched_control` subtracts that curve at the SAME average hold; only the remainder is timing skill. A random-exit control is included too. **Findings (3,294 simulated positions):** the 5-day min-hold is NOT strictly better and was REMOVED — identical rule, only the constraint differing, it cost ~1.8pp per position and destroyed ~37% of the timing edge (excess +1.27 → +0.80), because it holds through exactly the deterioration the model detected; `ml_exit` at 0.35 is the excess-optimal threshold (+1.27, vs a random control's +0.61 and a trailing stop's +0.44); and **`exit_method_consensus` NEVER FIRES at ≤ −0.35 (0.0% exit rate)** — the live `mechanical_exit` is effectively inert. CLI `python -m src.analysis.exit_policy_sim [--horizon 5] [--min-hold N]`. **Re-run this before adding any time-based exit constraint.**

### Database (DuckDB)

`data/llm_trader.db` is the **single source of truth** for trades, recommendations, run history (the legacy `cache/*.json` ledgers are import-only). All access goes through `src/db/`:

- **`connection.py`** — `connect(read_only=False)` yields a short-lived handle. Read-write opens `ensure_schema()` first; read-only requires the file to exist.
- **`schema.py`** — idempotent `CREATE TABLE IF NOT EXISTS` for the core tables: `runs`, `run_sources`, `recommendations`, `trades`, `hypothetical_trades`, `broker_reconciles`, `broker_orders`, `signals`, `trade_reviews`, `arm_recommendations`, `weight_history`, `signals_replay`, `code_versions`, `refactor_runs`. Trade/hypothetical rows store the **full dict in a JSON `data` column** (byte-identical round-trip) alongside projected scalar columns. New tables appear on the next write connection; new *columns* need a one-time `ALTER TABLE`.
- **`trade_reviews` table** — append-only, one row per held position re-judged each tick by the opener-pinned hold-review (`repo.insert_trade_reviews` ← `pipeline._persist_trade_reviews`): `reviewed_at`, `ticker`, `position_id`, review `confidence`/`action`/`direction`, the `conf_floor` tested against, `entry_confidence`/`entry_action`, `price`/`return_pct`, pinned `synthesis_model`/`sentiment_model`. The same-engine confidence-over-time series the dashboard plots (Recommendations tab → click a row).
- **`signals` table (the learning panel)** — every run persists the FULL per-ticker signal cross-section (one row per scored ticker): all method scores as DOUBLE columns (`schema.SIGNAL_METHOD_COLUMNS`, mirroring `tracker._ALL_METHODS` — a drift test keeps them in sync), `combined_score`, `combined_buy_score`/`combined_sell_score`, `confidence`, `direction`, `n_methods_agreeing`, `dominant_method`, snapshot `price`, `universe_source`, and the full score dict as JSON. The trade ledger only teaches what the gates let through (selection bias); this panel, joined against forward returns from `cache/ohlcv/`, is the unbiased IC/threshold/weight dataset. Forward-collected — judge nothing until weeks of cross-sections accumulate. Analyse with `python -m src.analysis.signal_panel` (`--horizons 1,5,10 --days 90 [--refresh]`): per-method Spearman IC + directional hit rate per horizon + `icstd`/`icir` (per-day IC std/information-ratio via `periodic_ic_stats`). Score-inversion readout: `python -m src.analysis.simulated_trades --directional` (per-`(method, side)` market-relative ICIR net of `horizon_market_benchmark`).
- **`repo.py`** — the typed read/write API: `load_trades()`/`save_trades()` (full-replace), `update_trade` (rewrites one row on its stable `trade_id`, ~53 ms vs 227 ms full replace; declines when the id isn't unique or unknown), `insert_run()`, `insert_run_sources()`, `insert_recommendations()`, `insert_broker_report()`, `fetch_df()`, `fetch_filled_lmt_legs()`. `set_read_only(True)` flips every read path to open read-only (the dashboard sets this).
- **`migrate.py`** — one-time `python -m src.db.migrate` imports the legacy JSON ledgers (idempotent). `tracker._load_trades()` also self-seeds from `cache/trades.json` if the DB is empty.

**Concurrency model:** DuckDB allows a single read-write handle OR many read-only handles across processes. The pipeline is the sole writer and holds the write lock only momentarily; the dashboard connects read-only with exponential-backoff retry.

### Model routing

| Task | Engines (A/B-routed) | Last resort |
|---|---|---|
| Per-ticker sentiment | **DeepSeek V4-Flash 90% / Qwen 10%** flipped once per run (`sentiment_qwen_share` 0.10; each engine is the other's per-call error fallback). Claude stripped unless `enable_claude_sentiment=true`. | score 0.0 (`none`) |
| Final synthesis (BUY/SELL/HOLD/WATCH) | Uniform pick from `LLM_AB_SYNTHESIS_MODELS` (below); cross-engine error fallback | rule-based `_fallback_recommendations()` |

**A/B routing (`LLM_AB_ANTHROPIC_SHARE`, default 0.5):** each run flips a coin per role (synthesis and sentiment independently) to pick which provider goes FIRST; the other is the error fallback. The engine that answered is recorded per run (`runs.llm_synthesis_provider`/`llm_sentiment_provider`), per recommendation (`recommendations.llm_provider`), and stamped on each new trade (`llm_synthesis_model`/`llm_sentiment_model`).

**Synthesis N-way bake-off (`LLM_AB_SYNTHESIS_MODELS`, SYNTHESIS only):** a comma-separated model-id list picks the per-run synthesis engine UNIFORMLY from that pool (so 3+ models accumulate comparable samples, each its own dashboard row). Provider inferred by `_engine_of` (`deepseek*` → DeepSeek, else Anthropic); the OTHER provider's default is the error fallback. **DeepSeek arms encode thinking with a `-thinking` suffix** on a logical id (`_deepseek_spec` decodes `deepseek-v4-pro-thinking` → API model `deepseek-v4-pro` + thinking ON). **Currently `deepseek-v4-flash,qwen/qwen3.7-plus-thinking` (≈50% each)** — the bake-off found the arms statistically indistinguishable (eleven paired tests, zero significant differences), so engine choice is a cost/latency decision. Empty → the legacy binary `LLM_AB_ANTHROPIC_SHARE` behavior.

**⚠ The Anthropic leg is currently DEAD** — the account is unfunded, so `ANALYST_MODEL` returns HTTP 400 "credit balance is too low" in ~0.5 s (fast, non-retried). Since Anthropic is never a chosen engine (only the third-tier error fallback), the practical chain is **DeepSeek → Qwen → (dead) → rule-based**. It self-heals when the account is funded, so the link is left in place. No open position is pinned to an Anthropic opener.

**Synthesis-prompt arms — dual-case / blind / sighted** (`dual_case_synthesis_share` 0.5 + `blind_synthesis_share` 0.5). Three arms: the dual-case flip is taken first and supersedes the blind/sighted axis (≈50% dual / ~25% blind / ~25% sighted), stamped in `gate_diag.dual_case_synthesis`/`blind_synthesis`. **Dual-case** presents each ticker as `BULL CASE conviction=… | BEAR CASE conviction=…` (the two camps' separate `combined_buy_score`/`combined_sell_score`) with NO verdict, treating "which case does the evidence support" as the question and making a contested/both-weak read an explicit HOLD/WATCH. Its substantive fix: each per-method line is gated by the side its OWN score points to (a bullish `news` score is hidden while a bearish one is shown, matching the per-side win-rate filter). The other two arms apply only the GLOBAL sub-50% filter. Value: it protects the cohort where the LLM adds value — neutral-origin BUYs (aggregator had no view, the model supplied the direction) beat echo BUYs. Tests: `tests/test_dual_case_synthesis.py`.

**Shadow synthesis arms** (`enable_shadow_arms` ON). Every arm is asked about every ticker each tick — the live arm drives the run, the other two are shadow calls nobody acts on (`src/analysis/arm_shadow.py` → `ShadowArmBranch`, started after the live recs, joined at persist time so orders never wait). Shadow calls are pinned (`force_engine`) to the live arm's engine, which also suppresses provenance writes. Cost: two extra SYNTHESIS calls per tick (one call for the whole top-N set). Fail-soft; persisted to `arm_recommendations`. Eval `src/analysis/arm_eval.py` (dashboard Entry Performance) reports a per-arm summary + a head-to-head table measured ONLY over ticker-days where two arms took different sides. Ledger-side: `compute_synth_arm_eval` → "Entry eval · prompt arm …" rows, stamped `entry_synth_arm` on new trades. Tests: `tests/test_arm_shadow.py`, `tests/test_arm_eval.py`.

**Held-positions prompt A/B (`OPEN_POSITIONS_PROMPT_SHARE`, default 0.5):** a per-run flip (Step 4.6) decides whether the synthesis prompt includes `<open_positions_context>` + §27 (current holdings with a zero-endowment-bias review instruction). Lands in `gate_diag.hold_prompt_active`; stamped `exit_hold_prompt` on every trade closed that run by both close paths. `compute_hold_prompt_eval()` → dashboard "Exit eval · hold-prompt ON/OFF" rows. Tests: `tests/test_hold_prompt.py`.

Available analyst models (`.env` `ANALYST_MODEL`): `claude-haiku-4-5-20251001` (fastest, 8K out), `claude-sonnet-4-6` (64K out), `claude-opus-4-7` (32K out), `claude-opus-4-8` (currently configured; sampling-free surface + adaptive thinking).

**Claude API calls use streaming** (`client.messages.stream`) to avoid SDK timeouts on large prompts. **Per-model sampling/thinking gating** (`_anthropic_sampling_kwargs`/`_anthropic_thinking_kwargs` in `claude_analyst.py`): Opus 4.7+ and the Fable/Mythos 5 families removed `temperature`/`top_p`/`top_k` (a 400 if sent), so `temperature=0` is sent ONLY on models that accept it (Haiku 4.5 / Sonnet 4.6 / Opus 4.6 / older). Adaptive thinking (`thinking={"type":"adaptive"}`, `display` omitted) is enabled on supporting models (Opus 4.6+, Sonnet 4.6+, Fable/Mythos 5). Both helpers are version-aware; an unforeseen model degrades via the engine fallback. **Engine fallback** (`_call_claude_analyst()`/`_call_deepseek_analyst()`): whichever engine the flip did NOT pick first is tried on any `anthropic.APIStatusError` / `APIConnectionError` / DeepSeek-SDK error; both LLMs failing → rule-based. Parsed responses are deduped per ticker (`_dedupe_recommendations`); `record_new_trades` guards against twin trades.

### Adding a new data source

1. **Per-ticker signal:** implement a `[-1.0, +1.0]` scorer, add weight in `aggregator.py`, add an `enable_*` flag in `settings.py`. Add the method to `tracker._ALL_METHODS` **and** `schema.SIGNAL_BASE_METHOD_COLUMNS` (`ALTER TABLE signals ADD COLUMN <m> DOUBLE` on an existing DB) — `tests/test_db_signals.py` fails if they drift. An OHLCV scorer that should also run on 30-min/weekly goes in `multi_timeframe.TECHNICAL_METHODS`. **If you change what an existing scorer OUTPUTS, register the epoch (`METHOD_SCORER_EPOCH`) or let auto-refactor derive it.**
2. **Smart money signal:** return `List[InsiderTrade]` from a new module, call from the Step 3 block, extend the `smart_money` list.
3. **Macro context:** return a Pydantic model, pass to `generate_recommendations()`, build a prompt block + instruction section in `claude_analyst.py`, render in the email template.
4. **News-like source:** return `List[NewsArticle]` (or pre-score via `provider_insights` to skip the LLM scorer), submit it `_safe`-wrapped in the Step 1 fetch pool, add to `_article_chunks`, add an `enable_*` flag. An always-on feed stays OUT of `data_quality.EXPECTED_SPARSE_SOURCES` (empty result alerts); an optional/event-driven one goes IN.

### ML methods

Trained models as signal methods. The convention (matching the buy/sell split combine) is that a method emits a **bullish score ∈ [0,1] AND a bearish score ∈ [0,1]** — a classifier's `P(up)`/`P(down)`, both low = a genuine no-view. Requires **lightgbm** in the production `.venv` (`requirements.txt`); models use lightgbm's **native Booster API, NOT the `LGBMClassifier` sklearn wrapper** (which would need scikit-learn even to unpickle — the artifact must stay sklearn-free). See `memory/ml-methods-plan-2026-07.md` for the full history.

**Harness (offline):** `src/analysis/ml_dataset.py` builds one row per (ticker, session_date) from the deep OHLCV cache (**76** causal features `ALL_FEATURE_COLUMNS` — raw + expanding within-ticker z-scores + 2 cross-sectional ranks; labels `fwd_ret_{raw,rel}_<h>d`; causality by construction, leakage-probed). The 9 pivot **leg-state features** live separately in `src/analysis/pivot_target.py` (merged on for the pivot model → its 85). The cache is **full-depth since 2026-08-08** (Polygon serves 2006+; ~5,000 bars for ~950 names, median ~2,265) and the full-universe training set materialises to `cache/ml/dataset_full.parquet` (~9M rows). `ml_train.py` = deterministic `SoftmaxLogistic` (pure-numpy baseline) + `LightGBMModel` (native-Booster classifier, the v1 fallback) + **`LightGBMRankRegressor` (the production v2 model)** + `walk_forward_predict` (trains only on rows whose label printed, `end_date < cutoff`) + `evaluate()` (IC/ICIR/hit/simret vs baselines). Leakage guarded by three adversarial tests in `tests/test_ml_dataset.py` (causal features / noise→IC≈0 / planted-signal→IC>0).

**`ml_ohlcv` — OHLCV base signal, WEIGHTED 0.12 in the combine since 2026-08-11 (user-directed promotion; panel-first weight 0 from 2026-07-30 to then). v2 since 2026-08-08: the SIGNED-PIVOT rank model.** A `LightGBMRankRegressor` (`ml_train.py`) on the within-day rank of the **signed pivot target** — the % return to the next pivot, peak or trough whichever comes first, `sign(target) = sign(tomorrow's move)`, median horizon 1 day (`src/analysis/pivot_target.py`: target + the 9 leg-state features; causality pinned by `tests/test_pivot_target.py` — a pivot at bar j is usable only from bar j+1). 85 features (76 causal OHLCV + 9 leg), **full universe, no conditioning, uniform day-equal weights** — conditioning, magnitude/recency/signed weighting and longer training were each measured ≤ this config (see `memory/pivot-horizon-target-2026-08.md`; signed-target weights are structurally unsound on a rank label). Trained on the full-depth cache (~9M rows, 2007→, Polygon serves 2006+); score = `clip(2·pred, −1, 1)`, meaningful relative to same-day scores. Promotion gate `python -m src.analysis.ml_validate --target pivot` (train-on-deep / judge-on-panel, point-in-time): **passed its pre-registered bar 2026-08-08** — panel IC +0.0639 / t +2.31 / edge +2.58pp over 14,610 rows, rel-5d cross-check positive (t +2.90). v1→v2 is epoch-registered (`METHOD_SCORER_EPOCH["ml_ohlcv"]`); within-v2 retrains stay the `ml_models` registry's job. EOD retrain is throttled (`ml_pivot_retrain_days` 7 — the full-universe dataset rebuild is heavy); `ml_ohlcv_target=classic` reverts trainer+EOD to the v1 rel-10d conditioned classifier (serving always dispatches on the artifact's own config). Weighted 0.12 since 2026-08-11 (joins combine/coherence/family votes; still excluded from the exit consensus); still fail-soft everywhere — a missing artifact means the method abstains, never a broken tick. Tests: `tests/test_ml_model_pivot.py`.

**`ml_buy` / `ml_sell` — the FULL STACKERS as combined_buy/sell_score, ML COMBINE ARM (A/B, LIVE at `ml_combine_arm_share`=0.5 — re-enabled 2026-08-11 after a spell at 0).** `src/analysis/ml_stacker.py`. Learned aggregators over 21 of the weighted method scores (`STACKER_LIVE_FEATURES` — deliberately NOT the post-promotion 27: the six 2026-08-11 promotions were measured as features and HURT while their panel history is mostly-NaN; revisit ~2026-09), 5-day CROSS-SECTIONAL-RANK label, isotonic-calibrated on OOF predictions. Unlike `ml_ohlcv` they **DRIVE decisions when the arm is on**: `combined_buy_score = compute_buy_conviction(...)` (centered `max(0, 2·P(up)−1)`) and `combined_sell_score = compute_sell_conviction(...)` (the sell model trains on the NEGATED return) — both replacing their weighted camps. Separate artifacts (`ml_buy_model.pkl`/`ml_sell_model.pkl`, registry rows); **`STACKER_GBM_PARAMS` since 2026-08-11** (15 leaves / min_child 20 / lr .05 / 200 trees — the 13-arm panel retune: OOS rank-5d IC +0.0463 → +0.0611, t +2.00, best ICIR; the lgb defaults were sized for deep-cache data; the calibrator's OOF walk uses the same params). Per-run A/B flip in the pipeline (`ml_combine_arm_share`, or `enable_ml_combine` to force), EOD-retrained. **Arm trades are stamped `ml_arm` only when the stacker ACTUALLY drove that trade's side** (`tracker._ml_arm_stamp`, 2026-08-11: the flip AND side-matching `combine_source` — stacker entry ⇔ ML exit per trade); safety exits always fire (`tracker._ARM_ALWAYS_EXIT`: flip / macro-PANIC / adverse-stop). **No forced holding period** — `ml_arm_min_hold_days` defaults to **0** (a min-hold was MEASURED HARMFUL, `exit_policy_sim`). Fail-soft per side: no artifact ⇒ the weighted combine is kept, recorded per ticker in **`combine_source`** (`weighted | ml | ml_buy | ml_sell`, on `signals` AND trades). The A/B (since 2026-08-11) evaluates the retuned stackers against the PROMOTED weighted combine — a stronger baseline than the one the stackers originally beat. Compare cohorts by the `ml_arm` stamp (dashboard "ML-arm eval · ML combine ON/OFF"; `compute_ml_arm_eval`). Tests: `tests/test_ml_stacker.py` (incl. the actual-use stamp invariant).

**`ml_exit` — the learned EXIT-TIMER, COUPLED to the entry arm (LIVE, `enable_ml_exit_model` ON).** `src/analysis/ml_exit_dataset.py`. A GBM answering "for a held position, exit now?" over 30 features: 9 position-STATE features the hand-built consensus throws away (`days_held`, oriented `ex_ret`/`ex_mfe`/`ex_mae`/`ex_giveback`/`ex_from_mae`, `ex_combine`, `ex_combine_delta`=conviction degradation since entry, `ex_elapsed_ratio`=held/method-horizon) + the 21 oriented method scores. Trained on **SIMULATED held positions over the signals panel** (`build_exit_dataset`: every directional ticker-day walked forward day-by-day; label `fwd_ret_pos_<h>d` = oriented held return, `+`=holding was right), 5-day horizon, native Booster, EOD-retrained. Emits a signed HOLD-conviction `2·P(keep)−1` ∈ [−1,+1] (`+`=keep, `−`=exit). **Its baseline (`exit_method_consensus`) is measured ANTI-PREDICTIVE at 3d AND 5d** (IC −0.066, hit 46% — it times multi-day exits backwards, the same 1-day-methods-over-weighted problem as the entry combine); the exit model beats it (h=5 hit 53.4%, ICIR +0.30). **The A/B coupling (2026-08-02):** ml_exit DRIVES the close ONLY for trades stamped `ml_arm` — and since 2026-08-11 the stamp requires the stacker to have ACTUALLY driven that trade's side (`tracker._ml_arm_stamp`: the run's flip AND the trade-side's `combine_source` ∈ {ml, ml_buy|ml_sell} — the swap is fail-soft per side, so a partial swap's weighted-side trade gets weighted exits), so stacker entry ⇔ ML exit per trade, not per coin. For that cohort it REPLACES two things: the anti-predictive `mechanical_exit` (now restricted to non-arm trades) **and the confidence-DEGRADATION exit** `llm_confidence_loss` (`tracker._ARM_ML_OWNED_EXITS` — permanently suppressed, not delayed: conviction is judged by a model trained on the oriented held return at the horizon the entry optimises, instead of by the drift of a scalar measured ~uninformative). A confident `≤ −ml_exit_threshold` (0.35, **validated as the excess-optimal bar** by the sweep in `exit_policy_sim`) closes with `exit_reason="ml_exit"`, with NO minimum holding period; direction flips and safety exits are never suppressed (a broken thesis is information, not degradation). For EVERY OTHER held position it is still computed + persisted to the `exit_signals` panel (`build_exit_scores` → IC-tracked as the `ml_exit` exit method), so its exit-side IC accrues live before it acts anywhere. Excluded from `exit_method_consensus` (`_CONSENSUS_SKIP`) so it never contaminates its own baseline. Fail-soft: no artifact/lightgbm ⇒ the hand-built exit machinery is kept. Train/serve parity (`live_exit_features` reproduces the dataset walk from the live OHLCV path) is a test. **Caveats:** modest absolute edge (IC ~0.02); thin (~34-day) SIMULATED-position panel, not real held trades. Tests: `tests/test_ml_exit.py`.

### Key constraints

**Polygon.io client** (`src/data/polygon_client.py`): `get_snapshots_batch()` (two calls), `get_bars()`, `get_grouped_daily_closes()` (every US ticker's last close in ONE `/v2/aggs/grouped` call — works on the free tier, where the per-ticker snapshot endpoint 403s). A 403 is logged once per endpoint-family then suppressed. Falls back to yfinance when `POLYGON_API_KEY` is absent. Free tier covers US equity/ETF; indices (^VIX) and futures (GC=F) use yfinance directly.

**Bulk vs execution pricing — two separate paths.** The bulk snapshot (`market_data.get_snapshots`: Polygon batch → yfinance → grouped-daily close) feeds the analysis panel (`signals.price`), scoring, ext_gap, and the price-provenance check. Trade execution comes from `tracker._fetch_price` (IBKR → yfinance → Polygon single-ticker), live only for actionable/held tickers. The deterministic anchor for analysis/NAV/IC is the completed daily CLOSE. `_assess_price_provenance` skips `price_source != "live"` anchors so a live fill is never falsely flagged against a prev-close fallback.

**Silent-default health monitors** (`pipeline._collect_sources` → `run_sources` → Data Quality tab + email banner): FX sizing rate (`broker/fx.py`), correlation sizing (`performance/correlation.py`), and macro-regime/market-mode input coverage each keep a reset-per-run health dict that surfaces as a source-health row.

**SEC EDGAR rate limit:** 10 req/s (`_REQUEST_DELAY = 0.12–0.15s`). The `_ticker_index`/`_ticker_cik` maps are module-level globals populated once per process — never re-fetch in a loop.

**yfinance rate limits:** on 429, `market_data.py` backs off 60s → 120s → 240s, stopping after 3 failures. Options-chain scanning is silent-fail per ticker.

**CFTC downloads:** COT ZIPs are ~5–10 MB; current + previous year fetched if current has insufficient history. Always check the cache first.

**Actionable signal threshold.** Baseline (NEUTRAL) is `confidence ≥ 0.85` (**Gate 1**, mechanical) AND `sources_agreeing ≥ 2` (**Gate 1b**, mechanical, `enable_agreement_gate`/`min_sources_agreeing_gate`). The Macro Regime Filter adjusts the threshold dynamically (`_REGIME_THRESHOLD`): RISK_ON 79%, NEUTRAL 85%, CAUTION 87%, RISK_OFF 89%, PANIC 95% (this is a minimum-confidence baseline, not a hard floor — RISK_ON sits below 0.85 by design). Off-RTH adds `extended_confidence_bump` (+6 pp, capped 95%; overnight uses +10 pp instead). BUY entries are blocked during PANIC (RISK_OFF gets the size haircut). A single strong source never produces a BUY/SELL. **Smoothed-step threshold** (`macro_regime.continuous_threshold`, `enable_continuous_regime_threshold` ON): each band keeps its documented threshold through its interior; only within `_THRESHOLD_SMOOTH_HALFWIDTH` (0.05) of a boundary does it ramp, entirely on the lenient side (NEUTRAL stays ≥0.85). The regime LABEL and BUY block stay step-based. The regime is deliberately NOT a per-ticker scoring method (a market-wide constant has no rank variance). Tests: `tests/test_regime_threshold.py`.

**Gate 1b scope:** `sig.sources_agreeing` (post win-rate-filter, effective/inversion-corrected sign) is meaningful only when the LLM's direction matches the aggregator's `sig.direction` (the ~96% echo case); a genuine override (`r.direction != sig.direction`) passes Gate 1b unchecked. Counted in `gate_diag.dropped_low_agreement` + the per-ticker `gate_outcomes` stamp; funnel rows in `compute_stage_eval`. **Gate 5 — overextension / anti-chase** (BUY-only, `enable_overextension_gate` ON): drops an actionable BUY whose trailing close-to-close return over the last `overextension_lookback_bars` (5) completed daily bars exceeds `overextension_runup_pct` (12%) — recent big gainers mean-revert and `combined_score` peaks post-run-up. DEFERRED, not banned (re-qualifies once cooled). SELLs are never gated. Fail-OPEN on missing/short history. `pipeline._is_overextended`/`_recent_runup_pct`; `gate_diag.dropped_overextended`.

**The actionable filter is extracted into `pipeline._apply_actionable_gates`** (Gates 1, 1b, 2, 3, 4, 5 — behaviour-preserving: same gates, same order, same counters, same `gate_outcomes` stamps). A drop is attributed to the FIRST gate that rejects it; an expensive gate is never consulted after an earlier one rejected the candidate. Tests: `tests/test_actionable_gates.py`.

### Broker integration (paper-first live execution)

`src/broker/` adds a real **execution leg** alongside the internal NAV simulator — a "shadow & reconcile" design. Gated by `settings.broker_mode`; **`off` (default) makes zero broker calls.**

- **Modes:** `off` | `dry_run` (log intended orders, submit nothing) | `ibkr_paper` | `ibkr_live`. Paper vs live is the configured `ibkr_port` (IB Gateway 4002/4001); the factory refuses to start `ibkr_paper` on a known live port.
- **Broker = Interactive Brokers** via `ib_async` → IB Gateway (the only API broker letting a Canadian resident paper + live trade US securities; the tradeable universe is 100% US stocks/ETFs). `ib_async` is imported lazily (off/dry_run paths import fine without it).
- **Single hook point — `reconcile.sync()`** runs once per tick right after `record_new_trades`. Idempotent and self-healing, in order: **(0) fill refresh** — earlier-tick orders not yet terminal are repaired from today's executions (`Broker.get_fills()`, keyed by `orderRef`); **(0b) tick-scoped order lifetime** (`broker_tick_scoped_orders`, on) — an order lives exactly one tick; anything still unfilled is cancelled and its leg cleared so the entry/exit pass resubmits re-anchored under a fresh `-rN` client_ref. Entries resubmit only when the trade survived this tick's signal pass AND clear the **price-aware resubmit gate** (`broker_price_aware_resubmit`, on, `_resubmit_decision`): chase only when the fresh signal still wants it (same direction) inside the adverse-price ceiling (`broker_resubmit_max_adverse_bps`, 100 bp), or at an equal-or-better price; a decayed-at-adverse entry is HELD (`RESUBMIT_HELD_ADVERSE`); a flipped signal is not resubmitted. EXITS are never gated. Dead/expired DAY-LMT orders are recovered (`EXPIRED` → re-sent). **(0c) cancel-on-close** — a ledger-CLOSED trade with a working entry gets it cancelled (`_cancel_entries_for_closed`). **(1)** internal OPEN trades without a `broker_order_id` → sized entry submitted (sizes the GAP vs any same-side held position; a position at/over target submits nothing → `POSITION_ALREADY_AT_TARGET`). **(2)** internal CLOSED trades still holding a broker position → close submitted, sized from the actual held position (sign-checked). **(3) drift** — broker positions the ledger can't explain: `broker_drift_action` **`"flatten"` (default)** submits a price-capped marketable LMT at a fresh quote (never adopted into the ledger), re-anchored each tick; a same-side flatten filled within ~90 min blocks a resubmit (`_recent_flatten_fill`); `ibkr_live` always refuses auto-flatten (downgraded to report). **(4) settle — fill fast or kill** (`_settle_unfilled_this_tick`, `broker_settle_seconds` 30, real `time.monotonic()` deadline): this tick's unfilled orders are watched (fills repaired the moment they land, `broker_settle_poll_seconds` 3 s), re-anchored at a fresh quote every `broker_settle_reanchor_every` polls (2 ≈ 6 s), and CANCELLED at the deadline so nothing rests across ticks. Every broker call is exception-safe (degrades to report-only). The internal NAV sim stays the source of truth; `tracker.py` is not modified.
- **Order-vs-ledger durability.** The invariant: **no order may work the book unless a ledger leg points at it.** `_persist_legs(trades, changed)` flushes the ledger (via `repo.update_trade`) immediately after every submission, so the live-order-unknown-to-ledger window is milliseconds. `cancel_order` cancels EVERY order matching a ref (IBKR does not dedupe `orderRef`) and confirms them all. `_working_order_for_ref` is a pre-submit duplicate guard (adopts an already-working ref → `duplicate_submits_blocked`). `_sweep_orphan_orders` (`broker_orphan_order_sweep`, on) cancels working orders no ledger leg owns → `orphan_orders_cancelled` (drift-flatten refs `drift-<TICKER>-` and ref-less hand-placed TWS orders are exempt). `IBKRBroker.connect()` calls `reqAllOpenOrders()` so a relaunched scheduler sees its prior sessions' orders. Tests: `tests/test_broker_reliability.py`, `tests/test_broker_price_aware_resubmit.py`.
- **Submission reliability (`_submit_with_retry`):** transient failures (connection/timeout/pacing, `_is_transient_failure`) retry up to `broker_submit_retries` (2) with `broker_retry_wait_seconds` (5 s); hard rejects never retry. A duplicate guard (`_known_order_result`) checks whether the errored attempt reached the broker before retrying. Every retry is a marketable LMT capped at `broker_limit_cap_bps`. Failures persist as `SUBMIT_FAILED`/`STALE_CANCEL`/`SETTLE_*` rows in `broker_orders`; per-run counters ride the report. **Connect retries** at sync start (`broker_connect_retries` 2 × 10 s). **Auto-reconnect:** every `IBKRBroker` method gates on `_ensure_connected()`, which redials a disconnected session (cooldown `broker_reconnect_cooldown_seconds` 60 s; explicit `connect()` calls bypass the cooldown). **Request timeout + sync watchdog** (freeze fix): `IB.RequestTimeout = broker_request_timeout_seconds` (45 s) bounds every ib_async request; a `threading.Timer` watchdog around `_broker_sync` (`broker_sync_watchdog_seconds` 600 s) logs CRITICAL + `os._exit(1)` on expiry (recovered by `--supervise`). Tests: `tests/test_broker_reconnect.py`.
- **Order types:** `broker_order_type` = **`LMT` (default)** or `MKT` — a marketable limit at the model price ± the session's cap (`broker_limit_cap_bps` 20 RTH / `_extended` 80 / `_overnight` 150). The cap bounds the worst fill; a missed cap is re-anchored in-tick by settle and killed if still unfilled. Off-RTH overrides the configured type to marketable LMT with `outsideRth=True` (IBKR rejects MKT off-RTH). Class-share tickers normalise both ways (`to_ib_symbol`/`from_ib_symbol`: yfinance `BRK-B` ↔ IBKR `BRK B`).
- **Execution measurement (persisted):** slippage (cost-normalized bps, entries + exits) + actual commissions, persisted per `sync()` to `broker_reconciles` + `broker_orders`. Each sync also captures account NAV (`get_account`) and IBKR's own account P&L (`Broker.get_pnl` → `reqPnL`: daily/unrealized/realized, fail-soft, best-effort/live-unvalidated).
- **Sizing** (`sizing.py`): `broker_sizing_mode` = `notional` (default: `broker_base_notional` in `broker_base_notional_ccy`, e.g. 2000 CAD, → USD via live FX in `fx.py`) or `equity_pct`. Both × the ledger's `position_size_multiplier`, with max-positions and max-gross-exposure caps (USD-normalised).
- **Idempotency:** `recommendation_id` is the IBKR `orderRef`; the reconciler enforces one broker order per client_ref (a duplicate is marked `DUPLICATE_REF_NOT_SUBMITTED`). A broker-health verdict (`_assess_broker_health`) + a price-provenance verdict (`_assess_price_provenance`, session bands `price_provenance_band_{rth,extended,overnight}_bps` 100/350/600, verdict in `gate_diag.price_provenance`) each mirror `_assess_llm_health` → CRITICAL log + email banner + `🔔` subject tag.
- **Ops:** IB Gateway must run alongside the scheduler and needs a ~daily re-login (IBKR auto-restart + IBController). Before enabling: `python -m src.broker.smoketest`, then `--order` for a 1-share round trip. **Gateway auto-recovery** (`src/broker/gateway_recovery.py`, `broker_gateway_auto_restart` on): when the gateway itself is the corpse (wedged-but-alive or down), `maybe_restart_gateway` kills the gateway java owning `ibkr_port` (or, if nothing is listening, identifies it by command-line signature via `_gateway_pids_by_signature`) and fires the `'IBC Gateway'` scheduled task. Fired from `reconcile.sync`'s connect-retry exhaustion and `ibkr._ensure_connected`'s wedge-forced redial failing. PAPER-ONLY (`ibkr_live` downgrades to CRITICAL log); cooldown `broker_gateway_restart_cooldown_minutes` 30; fail-soft. Tests: `tests/test_gateway_recovery.py` (conftest pins it OFF suite-wide).

Phased rollout: `dry_run` → `ibkr_paper` + reconcile (measure slippage / tracking-error / rejects) → `ibkr_live` (port 4001) with a capital cap. Plan: `~/.claude/plans/snuggly-munching-piglet.md`.

### Configuration

All settings live in `config/settings.py` as a `pydantic-settings` `BaseSettings` class. Every field maps to an env var (uppercase). Add new fields with defaults there; they become `settings.field_name` everywhere. **Never read `.env` directly — always go through `settings`.**

**Inert-config guard** (`tests/test_inert_settings.py`): fails on any NEW setting that is defined and documented but read nowhere (flipping it appears to work and changes nothing). A knowingly-inert setting must be listed in `KNOWN_INERT` and say so at its definition. Currently listed: `enable_combined_score_gate` / `min_combined_score_for_entry` (deliberately not wired — the ledger says a combined-score gate would block the LLM's best cohort, where the aggregator is undecided or wrong) and `schedule_daily` (a legacy cron string; the runner is driven by the RTH/extended/overnight windows). The guard exempts `*_long`/`*_short` names (resolved at runtime by `settings.directional`) and counts consumption by a `@property` on Settings.
