Guidance for Claude Code (claude.ai/code) working in this repository.

## Running the pipeline

```bash
python main.py                # Run once, console output only
python main.py --email        # Run once and send email report
python main.py --schedule     # Poll-loop runner
python main.py --supervise    # PRODUCTION (scripts/run_scheduler.bat): --schedule under an auto-restart supervisor
python main.py --dashboard    # Read-only monitoring dashboard (Plotly Dash via waitress)
python main.py --backfill     # Pre-warm OHLCV caches for the whole universe, then exit
```

**Scheduler** ticks on NYSE market days: RTH every 30 min 9:30–16:00 ET, extended 4:00–19:50, overnight 20:30–03:30 hourly on the overnight venue's Sun–Thu-night calendar. Emails fire at `scheduler_email_times` (04:00/09:30/16:00/19:50 ET); `SCHEDULER_EMAIL_EVERY_TICK=true` is the live setting → every slot. `email_on_problem` (ON) forces an out-of-schedule email on any broker/LLM/price health problem. Once per market day at/after `eod_maintenance_time` (16:20 ET) EOD maintenance (`enable_eod_maintenance`) runs in a **background thread** (single-flight; `runner._eod_work`: cache warm → `simulated_trades` retention → replay materialisation → walk-forward calibration → auto-refactor). A still-running EOD at the next day's slot is warned and skipped; `eod_replay_refresh_days` (45) is the size knob.

**`--supervise`** relaunches the scheduler if the process dies (e.g. the broker watchdog's `os._exit(1)`). A HANG is not caught by `--supervise` or Task-Scheduler restart-on-failure — both need the process to exit; the broker watchdog converts that hang class into an exit. **To STOP a supervised scheduler: kill the `--supervise` parent FIRST (so it can't respawn), then the `--schedule` child.** To restart, use `scripts/restart_all.ps1` — never ad-hoc `python.exe`, which is how duplicate schedulers appear.

`--backfill` is additive (merges into `cache/ohlcv/`, never deletes); `--backfill-30m` also warms the 30-min cache. Standalone: `python -m src.data.backfill [--days 730] [--with-30m] [--skip-daily]`. The daily cache is full-depth (Polygon serves 2006+; ~5,000 bars for ~950 names). Weekly is resampled from daily on demand; 30-min depth is Polygon-capped (~120 days).

Logs → `logs/llm_trader_YYYY-MM-DD.log` (7-day rotation). To force a fresh run ignoring caches, delete `cache/news_*.json` and/or `cache/snapshots_*.json`. **The OHLCV cache (`cache/ohlcv/`) and the DuckDB database (`data/llm_trader.db`) must never be deleted casually.**

**Trailing-NaN bar guard** (`cache.trim_trailing_nan_bars`, applied at PARSE time inside `load_ohlcv`). yfinance appends a NaN-Close row for the still-forming bar; an indicator handed one silently returns a different number. Only the trailing bar is trimmed and only on a missing Close. The guard lives at the market_data boundary — **scoring must never bypass `get_history`**. Tests: `tests/test_scorer_contract.py`.

**Intraday operation (no unclosed-bar look-ahead).** Marks and fills use **live** prices (`tracker._fetch_price`); the daily OHLCV feeding indicators is completed-bars-only (`market_data._drop_forming_bar` removes the forming bar until the 16:00 close). A **Hybrid** intraday overlay (`src/signals/intraday_timing.py`) affects entry/exit *timing* only: it defers an entry whose 30-min momentum strongly opposes it (`enable_intraday_timing`, ON) and can close on a hard intraday reversal (`enable_intraday_exit`, OFF). It never changes the daily-signal direction.

**Extended hours** (`extended_hours_mode` = `off | observe | trade`, live: **trade**). The runner ticks per `extended_windows` (`04:00-07:00@60,07:00-09:30,16:00-17:30,18:00-19:00@60,19:50-19:50` ET; `@MM` sets a per-window cadence). Extended slots are full trading ticks; `observe` mode runs analysis + persistence with zero ledger/broker mutation.

**Overnight session** (`overnight_hours_mode`, live: **trade**) on IBKR's overnight venue — Sun–Thu nights, 20:00–03:50 ET (`market_calendar.is_overnight_session_open`). Slots from `overnight_windows`. Overnight terms: modeled spread ×10, sizing ×`overnight_size_multiplier` (0.25), actionable threshold +10 pp (replaces, not stacks with, the extended +6 pp). Broker routes to the overnight venue (`broker_overnight_routing`, LMT-only, cap 150 bp); requires the gateway's API precaution bypasses in `C:\IBC\config.ini` (`BypassOrderPrecautions=yes` + `BypassRedirectOrderWarning=yes`). A refused overnight order counts as `overnight_deferred` and is resubmitted at the 04:00 pre-market open.

**Session classification** (`market_calendar.current_session` → `rth | extended | overnight`) is fixed once per run. `enable_extended_signal_profile` (**OFF**) governs whether the session changes the SCORE; with it off, scores are comparable across the day — one weight profile every session, `ext_gap` active in all sessions (reads 0.0 in RTH by design), no session-context prompt block. Independent of the flag: `extended_confidence_bump` (+6 pp) and `extended_size_multiplier` (×0.5).

**Extended trade lifecycle.** `_execution_iso()` returns *now* during RTH, extended-trade-mode and the live overnight session; closed venues, weekends and observe-mode snap to the next regular open. Every entry stamps `entry_session` (+ its sizing haircut); every close stamps `exit_session`. Costs are session-aware end to end (`spread._session_spread_multiplier`, `_pct_return`, daily-NAV anchors, `_normalize_closed_returns`, `_flip_trade`, live M2M). `reconcile.sync()` forces a marketable LMT outside RTH (IBKR rejects MKT there). Every perf surface accepts `session=`; the dashboard carries an RTH/Extended/Overnight toggle.

## Architecture

### Pipeline flow (`src/pipeline.py`)

`run_pipeline()` is the single entry point:

```
0.  Universe construction   — Static watchlist (always included) + dynamic discovery (trending, screener,
    macro→holdings, catalyst/analyst/earnings expansion, related-company peers). Discovery gate drops junk
    (is_valid_ticker), exotic security types (is_exotic_security), and microcaps below the OBSERVATION floor
    (discovery_min_price $1 / discovery_min_dollar_volume $1M — kept LOW so thin names keep accruing data).
1.  News & sentiment feeds  — RSS (CNBC/Seeking Alpha/Yahoo) + press wires + FDA/MedWatch + per-ticker Google
    News, all fetched FRESH every tick (the reactivity fast-lane) — plus NewsAPI, per-ticker yfinance news,
    Polygon (Benzinga), 8-K filings, Reddit, Quiver alt-data, analyst ratings, EPS surprises, short interest,
    Massive ticker events. All normalised to NewsArticle; merged pool URL-deduped.
2.  Market snapshots        — Polygon batch primary (real-time → price_source="live") → yfinance per-ticker →
    deterministic grouped-daily close (price_source="prev_close"). Indices/futures/OTC route through yfinance.
3.  Smart-money + macro     — Insider/congressional trades, options flow, SEC filings (13D/G, 144, 13F, Form 4),
    plus market-context fetchers (FRED, COT, VIX, MOVE, DIX, breadth, credit, bond/global macro, sector rotation).
3X. Regime & timing layers  — Macro Regime Filter, Market Mode, Catalyst Timing — gate BUYs, adjust thresholds/weights.
3#. Per-ticker scorers      — the 27 weighted methods + the panel-first set (below). Each returns [-1, +1].
3B. Broker advisor group    — src/signals/broker_advisor.py (enable_broker_advisor, currently OFF; needs broker_mode != off).
3M. Massive technicals      — server-side RSI+MACD composite scored as `massive`, run alongside our own `tech`.
3F. Fundamentals overlay    — Massive/Polygon ratios → <fundamentals_context> prompt overlay (§28) + directional
    factors f_value/f_quality/f_growth/f_short_squeeze (panel + small additive combine overlay).
3G. Corporate actions       — dividends + splits → §29 mechanics overlay + f_split / f_dividend factors.
4.  Signal aggregation      — aggregator.py combines per-ticker scores into a TickerSignal; sector_pairs.py finds opposites.
5.  Recommendations         — claude_analyst.py → BUY/SELL/HOLD/WATCH; cross-engine fallback; rule-based last resort.
6.  Performance tracking    — tracker.py + daily_nav.py: paper trades, M2M updates, path-faithful daily compound.
7.  Charts + email          — charts/, email_sender.py.
```

**Two-tier liquidity.** A name clearing the observation floor but below the **TRADE floor** (`trade_min_price` **$5** / `trade_min_dollar_volume` **$5M**, `enable_trade_liquidity_gate`) is **OBSERVE-ONLY** — fully scored and persisted to the `signals` panel but gated out of actionable trades by **Gate 4** (`pipeline._is_tradeable`, fail-closed via `is_liquid`). The pinned watchlist bypasses the DISCOVERY gate only (`_protected`), **NOT Gate 4** — pinning a thin name gets it analysed, not traded.

### Data flow design

**Two tiers of data.** Per-ticker signals scored `[-1, +1]` and combined into a `TickerSignal`; macro context (FRED, COT, …) passed as structured prompt blocks for the LLM to apply as regime overlays. News sentiment is the *level*, sentiment velocity the *rate of change*, trend strength the trend *quality* (distinct from momentum's return *size*). A continuous `coherence_factor` ∈ [0.45, 1.35] dampens confidence when methods disagree.

**Score-sign convention** (the invariant the combine, IC and inversion depend on — see the `aggregator.py` docstring): EVERY method's score sign is the predicted direction of the STOCK (`+` = up, `−` = down, position-independent); mean-reversion methods bake the reversal INTO the sign; `|score|` = confidence.

**Method set.** 27 weighted (`aggregator._BASE_WEIGHTS`): news 0.40, tech 0.30, insider 0.30, sector_momentum 0.20, pattern/momentum 0.18, massive/put_call/oi_skew/money_flow/trend_strength/pead/ext_gap/mom_12_1/hi52 0.15, iv_rank 0.13, sent_velocity/max_pain/vwap/iv_expr/coint/st_reversal/ml_ohlcv 0.12, broker_advisor/rsi2_rev/dloc_rev 0.10, market_momentum 0.08. **Panel-first at weight 0** (scored, persisted and IC-tracked; NOT in the combine, coherence, `sources_agreeing` or family votes until the panel proves them): `news_shock`, `squeeze`, `iv_term`, `avwap`, `resid_mom`, `vol_profile`. Additive overlays outside the normalised pool: `cross_sectional`, the 6 `f_*` factors, the 4 trend-predictability methods.

**PIVOT EVALUATION BASIS (standing directive).** The signed PIVOT target (`pivot_target.next_pivot_targets` — % return from close to the next pivot's EXTREME on the **H/L basis**: swing highs on each bar's HIGH, swing lows on its LOW, `PIVOT_BASIS="hl"`, `pivot_min_move_pct` confirmation) is the evaluation basis for every DECISION surface; FIXED horizons (1d/3d/1w/…) remain for dashboard monitoring, HOLDING-PERIOD estimation and EXIT machinery. Concretely: the sim/directional panels carry a `pv` pseudo-horizon (`simulated_trades.PIVOT_LABEL`), the signals panel carries `fwd_ret_pivot`/`end_date_pivot`, and the IC weight tilt, the IC-disproof filter, per-side weights, the inversion panel arm and the method STATES all read it. Stackers train on the within-day rank of the pivot target (`stacker_label_basis="pivot_rank"`, fail-soft to `rank_5d` below 500 settled rows). Point-in-time: a pivot label exists only once its CONFIRMING bar is inside the visible window (as-of truncation in `_pivot_targets`/`build_panel`). `method_horizon_days`/`best_days` stay on the fixed curve because exits need a NUMBER OF DAYS. Every fixed label stays computed; reverting any consumer is one setting. Tests: `tests/test_pivot_eval_basis.py`. History: `memory/pivot-eval-basis-2026-08.md`, `memory/pivot-horizon-target-2026-08.md`.

**Everything downstream of the entry decision uses the same target**: `predictability_sizing`, `ml_exit`'s label (the ORIENTED remaining move to the next pivot), `confidence_components`, `arm_eval`, `source_performance`, `ticker_performance`, `price_volume_perf`, the `predictability` feature IC, `exit_panel`, `exit_forward`, and the dashboard sim/exit IC tables. NOT flipped (no forward-label choice exists): calibrations judging a trade's own realized P&L, execution-cost calibrations, and holding-period machinery.

**METHOD RANK BASIS** (`method_score_basis="rank"`). The combine — and everything keyed on the same map (coherence, `sources_agreeing`, family votes) — consumes each method's **CENTERED WITHIN-RUN RANK**, not its absolute score. Zeros ABSTAIN (never ranked); a method with < `method_rank_min_views` (5) views this run gets **WEIGHT 0** (raw scores stay in the map; the method rides the `abstained` set, which zeroes its weight and drops it from coherence / `sources_agreeing` / family votes, exactly like a win-rate-filtered method). **Consumption-time only:** `build_signals` runs two phases (parallel raw scoring → per-method cross-section ranking → serial continuation combine), and every persisted surface — TickerSignal fields, the `signals` panel, trade attribution, the stacker and ml_exit feature vectors — keeps the RAW score, so no scorer epoch fires and history stays re-validatable. `method_score_basis="absolute"` reverts the combine byte-for-byte. Tests: `tests/test_method_rank_basis.py`.

- **Payoff-shaped rank mapping** (`src/signals/rank_shaping.py`, `enable_rank_shaping` ON): each method's percentile maps through its own SHRUNK measured rank→pivot-payoff decile curve (per-decile shrink toward the method's OLS line, `rank_shape_prior_n` 200 → observation-weighted DEMEAN → normalize), so a method whose extreme readings historically mean-revert contributes a REVERSED signal at the extreme. Identity fail-soft below `rank_shape_min_rows` (500) or amplitude < 0.05%. asof-registered; TTL 6h.
- **Tradeable rank pool** (`rank_tradeable_only` ON): ranks are computed over the Gate-4-eligible names only (cache-only `is_liquid`, budget n=0 — never spends API calls); every OBSERVE-ONLY view is INTERPOLATED against that same distribution (equivalent average-rank, clamped). Thinness is judged on the tradeable count; fail-soft to full-universe ranking when the pool is < 30.
- **Bands and scale.** Direction fires per side: `rank_diff_threshold_long` **0.324** / `_short` **0.346** (bullish ≈ the tradeable top 10%, bearish ≈ the bottom 5% — asymmetric because sell-heavy books were measured to lose), symmetric fallback `rank_diff_threshold` 0.182 when the pins are None. `raw_confidence` divides by `rank_raw_confidence_scale` **0.642**. The absolute basis keeps 0.15 / 0.5.
- **Resolution is centralised**: `aggregator._direction_bands(combine_source)` and `_raw_confidence_scale(combine_source)` are the ONLY places these are decided, because the cross-sectional overlay re-derives both on its adjusted score and a second copy has drifted twice.
- **Absolute-basis SHADOW combine** (`signals.combined_score_abs` + buy/sell twins) rides every row so rank-vs-absolute accrues as a live A/B. It carries the SAME additive overlays as the live total, so it is the same QUANTITY and differs only by basis; under `method_score_basis="absolute"` the two are equal pre-ML-arm.

**Buy/sell split combine.** Each weighted method's inversion-corrected view (`eff`) decomposes into a BUY component `max(0, eff)` and a SELL component `max(0, −eff)`; each side is weight-averaged over the methods HOLDING that view only (its own camp — abstainers and the opposing camp don't dilute a side). `combined_buy_score` / `combined_sell_score` are the two camps' convictions and **`combined_score` = their DIFFERENCE**. Camp SIZE is judged by the machinery built for it (coherence, Gate 1b, family agreement), not by re-diluting the score. Both sides are persisted, ride the sighted prompt, and are IC-monitored as `cmb_buy`/`cmb_sell`. The 6 `f_*` factors and the 4 trend-predictability methods are additive overlays landing on the DIFFERENCE; the trend methods are active only in their trend CONTEXT, each ×a learned orientation ∈ [−1, +1] (`trend_predictability.calibrate_trend_orientation`), single weight `trend_method_weight` 0.10. Tests: `tests/test_buy_sell_split.py`.

**Cross-family agreement + tape confirmation** (`src/signals/agreement.py`). `METHOD_FAMILIES` rolls the weighted methods into 7 independent INFORMATION families (Sentiment / Price-Trend / Rel-Strength / Volume-Flow / Options / Smart-Money / Event-Arb), so correlated methods are one voter, not many. Per-family magnitude-weighted votes (`family_vote_threshold` 0.05) are counted against the combined direction, exposed to the synthesis prompt, folded into confidence via a breadth factor ∈ [1 ± 0.12] (an opposing family drags 1.5× as hard as an aligned one helps), and stamped on new trades. **Tape confirmation** is the score-independent half: a raw price/volume state composite from cached daily OHLCV that qualifies agreement rather than joining the combine (confidence × `1 + 0.08×(tape × direction)`), persisted as the `fam_net`/`tape` pseudo-methods. `enable_family_agreement` / `enable_tape_confirmation` both ON. Tests: `tests/test_family_agreement.py`.

**Weighting stack** (multiplicative, then normalised across active methods): hand-set `_BASE_WEIGHTS` → market-mode profile → **win-rate adaptive** (`enable_adaptive_weights`, tilts by each method's solo win rate, Bayesian-shrunk) → **IC-informed adaptive** (`enable_ic_weights`, confidence-gated: tilts by reliability-adjusted IC over the unbiased panel at the PIVOT pseudo-horizon, only for methods whose mean-daily-IC t-stat ≥ `ic_weight_min_t` 2.0; a method below the gate keeps base weight) → OpEx max-pain boost → extended-session overlay. Cached `ic_weight_cache_seconds`.

**Win-rate HARD filter** (`enable_winrate_method_filter` ON). Any `_BASE_WEIGHTS ∪ INVERTIBLE_OVERLAYS` method whose GROSS solo win rate (`compute_solo_method_gross_winrate`) is `< winrate_filter_threshold` (0.50) over `≥ winrate_filter_min_trades` (10) attributed trades is DROPPED: weight → 0 (survivors renormalise), excluded from coherence / `sources_agreeing`, hidden from the synthesis prompt. Inverted methods exempt; a method below `min_trades` keeps full weight; `build_signals` suppresses the filter for any run where it would empty the book. Dropped methods are still scored, persisted and trade-attributed, so they can re-earn their place. Overlay filter/inversion is carried by `aggregator._overlay_factor(method)`.

**Per-SIDE win-rate filter + weighting** (`enable_side_winrate_filter` / `enable_side_adaptive_weights`, both ON). A method's bullish and bearish calls are separate skills: each camp is filtered and weighted on ITS OWN record (`side_filtered_methods(side)`, `side_weight_multipliers(side)` — Bayesian-shrunk toward 50% by `side_weight_prior_n` 10, clamped 0.5–2.0). Guard: the per-side filter is suppressed for a camp it would EMPTY. Tests: `tests/test_side_winrate_filter.py`.

**Stream-separation invariant.** The per-side filter reaches **coherence, `sources_agreeing` AND family agreement**, not just the combine — `aggregator` applies `_side_ok(method, eff)` when building `method_score_map_eff`, keyed on the method's own effective sign, so all four see the same book. Correct by design and NOT changed: the synthesis prompt applies only the GLOBAL filter (the LLM picks direction), and `broker_view` charges no modelled borrow.

**Method inversion** (`inverted_methods`, `aggregator._inverted_methods`). A method whose RAW score is reliably anti-predictive net of beta is sign-flipped in the combine and lifted off the IC floor to base weight; the panel keeps the RAW score so the inversion stays re-validatable. **Automatic inversion** (`enable_auto_inversion` ON) requires TWO bars: the gross solo win rate significantly below 50% by a one-sided exact binomial at `inversion_alpha` (0.05) AND replication on the independent panel arm, and the FLIPPED view itself clearing `winrate_filter_threshold`. Evidence floor `inversion_min_trades` (30). Strictly PER-METHOD, never per-FAMILY. Manual pins always win; auto-detection is fail-soft. **Currently `INVERTED_METHODS=` is empty and the detector selects nothing.** Tests: `tests/test_auto_inversion.py`, `test_panel_inversion_arm.py`, `test_overlay_inversion.py`.

**Market-relative WEIGHTING** (`src/analysis/market_relative.py`, ON). An absolute win rate cannot separate "this signal works" from "the market went up", so per-side adaptive weighting reads MARKET-RELATIVE hit rates from `compute_directional_perf` at the PIVOT pseudo-horizon, falling back to the absolute ledger basis when the panel is unavailable. The neutral point is the MEASURED baseline (≈48%), not 50% — the cap-weighted index beats its typical constituent. Scope: weighting and inversion use this basis; the hard filter, sizing, edge blend and all P&L reporting stay ABSOLUTE. **The HARD FILTER judges on PROMOTION LOGIC** (`enable_market_relative_filter`): a weighted method is dropped only when the promotion statistic itself — market-neutral per-day IC (`both`-side ICIR) — is SIGNIFICANTLY negative (`t ≥ ic_weight_min_t` 2.0) on the pivot pseudo-horizon with ≥ `market_relative_min_obs` (200) rows; no judgeable horizon → kept at full weight (unproven ≠ disproven — the same bar to lose weight as to earn it). Tests: `tests/test_market_relative_weighting.py`.

**Per-method HORIZON SKILL — three states** (`src/analysis/method_horizons.py`, `enable_method_horizons`). Measured over the solo-method simulation (`simulated_trades`) gated at `buy_sell_diff_threshold`. The STATE is judged on the SIGNED PIVOT TARGET (`win_pv`, one binomial at each name's own natural horizon), while the fixed 1/3/5/10d curve decides `best_horizon`/`best_days` — the HOLDING PERIOD the exits use. **PROVEN** keeps full weight; **DISPROVEN** is dropped by the filter; **UNPROVEN** is scaled by `unproven_weight_multiplier` (0.5). This basis SUPERSEDES the trade-ledger filter when available (the ledger is selection-biased). *Known basis gap:* that gate fires at 0.15 on each method's ABSOLUTE panel score while the live combine consumes ranks, so the simulation no longer mirrors the live decision rule — revisit once the rank basis has accrued panel history. CLI `python -m src.analysis.method_horizons`.

**Scorer-version epochs** (`src/signals/method_epochs.py`). `METHOD_SCORER_EPOCH` maps a method → the UTC INSTANT its current implementation went live; `score_is_comparable(method, when)` gates the win-rate filter and adaptive tilt; `epoch_for(method)` gives date-granular consumers the day AFTER a mid-day change; `confidence_is_comparable` / `CONFIDENCE_EPOCH` do the same for confidence. Fail-OPEN. Applied at three choke points: `signal_panel.build_panel` (masks superseded scores/confidence to NaN), `simulated_trades.load_sim_trades` → `_drop_superseded_scorer_rows`, and `compute_macro_eval` bundles. Register **categorical changes only** (the output means something different), not refinements. **Whenever you change what a scorer OUTPUTS, add the instant here** (or let auto-refactor derive it). Two traps: a freshly-epoched method falls below `winrate_filter_min_trades` and keeps FULL weight ("unproven", not "disproven"); and **an epoch registration breaks every test fixture that borrowed that method's name for unrelated behaviour** — move such fixtures to an un-epoched method. Set the instant from the ACTUAL restart, not from intent. Tests: `tests/test_method_epochs.py`, `test_simulated_trades.py`.

**Replay** (`src/analysis/replay.py`). Where the epoch mask achieves comparability by discarding evidence, replay REGENERATES it — faithful for the OHLCV-derived methods (`schema.REPLAYABLE_METHOD_COLUMNS`: tech, vwap, momentum, money_flow, trend_strength, iv_rank). The join must be **run-exact** (`restore_replayed` keys on `generated_at`) and **time-aware** (each row's own `generated_at` decides visible history, the signal-date bar existing only for a run at/after the 16:00 ET close). `build_panel` overwrites replayable superseded scores from `signals_replay`, and the epoch mask SKIPS restored cells. Also recovers market-condition context (`atr_pct`/`bb_width_pct`/`vol_ratio`/`tape_score`) and `movement_factor`. `pattern` and `sector_momentum` are EXCLUDED (live registry / current-time fetch); everything else needs an unstored point-in-time feed and stays masked. Two split guards refuse rescaled rows. No-look-ahead is enforced by adversarial probes (`tests/test_replay.py`). Materialised by EOD or `python -m src.analysis.replay --write`; `--validate` prints the fidelity table — **run it after any scorer change.**

**Walk-forward calibration** (`src/analysis/asof.py` + `walkforward.py`, table `weight_history`). `analysis_asof(date)` installs a point-in-time cutoff honoured at the same three choke points the epoch mask uses, so the weighting stack recomputes seeing only strictly-earlier rows. The ledger filter keys on the EXIT, not the entry; open trades are excluded. `analysis_asof` flushes every layer's TTL cache on entry AND exit. `backtest.run_backtest(walk_forward=True)` is the DEFAULT and resolves weights per signal date via `weights_for_date`. Kept current by EOD (`walkforward_eod_days` 3). Tests: `tests/test_walkforward.py`.

**Automatic database refactor** (`src/analysis/code_version.py` + `refactor.py`, `enable_auto_refactor`). Every method maps to its module(s) (`METHOD_SOURCES`; `unmapped_methods()` must stay empty, a test asserts it), fingerprinted by **normalised AST** (comments/formatting don't move it; a changed constant does). Repair runs in DEPENDENCY ORDER: DATA (replay) → EPOCHS (derived from `code_versions.first_seen_at`) → WEIGHTS (walk-forward) → DERIVED (backtest). A replayable method is REGENERATED; a non-replayable one can only be MASKED, which withholds real history, so masking is opt-in (`refactor_auto_epoch`, **OFF**) and reported. Fingerprints advance only on FULL success. CLI `python -m src.analysis.refactor --check|--apply`.

**The one genuine limitation is circularity, applying only to DERIVED values:** method scores don't depend on the weights (replaying + calibrating weights from the result is sound), but `combined_score`/`confidence`/gate outcomes DO — replaying those with today's weights is a BACKTEST: inspect, never re-calibrate the same weights from it. `signals` is never overwritten: it records what actually happened.

**STANDING RULE — a calibration may only fit data the CURRENT code produced.** Panel side: `build_panel` masks superseded scores and confidence to NaN. Ledger side: calibrations reading trade fields gate explicitly (`score_is_comparable`, `confidence_is_comparable`). Both fail OPEN. Satisfy the rule by RESTRICTING each calibration to comparable data, never by rescoring history onto the current formula. The Bayesian shrinkage every calibration carries makes the smaller clean sample safe.

**Significance tests are dependency-free by rule** (`src/analysis/stats.py`). scipy is not a declared dependency, so a `try/except` around `scipy.stats` would make the except branch the only one that ever runs. Exact binomial and Welch's t-test live in-tree, and the call sites deliberately do NOT wrap them in a bare except. Degenerate input returns NaN ("no verdict"), never 0.0. **General rule: an optional import guarding a verdict the system ACTS on is an invisible off switch, not a graceful fallback.**

**Silent channels.** The project configures **loguru** sinks only, so `logging.getLogger(__name__)` in `src/` yields a handler-less logger that discards everything — use `from loguru import logger`. `tests/test_inert_settings.py::test_no_module_logs_into_a_silent_channel` scans `src/`. **The unifying rule (unread setting, unreachable import branch, sinkless logger, a value computed but never stored, a constant duplicated across two sites): a mechanism whose failure mode is indistinguishable from normal operation must be verified mechanically, never by review.**

**Confidence-component isolation** (`src/analysis/confidence_components.py`). The seven ingredients (`raw_confidence`, `coherence_factor`, `movement_factor`, `volume_factor`, `family_conf_factor`, `tape_conf_factor`, `sector_conf_factor`) are persisted verbatim on `TickerSignal` and the `signals` panel, and their product reproduces the stored `confidence` exactly — which is what makes the isolation meaningful. All three confidence sites (score pass, cross-sectional overlay, sector-alignment pass) call ONE `aggregator._confidence_from`; the overlay RE-DERIVES from the adjusted score rather than rescaling the already-rounded value. Seven variants are reconstructed (`raw` alone and `raw × exactly one factor`, never stacked) and evaluated against the direction-oriented forward return — pivot target first, fixed horizons as monitors. Entry- and exit-side. `python -m src.analysis.confidence_components [--source entry|exit]`.

**Multi-timeframe technical signals** (`src/signals/multi_timeframe.py`, `enable_multi_timeframe_signals` ON). The 8 OHLCV methods (tech, vwap, momentum, money_flow, trend_strength, iv_rank, pattern, sector_momentum) are each computed on **30-min**, **daily** and **weekly**. Every OHLCV scorer takes an optional `df=`/`interval=` (`df=None` reproduces the daily output bit-for-bit). `build_signals` feeds `combined_score` a per-method renormalised blend (`tf_blend_30m/1d/1w` 0.20/0.60/0.20; a 0-score timeframe abstains; revert with `tf_blend_1d=1.0`). The daily score stays in each `*_score` field; 30-min/weekly ride `timeframe_scores` → panel `*_30m`/`*_1w` columns. 30-min history is yfinance-capped at ≤60 days and 429-prone. Tests: `tests/test_multi_timeframe.py`.

**News-family continuity.** The rank transform needs cross-sectional VARIANCE — a tie group collapses to one shared average rank — so the qualitative-data methods are kept continuous by construction. `insider` weights each filing by log-dollar notional (**exact `InsiderTrade.notional_usd` when the source knows it**; 13F holdings, Form 4 buys and options sweeps all compute one — bucket midpoint otherwise), per-day recency decay on the transaction date (7d half-life, 45d max), a seniority multiplier and a bounded disclosure-lag prior. `news` scales the LLM verdict by evidence MASS (Σ per-article recency weights) × a smooth source-diversity curve, and the sentiment prompt carries a two-decimal cross-sectional precision mandate. Both are epoch-registered, and both persist at **6 decimals** on the `TickerSignal` — the persisted value is what the rank transform orders on, so a coarse `round()` there silently re-merges what the scorers separated (pinned by an AST test). Two traps: the sentiment cache key must stay salted with `_SENT_PROMPT_VERSION` (or a prompt edit keeps serving old-prompt verdicts for the TTL), and **adding a model field does not populate the caches that feed it** — `cache/form4_buys_*.json` is date-keyed, so a field-level fix lands only as its caches roll over. Residual ties are GENUINE (congressional ranges by law, 13D/G percentages, Form 144 "see filing"): identical evidence *should* share a rank, and manufacturing variance there would be inventing signal. **0% tie mass is not the target; zero ARTIFICIAL ties is.** Tests: `tests/test_news_family_continuity.py`.

**`news_shock`** (`src/signals/news_shock.py`, panel-first weight 0): `sign(news) × clip(log2(mass_today / baseline)/3, 0, 1)` — abnormal news ATTENTION in the direction of the news read, full score at 8× the ticker's own normal. Baseline = the per-ticker trailing median of `signals.news_recency_mass` (forward-collected, with `news_article_count`) over `news_shock_baseline_days` (20), needing `news_shock_min_days` (5) covered days — so the method abstains until history accrues. Below-baseline attention is NOT a fade (scores 0); no news direction, no baseline, or a failed baseline query all abstain. One baseline query per tick (20-min TTL, asof-registered).

**Macro Regime Filter** (`macro_regime.py`): hard pre-filter after the LLM runs. Reads VIX, MOVE, bond internals, global macro, FRED, breadth, credit, DIX; computes a weighted composite regime (PANIC|RISK_OFF|CAUTION|NEUTRAL|RISK_ON) that raises the confidence threshold. **BUY entries are blocked entirely during PANIC**; **RISK_OFF takes a size haircut** (`enable_regime_size_haircut`, `risk_off_size_multiplier` 0.5) rather than the BUY ban. `macro_regime_exit` closes longs in PANIC (and RISK_OFF only when the haircut is disabled — a guard forbids any regime both admitting longs on entry and closing them on exit). **Fails CAUTIOUS, not open:** below `macro_regime_min_inputs` (3) feeds, a permissive verdict is forced to at least CAUTION. Tests: `tests/test_regime_haircut.py`.

**Market Mode Switching** (`market_mode.py`): adjusts the weight profile by market structure. TRENDING → up-weight `tech`/`news`, down-weight `vwap`/`put_call`. CHOPPY → the reverse.

**Catalyst Timing** (`catalyst_timing.py`): computed BEFORE synthesis → prompt §26. Three mechanisms: Earnings Blackout (removes tickers within 2 days of earnings, with a post-release exemption at `days_since_report ≤ 1`), OpEx Amplifier (boosts `max_pain` weight during OpEx week), 8-K + Insider Buy WATCH elevation. Enforcement stays mechanical post-synthesis. Tests: `tests/test_catalyst_prompt.py`.

**8-K filings, Google Trends, Reddit, analyst ratings, EPS surprises, short interest are treated as news** — all return `List[NewsArticle]` and are scored by the same sentiment pipeline. **Smart money signals** (insider trades, options flow, SEC filings) return `List[InsiderTrade]` and combine into a single `insider_score`.

**Method attribution** (`tracker.py`): every new trade stores the raw method scores (`tracker._ALL_METHODS`) at entry plus `methods_agreeing` and `dominant_method`. `get_performance_for_email()` returns `performance_table` (total → asset → direction → session → method), `trades_svg` (inline SVG, no kaleido), `portfolio_metrics`, `solo_method_perf`, `llm_perf` (per-engine, deduped to the engine's last call per ticker-day, anchored at the rec-time snapshot, with a split guard; rule-based fills stamped `RULE_FILL_MODEL` and ranked LAST), `method_eval_stats`, `method_order_by_winrate`, `attributed_count`. Legacy trades without `methods_agreeing` are excluded from method rows but included in the others.

### Performance calculation

Two engines side by side, both rooted in the *real* observed prices stored on each trade.

**Per-trade `return_pct` (buy-and-hold, cost-aware) — `tracker._pct_return()`**

```
cost_in  = _one_side_cost(entry_price, asset_type)            # half-spread + commission
cost_out = _one_side_cost(exit_or_current_price, asset_type)
BUY  : eff_entry = entry × (1 + cost_in);   eff_exit = exit × (1 − cost_out)
       return_pct = (eff_exit − eff_entry) / eff_entry × 100
SELL : eff_entry = entry × (1 − cost_in);   eff_exit = exit × (1 + cost_out)
       return_pct = (eff_entry − eff_exit) / eff_entry × 100
```

**Per-trade cost attribution** (`sim_per_trade_cost_attribution`, ON). Each leg is charged the best-fitting cost by a four-tier hierarchy (`spread.resolve_leg_cost`): the leg's OWN realized cost if it FILLED → the tick average of filled trades (≥3 legs) → the time-of-day PERIOD average → the modeled `_one_side_cost`. Ledger purity is preserved — every sim trade still assumes it fills; only the COST is sourced more precisely. Both return engines share `resolve_trade_leg_cost`.

**Short borrow carry** (`enable_short_borrow_cost`, `short_borrow_annual_pct` 3.0%): a direction-asymmetric HOLDING cost (SELL legs only) charged per **calendar** day, subtracted in `_pct_return` and per-day in the daily-NAV walk. Prefers the broker's real fee over the setting.

**One-way cost** (`spread._one_side_cost`) = half-spread + commission. The commission term is a deliberate **fee ceiling, not a best estimate** (`ibkr_fixed` default: max($1.00, $0.005/share)), capped at 1% of trade value, × `commission_buffer` (1.5). **Real-fill calibration** (`sim_use_real_fill_costs`, ON): once ≥10 actual **LMT** fills exist, `calibrate_sim_costs()` measures the average all-in one-way cost and installs it via `spread.set_real_cost_override()`. A sanity band (±2%) discards legs with a stale `model_price`. Residual bias: the sample is only filled legs (~13% fill rate), so it understates the intended-trade cost. Called before the tick's normalize/M2M/entry steps so a run uses one cost basis throughout.

**Path-faithful daily compound — `daily_nav.compute_compound_return(trades)`.** Per trade: load OHLCV closes → build chronological marks `(entry_date, eff_entry)` → every cached close strictly between → `(exit_date or today, eff_exit)` → per adjacent pair `r_d = sign × (mark_d − mark_{d−1}) / mark_{d−1}`. Portfolio: group `(date, daily_return, weight)` by date → `Σ(r·w)/Σ(w)` → compound sequentially. **Deterministic given the database.** Time-window variants filter by `entry_date` before aggregating; the cost basis is always from the full ledger.

**Summary statistics — `tracker._compute_segment_stats()`** (any slice): `trades`, `win_rate` (GROSS — see below), `compound_return` (daily walk), `avg_return` (equal-weighted), `wtd_avg_return` (capital-weighted), `best`/`worst`. Open trades' `return_pct` is the live M2M so they contribute to every metric.

**THE WIN-RATE CONVENTION (standing directive): every win rate in the system is GROSS; costs are measured by the RETURN metrics only.** A win rate asks one question — did the position move the way it was supposed to, on raw prices. A cost-adjusted win rate silently answers *two* ("was the direction right?" and "was the move bigger than the round trip?"), and the second is an execution property that moves with the spread model, the venue and the session — so the same signal would score worse for being traded in wide markets, and every cost recalibration would rewrite the win rate of history that did not change. Canonical helpers: `tracker.gross_return_pct(trade)`, `is_gross_win(trade)` (`None` when prices are unusable — such trades leave BOTH numerator and denominator, so a data gap can't masquerade as a bad signal), `gross_win_rate(trades)`. Applies to every breakdown, eval row, sizing calibration, `broker_view`, `source_performance`, `pattern_registry`, `confidence_calibration`, `regime_performance`, `policy_eval` and the equity chart. Panel/simulated surfaces were already gross by construction. Pinned by `tests/test_gross_winrate_convention.py`, whose decisive case is a right-direction trade whose move was smaller than the round trip: a WIN with a negative return, both in the same stats dict.

**Hypothetical solo & eval stats.** If a method's sign matches the actual action → use the trade verbatim; if it disagrees → `_flip_trade()` returns a same-ticker/same-dates dict with action inverted and `return_pct` re-derived. Conviction bands (`_eval_stats`): Low 0.10–0.35 / Medium 0.35–0.65 / High 0.65+ on `|method_score|`.

**Self-calibrating parameters.** Frozen constants are replaced by values learned from the system's own tables through one idiom (documented prior → evidence → Bayesian shrinkage → clamps → fail-soft to the static setting), all reported to the calibration registry (`src/performance/calibration.py` → `gate_diag["calibrations"]` → the Data Quality tab): per-session real-fill costs, the derived horizon cost hurdle, the engine-relative actionable threshold, the calibrated exit-confidence floor, breadth sizing, the expected-edge sizing blend, the predictability sizing tilt, and the edge-decay time-stop window. Risk guardrails (liquidity floors, exposure caps, wipe guards, order-cap ceilings) and the calibrations' own meta-parameters stay fixed.

**Direction-scoped parameters** (`config.settings.directional(name, direction)`): resolves `{name}_long` / `{name}_short` when set, else the shared `{name}`. Every override defaults to None (inert). Splits are justified where the asymmetry is STRUCTURAL or a threshold SWEEP is stable across a wide band — never a single point estimate. Two are MEASURED per side rather than pinned:

- **Per-side actionable threshold** (`tracker.calibrate_side_threshold`, `enable_side_threshold_calibration`). Gate 1 is the highest-leverage parameter, so this is the most conservative split: Bayesian-shrunk by `side_threshold_prior_n` (40), capped at `side_threshold_max_adjust` (+0.04), and it can only TIGHTEN. Evidence is whether confidence DISCRIMINATES on that side (per-direction Spearman of entry confidence vs realised return). Surfaced in `gate_diag.threshold_adj_buy/sell`; pin with `actionable_threshold_adj_{long,short}`.
- **Per-side horizon ramp** (`tracker.calibrate_horizon_ramp`, `enable_horizon_ramp_calibration`). `horizon_expiry_floor_mult` resolved per DIRECTION from the gap between what `horizon_expired` trades returned and that side's other exits (negative → tighten, positive → loosen). Bayesian-shrunk by `horizon_ramp_prior_n` (30), clamped ±30%, floored at 1.0. Tests: `tests/test_directional_params.py`.

**Trade lifecycle — `tracker.py`**

| Function | When | What it does |
|---|---|---|
| `record_new_trades()` | After the LLM produces recommendations | Opens a trade per actionable BUY/SELL; stamps `entry_datetime`/`entry_price`/`entry_session`; sizes via the chain below; stores all raw method scores + breadth/predictability fields + `dominant_method`. |
| `close_trades_on_signal_reversal()` | Before opening new trades | Serves only legacy/rule-based-opened trades (LLM-opened positions are owned by the hold-review). |
| `_refresh_open_trade_ohlcv()` | First step of `update_open_trades()` | Force-refreshes OHLCV for every open-trade ticker. |
| `_normalize_closed_returns()` | Second step | Idempotently rederives `return_pct` for every closed trade through the current spread model. |
| `update_open_trades()` | Each tick, BEFORE Step 4 | Refreshes `current_price`/`return_pct`. **No time cap** — positions are never closed on age. |
| `monitor_open_positions()` | Each tick, after the above | The primary exit. See below. |

**Sizing chain (`record_new_trades`).** compressed confidence ramp (`confidence_size_span` 0.5 → max 1.5×) × **agreement-breadth tilt** (self-calibrating, set-size-normalized — breadth was the strongest entry-time discriminator) × **expected-edge blend** (`performance/edge_sizing.py`, ridge model whose say grows with closed-trade evidence, inert below 20 closes) × **predictability tilt** (`performance/predictability_sizing.py`, sizes up forecastable-direction names, never a gate) → **regime size haircut** (RISK_OFF ×0.5) → correlation-aware haircut (scale-down vs same-direction open peers, hard skip at the correlated-exposure cap) → `extended_size_multiplier` (×0.5 extended / ×0.25 overnight).

**Exits (`monitor_open_positions`, `enable_llm_hold_review` + `enable_pinned_hold_review`, both ON).** `pipeline._build_hold_reviews` re-judges every LLM-opened position on EVERY tick with the SAME synthesis AND sentiment engines that opened it, on freshly refetched news + prices — an apples-to-apples same-engine comparison. **Latency overlap** (`enable_hold_review_overlap`, ON): the review pipeline runs CONCURRENTLY with main Steps 4–5, joined before the monitor runs; provenance-safe (forced-engine calls don't write run meta / sentiment tallies). No review this tick (opener engine failed) → hold. `enable_pinned_hold_review=false` → cheaper fallback; `enable_llm_hold_review=false` → revert to the aggregator monitor. Reasons:

- `macro_regime_exit` — long in PANIC (engine-independent).
- `llm_signal_flipped` — the opener now calls the opposite direction.
- `llm_confidence_loss` — **OFF (`enable_llm_confidence_loss_exit=false`)**: the only exit rule the post-exit forward returns condemn (+1.50/+2.24 at 1d/5d — money left behind; 62% of those exits kept running). LLM confidence is measured ~uninformative about forward returns, so its DRIFT is not evidence. **Not a zombie risk:** the PAST-WINDOW half of the same test (`horizon_expired`) is measured CORRECT and still fires, so a decayed position closes at its horizon instead of before it (a test pins this).
- `trailing_stop` (`enable_trailing_exit`) — once MFE arms past `trailing_arm_pct` (3%), close on give-back ≥ `trailing_give_back_frac` (0.5) of the peak.
- `adverse_stop` (`enable_adverse_stop`, long 8% / short 20%) — caps a single position's loss on the cost-adjusted M2M, and only when the LLM review HELD. The split runs OPPOSITE the "stop shorts tighter" prior because shorts against this book tend to RECOVER.
- `mechanical_exit` (`enable_mechanical_exit`) — **OFF SINCE 2026-08-02, DELIBERATELY. Do NOT "fix" its threshold.** Two independent measurements condemn it: the consensus is ANTI-PREDICTIVE (IC −0.066 / hit 46% at 3d and 5d), and it cannot fire at that threshold anyway (a MEAN of ~21 near-zero scores; observed range `[−0.26, +0.32]` over 23,387 held-days, 0.000% fire rate). It was inert BY ACCIDENT, which was quietly protecting the book; lowering the bar to make it fire would wire in a rule that exits wrong ~54% of the time.
- `ml_exit` (`enable_ml_exit_model`, ARM trades only) — the learned exit-timer closes an `ml_arm`-stamped trade when hold-conviction ≤ −`ml_exit_threshold` (0.35). **No minimum hold** (`ml_arm_min_hold_days` 0 — a min-hold was MEASURED HARMFUL).
- `method_horizon` — a position's target hold is the conviction-weighted average of its own PROVEN methods' measured best horizons (`exit_methods.method_horizon_days`); participates in `exit_method_consensus`.
- `edge_decay` (`enable_edge_decay_exit`) — raises the confidence floor once held past the realized edge-positive window (`analysis/horizon_edge.py` → `edge_days`; bounded by `edge_decay_floor_cap` 0.08 × evidence strength).

The confidence floor those last two nudge is also moved by **exit-conviction consensus** (`enable_exit_conviction`, `analysis/exit_conviction.py`): the breadth of the raw signal methods' oriented exit scores (LLM + aggregator excluded) — consensus-exit raises the floor, consensus-hold lowers it, evidence-throttled (`exit_conviction_span_prior` 0.03 → cap 0.10). With `llm_confidence_loss` off, the floor's live consumer is the ramped `horizon_expired` test.

**Note the flag coupling:** `enable_ml_exit_model` is named explicitly in the `_escores` build condition in `monitor_open_positions`, because `ml_exit` reads `_escores` and would otherwise die silently once the conviction/edge-decay/mechanical flags were all off. The aggregator's `combined_score`/`confidence` is no longer consulted for LLM-opened trades; it survives as the `signal_flipped`/`signal_decay` backstop for legacy/rule-based-opened trades only.

Exit harnesses (dashboard Exit-Perf tab): `analysis/exit_forward.py` (post-exit forward returns — a persistently positive mean = the rule exits too early), `analysis/monte_carlo.py`, `analysis/policy_eval.py`.

**SEQUENTIAL exit-policy simulator** (`src/analysis/exit_policy_sim.py`). `exit_policy_eval` is MYOPIC (per position-day) and cannot evaluate a rule that spans days. This runs **close-once** policies over the simulated held-position dataset. **The headline metric is `EXCESS`, not `mean_ret`** — on a decaying book the raw return of any rule mostly reflects how long it holds, so fixed-day controls trace return-vs-hold with ZERO information and `add_excess_vs_matched_control` subtracts that curve at the SAME average hold; only the remainder is timing skill. CLI `python -m src.analysis.exit_policy_sim`. **Re-run this before adding any time-based exit constraint.**

### Database (DuckDB)

`data/llm_trader.db` is the **single source of truth** for trades, recommendations and run history (the legacy `cache/*.json` ledgers are import-only). All access goes through `src/db/`:

- **`connection.py`** — `connect(read_only=False)` yields a short-lived handle. Read-write opens `ensure_schema()` first.
- **`schema.py`** — idempotent `CREATE TABLE IF NOT EXISTS` for `runs`, `run_sources`, `recommendations`, `trades`, `hypothetical_trades`, `broker_reconciles`, `broker_orders`, `signals`, `trade_reviews`, `arm_recommendations`, `weight_history`, `signals_replay`, `code_versions`, `refactor_runs`. Trade rows store the **full dict in a JSON `data` column** alongside projected scalar columns. New tables appear on the next write connection; new *columns* go in `_ADD_COLUMNS`.
- **`signals` (the learning panel)** — every run persists the FULL per-ticker cross-section: all method scores as DOUBLE columns (`SIGNAL_METHOD_COLUMNS`, mirroring `tracker._ALL_METHODS` — a drift test keeps them in sync), `combined_score` + buy/sell sides + their absolute-basis twins, the 7 confidence components, the news-attention columns, `direction`, `n_methods_agreeing`, `dominant_method`, `price`, `universe_source`, `combine_source`, and the full score dict as JSON. The trade ledger only teaches what the gates let through (selection bias); this panel, joined against forward returns, is the unbiased IC/threshold/weight dataset. Analyse with `python -m src.analysis.signal_panel --days 90` (the pivot pseudo-horizon rides every run automatically).
- **`trade_reviews`** — append-only, one row per held position re-judged each tick by the opener-pinned hold-review; the confidence-over-time series the dashboard plots.
- **`repo.py`** — the typed read/write API: `load_trades()`/`save_trades()`, `update_trade` (rewrites one row on its stable `trade_id`), `insert_run()`, `insert_run_sources()`, `insert_recommendations()`, `insert_signals()`, `insert_broker_report()`, `fetch_df()`, `fetch_filled_lmt_legs()`. `set_read_only(True)` flips every read path (the dashboard sets this).
- **`migrate.py`** — one-time `python -m src.db.migrate` imports the legacy JSON ledgers (idempotent).

**Concurrency model:** DuckDB allows a single read-write handle OR many read-only handles across processes. The pipeline is the sole writer and holds the write lock only momentarily; the dashboard connects read-only with exponential-backoff retry.

A **background warmer** re-warms all heavy accessors as soon as a new run lands. Route any NEW heavy accessor through `_cached` AND add it to `_warm_targets`. **Reporting horizons ≠ decision horizons (2026-08-15).** The dashboard's simulated ENTRY/EXIT tables report `data.PANEL_HORIZONS` (`pv` + 1d/3d/1w/2w/1m) — the three intraday horizons (30m/3h/6h) were dropped because computing them reads the WHOLE 30-min OHLCV cache (~2,700 files / ~190 MB) where the daily ones reuse an already-parsed frame: **measured 109.5 s → 87.3 s (−20%, reproducible to 0.2 s) across `simulated_method_perf` + `shadow_exit_method_perf` + `exit_method_perf`**, the most expensive columns on the page. This is a REPORTING narrowing only, threaded as `horizons=` through `compute_method_perf` / `compute_exit_method_perf` / `compute_shadow_exit_method_perf` (`simulated_trades.resolve_horizons`; **default unchanged = the full set**), and `app._SIM_HORIZONS` is derived from `PANEL_HORIZONS` so rendered and computed columns cannot drift. **The default must stay full**: the same curve is a live decision surface — `edge_curve` picks each position's `target_horizon` from it and **`6h` is the ledger's most-used pick** (59 `horizon_expired` closes, the largest single (reason, horizon) cell), and a missing label fails SILENTLY the wrong way (`cap_horizon`'s `HORIZON_ORDER.get("6h", <longest>)` would stop the LLM shortening a SHORT-TERM call instead of raising). `compute_directional_perf` is deliberately NOT narrowed — it is the memo the live IC-weight / market-relative / inversion paths share. Tests: `tests/test_panel_horizons.py`. Perf-critical internals: `cache.load_ohlcv` memoises the parsed frame on (path, mtime, size) returning a COPY, bounded by `ohlcv_parse_cache_mb` (1200 MB); `build_panel` is memoised per (horizons, days, dedupe) against the latest `run_id`; `_load_signals` and `load_sim_entry_events` push their dedupes into DuckDB. Check `cache.ohlcv_parse_cache_stats()` before optimising an individual accessor.

The engine that answered is recorded per run (`runs.llm_synthesis_provider`/`llm_sentiment_provider`), per recommendation, and stamped on each new trade. **⚠ The Anthropic leg is DEAD** (unfunded account → HTTP 400 in ~0.5 s). **Synthesis prompt** (`SYNTHESIS_PROMPT_VERSION`, stamped into the run meta so evals can split prompt eras). A `<selection_process>` block — static, before the cache sentinel, byte-identical across arms so the within-tick prefix cache serves all three arms + hold reviews — tells the model the process its recommendations feed: cross-sectional rank selection on the tradeable pool, the next-swing pivot objective with its ~2-day edge peak and day-5 decay, mechanical fast exits, asymmetric top-decile-buy / bottom-5%-sell selectivity, the anti-chase rule, the earnings blackout, and the LLM's role (read the story, veto incoherence; a precise confidence beats a bold one). Camp scores carry **percentile standings** (`buy_score=0.08 (p99 today)`) against all tickers scored this run, suppressed below 30 scored — scores are comparable only WITHIN a run and the two combine engines run on ~5× different scales, so the arms are told to judge STANDING, never absolute size. Time horizons are framed around the measured hold profile (SWING is the default; POSITION is rare by construction). §27 adds "judge the REMAINING move, not the move already taken". Tests: `tests/test_synthesis_prompt_process.py`.

**Synthesis-prompt arms — dual-case / blind / sighted** (`dual_case_synthesis_share` 0.5 + `blind_synthesis_share` 0.5; the dual flip is taken first and supersedes the blind/sighted axis → ≈50% dual / ~25% blind / ~25% sighted, stamped in `gate_diag`). **Dual-case** presents each ticker as `BULL CASE conviction=… | BEAR CASE conviction=…` with NO verdict, and gates each per-method line by the side its OWN score points to (matching the per-side win-rate filter); the other two arms apply only the GLOBAL filter. Tests: `tests/test_dual_case_synthesis.py`.

**Shadow synthesis arms** (`enable_shadow_arms` ON). Every arm is asked about every ticker each tick — the live arm drives the run, the other two are shadow calls nobody acts on (`arm_shadow.ShadowArmBranch`, started after the live recs, joined at persist time so orders never wait). Shadow calls are pinned to the live arm's engine, which also suppresses provenance writes. Cost: two extra synthesis calls per tick. Persisted to `arm_recommendations`; eval `src/analysis/arm_eval.py` reports a per-arm summary + a head-to-head measured ONLY over ticker-days where two arms took different sides. Tests: `tests/test_arm_shadow.py`, `test_arm_eval.py`.

**Held-positions prompt — ALWAYS ON** (the A/B was retired and ON adopted). The synthesis prompt always includes `<open_positions_context>` + §27 whenever positions are open. `exit_hold_prompt` is still stamped (now always True) so the ledger stays honest and the historical ON/OFF comparison stays readable. 2. **Smart money signal:** return `List[InsiderTrade]` from a new module, call from the Step 3 block, extend the `smart_money` list.

### ML methods

Trained models as signal methods. The convention (matching the buy/sell split) is that a method emits a **bullish score ∈ [0,1] AND a bearish score ∈ [0,1]** — a classifier's `P(up)`/`P(down)`, both low = a genuine no-view. Requires **lightgbm**; models use lightgbm's **native Booster API, NOT `LGBMClassifier`** (which would need scikit-learn even to unpickle — the artifact must stay sklearn-free). History: `memory/ml-methods-plan-2026-07.md`.

**Harness (offline):** `src/analysis/ml_dataset.py` builds one row per (ticker, session_date) from the deep OHLCV cache (**76** causal features — raw + expanding within-ticker z-scores + 6 cross-sectional ranks; labels `fwd_ret_{raw,rel}_<h>d`; causality by construction, leakage-probed). The 9 pivot **leg-state features** live in `src/analysis/pivot_target.py`. The full-universe training set materialises to `cache/ml/dataset_full.parquet` (~9M rows). `ml_train.py` = `SoftmaxLogistic` (pure-numpy baseline) + `LightGBMModel` + **`LightGBMRankRegressor` (the production v2 model)** + `walk_forward_predict` (trains only on rows whose label printed) + `evaluate()`. Leakage guarded by three adversarial tests in `tests/test_ml_dataset.py`.

**`ml_ohlcv` — OHLCV base signal, WEIGHTED 0.12.** A `LightGBMRankRegressor` on the within-day rank of the **signed pivot target**, 85 features (76 causal OHLCV + 9 leg), full universe, no conditioning, uniform day-equal weights. Score = `clip(2·pred, −1, 1)`, meaningful relative to same-day scores. Promotion gate: `python -m src.analysis.ml_validate --target pivot` (train-on-deep / judge-on-panel, point-in-time). The artifact stamps `pivot_basis` and serving **ABSTAINS on a mismatch** (`BASIS_STALE`) — a close-era model must not read H/L leg features, so a pivot redefinition takes the method to 0.0 until the retrain lands. Retrains weekly; `ml_ohlcv_target=classic` reverts the trainer to the v1 classifier (serving always dispatches on the artifact's own config). Fail-soft everywhere. Tests: `tests/test_ml_model_pivot.py`.

**`ml_buy` / `ml_sell` — the FULL STACKERS as combined_buy/sell_score (A/B at `ml_combine_arm_share` 0.5).** `src/analysis/ml_stacker.py`. Learned aggregators over 21 of the weighted method scores (`STACKER_LIVE_FEATURES` — deliberately not all 27: the six promoted price methods measured worse as features while their panel history is mostly-NaN), within-day rank label on the signed pivot target, isotonic-calibrated on OOF predictions. Unlike `ml_ohlcv` they **DRIVE decisions when the arm is on**: `combined_buy_score = compute_buy_conviction(...)` and `combined_sell_score = compute_sell_conviction(...)` replace their weighted camps. Separate artifacts + registry rows; `STACKER_GBM_PARAMS` (15 leaves / min_child 20 / lr .05 / 200 trees — the lgb defaults were sized for deep-cache data). Per-run flip in the pipeline (`enable_ml_combine` forces). Fail-soft per SIDE: no artifact ⇒ the weighted combine is kept, recorded per ticker in **`combine_source`** (`weighted | ml | ml_buy | ml_sell`, on `signals` AND trades).

**The ML combine runs on its own scale.** The stacker conviction is a calibrated probability margin, so it lives far below the weighted combine (mean `|combined|` ~0.06 vs ~0.30) — a probability near 0.5 is a genuine no-view, not a small z-score. Both live gates are therefore resolved per combine: `ml_diff_threshold_long` **0.0463** / `_short` **0.0374** and `ml_raw_confidence_scale` **0.0658** (the divisor is solved against **Gate 1**, not the `|combined|` quantiles, because Gate 1 is what binds). Applied ONLY to the full `"ml"` swap; a partial `ml_buy`/`ml_sell` puts two scales in one difference and keeps the weighted bands. **This equalises EXPOSURE, not skill.** ⚠ `ml_raw_confidence_scale` is **PROVISIONAL** pending a multi-day read — the first post-fix run came in hotter than the calibration predicted (joint exposure 42.4% vs 33.4%); re-compare `pct_dir`/`pct_gate1`/joint and `runs.n_actionable` for `combine_source='ml'` vs `'weighted'` after ~5 trading days, and raise the divisor (0.0658 → ~0.075 pulls Gate 1 to ~33.8%) if ML exposure is still materially higher. **The reusable tell: an A/B arm that silently stops ACTING looks identical to an arm that is losing — always check each arm's exposure before reading its P&L.**

**`ml_exit` — the learned EXIT-TIMER, COUPLED to the entry arm (ON).** `src/analysis/ml_exit_dataset.py`. A GBM answering "for a held position, exit now?" over 30 features: 9 position-STATE features the hand-built consensus throws away (`days_held`, oriented `ex_ret`/`ex_mfe`/`ex_mae`/`ex_giveback`/`ex_from_mae`, `ex_combine`, `ex_combine_delta`, `ex_elapsed_ratio`) + the 21 oriented method scores. Trained on **SIMULATED held positions over the signals panel**; label = `fwd_ret_pos_pv`, the ORIENTED REMAINING MOVE to the next H/L pivot (fail-soft to the fixed held-return label below 500 settled rows, basis stamped in the artifact). Emits a signed HOLD-conviction `2·P(keep)−1`. **The A/B coupling:** ml_exit drives the close ONLY for trades stamped `ml_arm` — and the stamp requires the stacker to have ACTUALLY driven that trade's side (`tracker._ml_arm_stamp`), so stacker entry ⇔ ML exit per trade, not per coin. For that cohort it REPLACES the anti-predictive `mechanical_exit` **and** the confidence-degradation exit (`_ARM_ML_OWNED_EXITS`, permanently suppressed). Direction flips and safety exits (`_ARM_ALWAYS_EXIT`) are never suppressed. For every other held position it is still computed + persisted to the `exit_signals` panel so its exit-side IC accrues before it acts. Excluded from `exit_method_consensus` so it never contaminates its own baseline. **`ex_combine` is BASIS-INVARIANT**: both `build_exit_dataset` and `live_exit_features` prefer `combined_score_abs` (falling back to `combined_score` on pre-shadow rows, which ARE absolute), `signal_at_entry` snapshots the abs twin, and the artifact stamps `combine_basis` — so neither the rank switch nor a shaped curve refreshing under its TTL can shift a trained model's feature distribution mid-hold. Caveats: modest absolute edge (IC ~0.02); a thin SIMULATED-position panel, not real held trades. Tests: `tests/test_ml_exit.py`.

**Retrains.** All three artifacts retrain **weekly, Saturday 08:00 ET** (`runner._run_weekly_ml_train`, single-flight background thread). To retrain out of band, run them **in this order**:

```bash
python -m src.signals.ml_model                  # ml_ohlcv        (forced; --throttled honours ml_pivot_retrain_days)
python -m src.analysis.ml_stacker --train       # ml_buy + ml_sell (always as a PAIR)
python -m src.analysis.ml_exit_dataset --train  # ml_exit
```

**Why that order:** not a training-input dependency (all three train on already-persisted history), but each model's FUTURE training rows are manufactured by the upstream artifacts' live scores — `ml_ohlcv` feeds `combined_score`, the stackers REPLACE that combine's camps on arm runs, and `ml_exit` reads the resulting combine. Retraining downstream-first just means the downstream model spends the gap learning from an upstream you were about to fix. Fix the ABSTAINING artifact first.

Every step is fail-soft, so an ad-hoc retrain is **safe alongside the live scheduler** — it is CPU/RAM-heavy (the ml_ohlcv rebuild re-materialises the 5.4 GB parquet, ~8 GB RSS, 20–40 min), not lock-dangerous. A kill mid-rebuild is clean (parquet and pickle are written only at the very end). Four traps, each SILENT:

- **The throttle returns `None`, not an error** — `eod_train()` unforced skips whenever the artifact is younger than `ml_pivot_retrain_days` (7). The CLI therefore **forces by default**.
- **`python -m src.signals.ml_model` must dispatch through `eod_train`** — calling `train_and_persist()` directly trains v1 *classic* regardless of `ml_ohlcv_target`, silently downgrading a weighted method.
- **The replay step does NOT regenerate `ml_ohlcv`** — a model-derived score cannot join the replayable set (replaying it with a model trained through today is look-ahead). Its panel history is masked by the epoch and refills only FORWARD.
- **The stackers are downstream of the pivot LABEL, not of `ml_ohlcv`'s scores** — `ml_ohlcv` is deliberately absent from `STACKER_LIVE_FEATURES`. Retrain them after a `stacker_label_basis` change, not because `ml_ohlcv` moved.

**Retrain out of band whenever a CATEGORICAL change lands:** a pivot redefinition (serving abstains with `BASIS_STALE`, so a 0.12-weighted method reads 0.0 until the retrain — urgent, not cosmetic), a `stacker_label_basis` change, or a feature-set change.

### Key constraints

**Polygon.io client** (`src/data/polygon_client.py`): `get_snapshots_batch()` (two calls), `get_bars()`, `get_grouped_daily_closes()` (every US ticker's last close in ONE call — works on the free tier, where the per-ticker snapshot endpoint 403s). A 403 is logged once per endpoint-family then suppressed. Falls back to yfinance without a key. Indices (^VIX) and futures (GC=F) use yfinance directly.

**Bulk vs execution pricing — two separate paths.** The bulk snapshot feeds the analysis panel, scoring, ext_gap and the price-provenance check. Trade execution comes from `tracker._fetch_price` (IBKR → yfinance → Polygon single-ticker), live only for actionable/held tickers. The deterministic anchor for analysis/NAV/IC is the completed daily CLOSE. `_assess_price_provenance` skips `price_source != "live"` anchors so a live fill is never falsely flagged against a prev-close fallback.

**Silent-default health monitors** (`pipeline._collect_sources` → `run_sources` → Data Quality tab + email banner): FX sizing rate, correlation sizing, and macro-regime/market-mode input coverage each keep a reset-per-run health dict that surfaces as a source-health row.

**SEC EDGAR rate limit:** 10 req/s (`_REQUEST_DELAY` 0.12–0.15s). The `_ticker_index`/`_ticker_cik` maps are module-level globals populated once per process — never re-fetch in a loop. **yfinance:** on 429, back off 60s → 120s → 240s, stopping after 3 failures; options-chain scanning is silent-fail per ticker. **CFTC:** COT ZIPs are 5–10 MB; always check the cache first.

**Actionable signal threshold.** Baseline (NEUTRAL) is `confidence ≥ 0.85` (**Gate 1**, mechanical) AND `sources_agreeing ≥ 2` (**Gate 1b**, `enable_agreement_gate` / `min_sources_agreeing_gate`). The Macro Regime Filter adjusts it dynamically: RISK_ON 79%, NEUTRAL 85%, CAUTION 87%, RISK_OFF 89%, PANIC 95% (a minimum-confidence baseline, not a hard floor — RISK_ON sits below 0.85 by design). Off-RTH adds +6 pp (overnight +10 pp instead), capped 95%. BUY entries are blocked during PANIC. A single strong source never produces a BUY/SELL. **Smoothed-step threshold** (`enable_continuous_regime_threshold` ON): each band keeps its documented threshold through its interior; only within 0.05 of a boundary does it ramp, entirely on the lenient side. The regime LABEL and BUY block stay step-based. The regime is deliberately NOT a per-ticker scoring method (a market-wide constant has no rank variance). Tests: `tests/test_regime_threshold.py`.

**Gate 1b scope:** `sources_agreeing` (post win-rate-filter, inversion-corrected) is meaningful only when the LLM's direction matches the aggregator's (the ~96% echo case); a genuine override passes Gate 1b unchecked. **Gate 5 — overextension / anti-chase** (BUY-only, `enable_overextension_gate` ON): drops an actionable BUY whose trailing close-to-close return over the last `overextension_lookback_bars` (5) completed bars exceeds `overextension_runup_pct` (12%) — recent big gainers mean-revert and `combined_score` peaks post-run-up. DEFERRED, not banned. SELLs are never gated. Fail-OPEN on missing history.

**The actionable filter is extracted into `pipeline._apply_actionable_gates`** (Gates 1, 1b, 2, 3, 4, 5 — same gates, same order, same counters, same `gate_outcomes` stamps). A drop is attributed to the FIRST gate that rejects it; an expensive gate is never consulted after an earlier one rejected the candidate. Tests: `tests/test_actionable_gates.py`.

### Broker integration (paper-first live execution)

`src/broker/` adds a real **execution leg** alongside the internal NAV simulator — a "shadow & reconcile" design. Gated by `settings.broker_mode`; **`off` makes zero broker calls.** Live: **`ibkr_paper`** (port 4002).

- **Modes:** `off` | `dry_run` | `ibkr_paper` | `ibkr_live`. Paper vs live is the configured `ibkr_port`; the factory refuses to start `ibkr_paper` on a known live port.
- **Broker = Interactive Brokers** via `ib_async` → IB Gateway (the only API broker letting a Canadian resident paper + live trade US securities). `ib_async` is imported lazily.
- **Single hook point — `reconcile.sync()`** runs once per tick right after `record_new_trades`. Idempotent and self-healing, in order: **(0) fill refresh** — earlier-tick orders not yet terminal are repaired from today's executions (keyed by `orderRef`); **(0b) tick-scoped order lifetime** — an order lives exactly one tick; anything still unfilled is cancelled and its leg cleared so the entry/exit pass resubmits re-anchored. Entries resubmit only when the trade survived this tick's signal pass AND clear the **price-aware resubmit gate** (chase only when the fresh signal still wants it inside `broker_resubmit_max_adverse_bps` (100 bp), or at an equal-or-better price); EXITS are never gated. **(0c) cancel-on-close.** **(1)** internal OPEN trades without a `broker_order_id` → sized entry (sizes the GAP vs any same-side held position). **(2)** internal CLOSED trades still holding a position → close, sized from the actual position (sign-checked). **(3) drift** — positions the ledger can't explain: `broker_drift_action` **`"flatten"`** submits a price-capped marketable LMT (never adopted into the ledger), re-anchored each tick; `ibkr_live` always refuses auto-flatten. **(4) settle — fill fast or kill** (`broker_settle_seconds` 30): this tick's unfilled orders are watched, re-anchored at a fresh quote every ~6 s, and CANCELLED at the deadline so nothing rests across ticks. Every broker call is exception-safe.
- **Order-vs-ledger durability.** The invariant: **no order may work the book unless a ledger leg points at it.** `_persist_legs` flushes the ledger immediately after every submission. `cancel_order` cancels EVERY order matching a ref (IBKR does not dedupe `orderRef`). `_working_order_for_ref` is a pre-submit duplicate guard. `_sweep_orphan_orders` cancels working orders no ledger leg owns (drift-flatten refs and hand-placed TWS orders are exempt). `IBKRBroker.connect()` calls `reqAllOpenOrders()` so a relaunched scheduler sees prior sessions' orders. Tests: `tests/test_broker_reliability.py`, `test_broker_price_aware_resubmit.py`.
- **Submission reliability:** transient failures retry up to `broker_submit_retries` (2) × `broker_retry_wait_seconds` (5 s); hard rejects never retry. A duplicate guard checks whether the errored attempt reached the broker before retrying. Failures persist as `SUBMIT_FAILED`/`STALE_CANCEL`/`SETTLE_*` rows. **Auto-reconnect:** every method gates on `_ensure_connected()` (cooldown 60 s). **Request timeout + sync watchdog:** `IB.RequestTimeout` (45 s) bounds every request; a `threading.Timer` watchdog around `_broker_sync` (600 s) logs CRITICAL + `os._exit(1)` on expiry (recovered by `--supervise`). Tests: `tests/test_broker_reconnect.py`.
- **Order types:** `broker_order_type` **`LMT`** — a marketable limit at the model price ± the session's cap (20 bp RTH / 80 extended / 150 overnight). Off-RTH overrides MKT to marketable LMT with `outsideRth=True`. Class-share tickers normalise both ways (`BRK-B` ↔ `BRK B`).
- **Execution measurement (persisted):** slippage (cost-normalized bps) + actual commissions per `sync()` to `broker_reconciles`/`broker_orders`, plus account NAV and IBKR's own `reqPnL` snapshot.
- **Sizing** (`sizing.py`): `notional` (default: `broker_base_notional` 2000 CAD → USD via live FX) or `equity_pct`, × the ledger's `position_size_multiplier`, with max-positions and max-gross-exposure caps.
- **Idempotency:** `recommendation_id` is the IBKR `orderRef`; one broker order per client_ref (a duplicate is marked `DUPLICATE_REF_NOT_SUBMITTED`). A broker-health verdict and a price-provenance verdict each mirror `_assess_llm_health` → CRITICAL log + email banner + `🔔` subject tag.
- **Ops:** IB Gateway must run alongside the scheduler and needs a ~daily re-login (IBC). Before changing modes: `python -m src.broker.smoketest`, then `--order` for a 1-share round trip. **Gateway auto-recovery** (`broker_gateway_auto_restart` ON): when the gateway itself is wedged-but-alive or down, `maybe_restart_gateway` kills the java process owning `ibkr_port` and fires the `'IBC Gateway'` scheduled task. PAPER-ONLY (`ibkr_live` downgrades to a CRITICAL log); cooldown 30 min; fail-soft. Tests: `tests/test_gateway_recovery.py`.

### Configuration

All settings live in `config/settings.py` as a `pydantic-settings` `BaseSettings` class. Every field maps to an env var (uppercase). Add new fields with defaults there; they become `settings.field_name` everywhere. **Never read `.env` directly — always go through `settings`.**

**Inert-config guard** (`tests/test_inert_settings.py`): fails on any NEW setting that is defined and documented but read nowhere (flipping it appears to work and changes nothing). A knowingly-inert setting must be listed in `KNOWN_INERT` and say so at its definition. Currently listed: `enable_combined_score_gate` / `min_combined_score_for_entry` (deliberately not wired — the ledger says a combined-score gate would block the LLM's best cohort) and `schedule_daily` (a legacy cron string). The guard exempts `*_long`/`*_short` names (resolved at runtime by `settings.directional`) and counts consumption by a `@property` on Settings. **Delete a retired knob rather than pinning it to a no-op value** — a pinned knob reads as live.
