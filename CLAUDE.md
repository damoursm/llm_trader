- **How it runs.** On every non-observe market-day tick `pipeline` launches the scorer as a SUBPROCESS (`sel_short.launch`): `--run --day D --bars k1,k2,…` for EVERY completed regular-hours bar of the day not yet run, oldest first (`pending_bars`; one bar's crash never costs the next, a bar that crashed twice is skipped), or `--prepare` once from 09:00 ET (extends the deep 30-minute store through the previous session, fixes the day's universe, checks the session snapshot). A run fetches the day's bars for the universe from Polygon (from the store's last session when it is behind), rebuilds each series, computes the training features (`ml_model.features_30m_from_hlc` + `deep_features.serving_vector` from the pre-open snapshot; `ensure_snapshot` first rebuilds a missing or DEFECTIVE one — < 80% of the universe carrying a previous close), scores (~2–3 min a bar, 6 processes), appends every score to the day's score file and journals the decision. A snapshot still defective after the rebuild (or a rebuild that raises) takes only the MODEL off that bar (`SNAPSHOT_DEFECTIVE`); the vol arm runs. SPLITS: a split effective after a name's stored history was last adjusted (the deep `splits` family; `intraday_store.reset_split_tickers`) resets that history — refetched whole, adjusted as of today — in the pre-open run, the prepare and each run before any inference — the SPLIT DATA decides (user directive 2026-09-28): an extension that finds the last stored session rescaled only prompts that check, and without a split record it is logged, never reset. LIVE PATH FIRST (`enable_live_path_first`, user directive 2026-09-28): at the START of the tick the marks (`calibrate_sim_costs` + `update_open_trades`), the exits (`monitor_sel_short_positions`) and the one-shot flatten run; then, on the main thread while Steps 1-3 fetch in the pool, the tick WAITS for the scorer (≤ `sel_short_wait_seconds` 480 — the two models' fetch, features and inference; a `--prepare` is never waited for), `tracker.record_sel_short_trades` opens journaled picks ≤ 75 min old and the broker syncs — entries ~2.5 min after the tick starts (2:20–2:36 on the 2026-09-28 afternoon ticks) instead of after the shadow pipeline. The end-of-tick block still runs the legacy exits (they need the shadow signals), re-judges the strategy's exits, takes a late scorer's picks and syncs again (the two reports merged). `busy.lock` (touched every 30 s, stale after 180 s) keeps one scorer at a time; a run never extends the store inline. Live scores equal the evaluation arrays' construction exactly.
- **Broker.** A sel_short entry the settle pass killed unfilled is re-anchored and resent every tick while its ledger row is open (the price-aware resubmit gate reads the legacy rank map and would strand it). An order IBKR REFUSES outright is resent in the same tick (`broker_refused_resends_per_tick` 2, re-anchored, next `-rN` ref) and again on later ticks; an entry refused on `broker_refused_max_ticks` 6 ticks is given up (`REFUSED_GAVE_UP`), an exit never. A closed trade whose own entry never filled sends no exit (`NEVER_FILLED`, terminal); a closed trade's exit is the holding MINUS what open trades own in the ticker; no position row = flat = no exit. Entry fill rates on SELLs: 69% RTH, 25% extended, 9% overnight. ### Signals and the combine (SHADOW)

Everything in this section runs every tick and is persisted to the `signals` panel; it drives only the shadow rank rule.

- **Score-sign convention** (the invariant the combine, IC and inversion depend on): every method's sign is the predicted direction of the STOCK (+ up, − down); mean-reversion methods bake the reversal into the sign; |score| is confidence.
- **Weighted methods** (`aggregator._BASE_WEIGHTS`): news 0.40; tech, insider 0.30; sector_momentum 0.20; pattern, momentum 0.18; massive, put_call, oi_skew, money_flow, trend_strength, pead, ext_gap, mom_12_1, hi52 0.15; iv_rank 0.13; sent_velocity, max_pain, vwap, iv_expr, coint, st_reversal, ml_ohlcv 0.12; news_quiet, rsi2_rev, dloc_rev 0.10; news_bull_fresh, market_momentum 0.08; news_bear_fresh, catalyst_tilt 0.06; news_shock 0.04 (`broker_advisor` keeps a 0.10 weight but is OFF). **A weighted method needs FOUR registrations**: the base weight, an `_raw_active` entry (without it `_normalised_weights` gives it weight 0 while it scores, persists and ranks — `tests/test_news_quiet.py` pins it), `agreement.METHOD_FAMILIES`, and — to reach DIRECTION — `ml_stacker.STACKER_SIGNED_FEATURES`: the stackers are the combine, so a base weight alone reaches only coherence, `sources_agreeing` and the family votes.
- **The ML stackers ARE the combine** (`src/analysis/ml_stacker.py`, `ml_combine_arm_share` 1.0; the weighted camps are the per-side fail-soft, recorded per ticker in `combine_source`). Frozen 2026-08-24 logistic artifacts (`stacker_model_class`). 54 features: 31 SIGNED (the weighted method scores incl. `ml_ohlcv`, `tape_score`, the news family and `news_raw_score`) + 23 unsigned context (news mass / count, `atr_pct` / `bb_width_pct` / `vol_ratio`, an 18-class catalyst one-hot). Confidence and its factors are EXCLUDED (computed downstream of the combine; a test pins it). News features enter as the within-run centered rank over the Gate-4 pool (`stacker_news_basis="rank"`; `centered_rank_pooled` mirrors the aggregator's transform minus shaping), but serving dispatches on the ARTIFACT's `news_basis` stamp — the frozen artifacts stamp `absolute`. - **Rank basis** (`method_score_basis="rank"`): the combine consumes each method's CENTERED WITHIN-RUN RANK. Zeros abstain; a method with fewer than `method_rank_min_views` (5) non-zero views on tradeable names gets weight 0 for the run (override `news_quiet=3` — abstention is its mechanism — logged as `rank-thin this run`); ranks are over the Gate-4 pool with observe-only names interpolated; each method's percentile is payoff-shaped (`src/signals/rank_shaping.py`); bands `rank_diff_threshold_long` / `_short` 0.324 / 0.346, `rank_raw_confidence_scale` 0.642 — resolved ONLY in `aggregator._direction_bands` / `_raw_confidence_scale`. Consumption-time only: every persisted surface keeps the RAW score. An absolute-basis twin (`combined_score_abs` + buy/sell) rides every row.
- **Buy/sell split**: each method's effective view splits into BUY / SELL components averaged within its own camp; `combined_score` = buy − sell. The `f_*` factors and the 4 trend-predictability methods are additive overlays (`f_short_squeeze` excluded).
- **Agreement**: `METHOD_FAMILIES` rolls the methods into 7 information families; family votes and tape confirmation fold into confidence (`src/signals/agreement.py`).
- **Weighting and filters** (weights and confidence only): base → market-mode profile → win-rate adaptive → IC-informed (only methods with a pivot-basis IC t ≥ 2) → the OpEx max-pain boost. The win-rate hard filter (< 50% gross over ≥ 10 trades) and the per-SIDE filter and weights, which reach coherence, `sources_agreeing` and the family votes as well. Auto-inversion is on but `INVERTED_METHODS` is empty and the detector selects nothing. The market-relative hard filter drops only a significantly negative market-neutral ICIR. Per-method horizon states: PROVEN / DISPROVEN (dropped) / UNPROVEN (×0.5).
- **Multi-timeframe**: the 8 OHLCV methods on 30-minute, daily and weekly bars, blended 0.20 / 0.60 / 0.20 (`tf_blend_*`); the daily score stays in `*_score`, the others ride `timeframe_scores`.
- **Regime layers**: the Macro Regime Filter (PANIC blocks BUYs; RISK_OFF takes a ×0.5 size haircut; fails CAUTIOUS below 3 inputs), Market Mode (TRENDING / CHOPPY weight profiles), Catalyst Timing (earnings blackout, OpEx max-pain amplifier, 8-K + insider WATCH).
- **Panel-first (weight 0)**: `news_unpriced` / `news_unpriced_all` (measured harmful twice — accruing columns, not candidates), `squeeze`, `iv_term`, `avwap`, `resid_mom`, `vol_profile`, plus the `f_*` factors as overlays.

**The rank rule and the gate cascade** (shadow; `src/signals/rank_entry.py`, `enable_llm_synthesis` false): per run and per side, the direction band decides IF and the within-run rank of `combined_score` over the Gate-4 pool decides WHICH, capped at `gate1_rank_cap` (3) per side; provenance `rank` / `rank-v1`. `pipeline._apply_actionable_gates` then applies, attributing each drop to the first rejecting gate: Gate 2 (the PANIC BUY block), Gate 3 (the earnings blackout), Gate 4 (the trade floor), Gate 4b (live-book half-spread ≥ 12 bp → DEFERRED; no live book → pass), Gate 5 (BUY-only anti-chase: a 5-bar run-up > 12% → DEFERRED). Tests: `tests/test_rank_entry.py`, `tests/test_actionable_gates.py`, `tests/test_gate_funnel.py`.

### Performance and the ledger

- **Per-trade return** (`tracker._pct_return`): cost-aware buy-and-hold (`cost_in` / `cost_out` = half-spread + commission; SELL mirrors BUY); open trades are marked live.
- **Costs per leg** (`spread.resolve_leg_cost`, `sim_per_trade_cost_attribution`): the leg's own fill → the same-tick average of fills in its liquidity class → the tick average → the time-of-day period average in its class (shrunk) → the period average → `_one_side_cost` (the calibrated real-fill overrides; the hand-built spread formula only on a fills-free database or for sub-minimum-price legs). Commission is a fee CEILING (`ibkr_fixed` max($1, $0.005/share), ×1.5). `calibrate_sim_costs` runs before each tick's mark and entry steps. Tests: `tests/test_cost_buckets.py`.
- **Short borrow carry** (`enable_short_borrow_cost`): every stock short pays IBKR's fee DAY BY DAY (user directive 2026-10-06: "we want the real exact borrow fees we would have in live trading a real account and we want that data to be as complete as possible"; `src/performance/borrow_fees.py`, `enable_ibkr_borrow_schedule`): every calendar day from the short's settlement to the cover's — IBKR's trade date (an overnight-session execution belongs to the next session), T+1 on days that settle (Columbus and Veterans Day trade but never settle) — shares × roundup(1.02 × the prior session's close, to the dollar) × THAT day's rate / 360. Each day, in order: what IBKR charged our account (`broker_borrow_fees`, per share); IBKR's own rate with the formula — our archive's last file of the day, IBKR's API bar, the community archive (`borrow_history.fee_daily`), carried over a day none holds for at most a week (or from around the entry), the file in force for a day not over (provisional); the entry stamp; `short_borrow_annual_pct` 3%. Stored on the trade (`borrow_days` [day, source, rate, collateral price, fee per share], `borrow_fee_ps` / `borrow_fee_usd`, `borrow_rate_now`, `borrow_final`) and charged by `_pct_return`, the daily NAV (each day in its interval) and so the simulated account; the hypothetical rows (flips, decision streams) keep the flat rate-at-entry carry. A short CLOSED before the schedule existed keeps that flat carry until `borrow_backfill_closed` — the user's condition: the formula backfills only once checked against IBKR's own charges (`python -m src.performance.borrow_fees --verify`). Dry run on the 501 past stock shorts: 91% of their 986 charged days from IBKR's data (the rest names still queued in the fee pull); JAGX at 960 %/yr owed 9.1% of the position over 4 days where the flat carry charged 0.015%. No look-ahead: a day not over reads only the file in force and closes final from 16:15 ET (`tests/test_no_lookahead.py`). Tests: `tests/test_borrow_fees.py`.
- **IBKR borrow book** (`src/data/ibkr_borrow.py`): IBKR's public short-stock file (`ftp2.interactivebrokers.com`, user `shortstock`; shares available + annual fee for ~19,750 symbols) is downloaded in every tick's Step-1 pool and archived RAW in `data/ibkr_borrow/<ET date>/<HHMMSS>.txt.gz` (never delete — IBKR keeps no history); `borrow_at(ticker, when)` reads the file in force at any instant. Every NEW equity short is checked when opened (`enable_short_borrow_gate`): the selection short needs ≥ $10k available at any fee; the legacy entry paths also refuse a fee above `short_borrow_max_fee_pct` 50%/yr. No snapshot within 120 min → not checked (warned); futures / indices / FX / crypto are never judged. Tests: `tests/test_ibkr_borrow.py`.
- **Daily NAV** (`daily_nav.compute_compound_return`): a path-faithful daily walk over cached closes, capital-weighted per day and compounded; deterministic given the database.
- **Win rates are GROSS** (standing directive): a win is the right direction on raw prices (`tracker.gross_return_pct`, `is_gross_win`, `gross_win_rate`); costs live in the RETURN metrics only. Pinned by `tests/test_gross_winrate_convention.py`.
- **Self-calibrating parameters** share one idiom — prior → evidence → Bayesian shrinkage → clamps → fail-soft to the static setting — and report to the calibration registry (`src/performance/calibration.py` → the Data Quality tab).
- **Email performance** (`get_performance_for_email`): segment stats, the solo-method simulation and the method evaluation; `sel_short` trades carry no method scores, so they appear in no method row.

### Adding a new data source

1. **Per-ticker signal:** implement a `[-1.0, +1.0]` scorer and an `enable_*` flag in `settings.py`. 2. **Smart money signal:** return `List[InsiderTrade]` from a new module, call it from the Step 3 block, extend the `smart_money` list.

### ML models

LightGBM models use the native **Booster API**, never `LGBMClassifier` (which needs scikit-learn even to unpickle — artifacts stay sklearn-free).

- **Harness**: `src/analysis/ml_dataset.py` (76 causal features, leakage-probed), `pivot_target.py` (9 leg-state features), `ml_train.py`.
- **`ml_ohlcv`** (weight 0.12 in the shadow combine and a stacker feature): a `LightGBMRankRegressor` on the within-day rank of the signed pivot target. The installed artifact (2026-09-19) is trained on 30-MINUTE rows (11.6M rows, train_max 2026-06-01, label `hl1@30m`) and served at the last completed 30-minute bar through `_score_30m`: serving dispatches on the artifact's own `feature_bars` stamp and ABSTAINS (`BASIS_STALE`) when its `pivot_basis` differs from the one in force. A model-derived score is not replayable (its epoch masks history; it refills forward). Validate with `python -m src.analysis.ml_validate --target pivot --from-parquet cache/ml/dataset_full.parquet` (the CLI default parquet is not what production trains on; ~32 GB RSS — never beside the scheduler). Tests: `tests/test_ml_model_pivot.py`.
- **`ml_exit`** (`src/analysis/ml_exit_dataset.py`): a GBM exit timer over position-state + oriented method features (`EXIT_METHODS = list(STACKER_SIGNED_FEATURES)`), labelled with the oriented remaining move to the next pivot; it closes LEGACY positions at hold-conviction ≤ −0.35 and scores the follow-through cohorts. `ex_combine` reads the absolute twin (basis-invariant). Tests: `tests/test_ml_exit.py`.
- **Selection-objective models** (`src/analysis/sel_models.py` on the `ml30.py` arrays; the MLP `sel_deep.py` runs in the torch venv): per-side LightGBM `lambdarank` / `tailreg` (+ the `rankreg` baseline), scored by `eval_metrics.selection_objective` beside a volatility-matched control (`sel_models.vol_control`). Tests: `tests/test_sel_models.py`, `tests/test_ml30.py`.
- **Follow-through** (`src/signals/follow_through.py`; scoring ON, trading OFF): each tick batch-scores every Gate-4 name's hypothetical held cohorts with the live `ml_exit` artifact → `signals.ft_score / ft_dir / ft_selected`. Tests: `tests/test_follow_through.py`.
- **Retrains are HELD** (`ENABLE_EOD_ML_TRAIN` / `_BUY_TRAIN` / `_EXIT_TRAIN` = false in `.env`; the code defaults stay True and the scheduler logs the hold at startup). Out of band, in this order: `python -m src.data.intraday_store --extend` → `python -m src.signals.ml_model` (forced; it must dispatch through `eod_train`) → `python -m src.analysis.ml_stacker --train` (always the pair) → `python -m src.analysis.ml_exit_dataset --train`. ### Key constraints

- **Polygon** (`src/data/polygon_client.py`) is the PRIMARY equity price source: snapshots with the live NBBO, bars, news, reference data. `_get` retries once on a transport error or 5xx (never on 403 / 404 / 429); a 403 is logged once per endpoint family. `to_polygon_symbol()` maps `BRK-B` → `BRK.B` at every per-ticker call site (the hyphen form silently returns nothing).
- **yfinance is structurally required** for what Polygon does not serve: indices (^VIX / ^MOVE / ^TICK — the Macro Regime Filter), futures, options chains, fundamentals / analyst / earnings. On a 429 it backs off 60 → 120 → 240 s and stops after 3 failures. `ENABLE_IBKR_PRICE_FEED=false`: this account has no API entitlement for live US quotes.
- **Two price paths.** The bulk snapshot feeds analysis, scoring and the price-provenance check (its NBBO comes from `lastQuote`). Execution prices come from `tracker._fetch_price` (RTH: Polygon last trade → yfinance; off-RTH: yfinance 1-min prepost → Polygon). Order books come from `reconcile._quote_for` (IBKR `get_quote`, which never answers here, → Polygon `/v2/last/nbbo`, refused past 120 s). The analysis / NAV anchor is the completed daily close.
- **Silent-default health monitors** (FX sizing rate, correlation sizing, regime / mode input coverage) surface as source-health rows.
- **SEC EDGAR**: 10 req/s shared (`_REQUEST_DELAY` 0.12–0.15 s; the ticker/CIK maps are populated once per process). **CFTC** COT ZIPs are 5–10 MB — check the cache first.

### Broker integration

`src/broker/` is the real execution leg beside the internal ledger ("shadow & reconcile"). Modes `off | dry_run | ibkr_paper | ibkr_live` (`broker_mode`, live: `ibkr_paper`, port 4002; the factory refuses paper on a known live port). Interactive Brokers through `ib_async` (imported lazily) → IB Gateway under IBC (`docs/DEPLOYMENT.md`).

- **`reconcile.sync()`** runs TWICE per tick — in the live path right after the selection short's entries, and at the end of the tick (legacy exits, a late scorer's picks, a same-tick resend of anything the first left unfilled; the two reports are merged) — idempotent: **(0)** fill refresh by `orderRef`; **(0b)** tick-scoped order lifetime — unfilled orders are cancelled and their legs cleared; entries are resubmitted re-anchored through the price-aware gate (`broker_resubmit_max_adverse_bps` 100) EXCEPT the live books' entries (`sel_short`, `dip_long`), which are resent while their row is open; unfilled legacy entries are never sent while a live book is on (`LEGACY_ENTRY_SHADOWED`); exits are never gated; **(0c)** cancel-on-close; **(1)** entries size the GAP against any same-side holding NO OTHER open trade owns (`_owned_by_open`: the selection short stacks several open trades on one name, 2026-09-28); **(2)** closed trades still holding a position are closed from the actual position MINUS what open trades in the ticker own and MINUS the shares already being covered (the unfilled rest of working covers, covers sent earlier in the pass) — two closed trades on one name never cover it twice; a dead entry leg stays parked only when shares no other open trade owns back it; a closed trade whose own entry never filled sends nothing (`NEVER_FILLED`, terminal) and no position row means flat (no order) — never an exit sized from the recorded fill; an order IBKR REFUSES outright is resent in the same tick (`broker_refused_resends_per_tick`) and parked for the next (an entry is given up after `broker_refused_max_ticks`, an exit never); **(3)** drift → `broker_drift_action="flatten"` (never adopted into the ledger; `ibkr_live` always refuses auto-flatten); **(4)** settle — fill fast or kill (`broker_settle_seconds` 30, re-anchored every ~6 s).
- **Invariant**: no order works the book unless a ledger leg points at it — `_persist_legs` flushes after every submission, `cancel_order` cancels every order with a ref, a pre-submit duplicate guard, an orphan sweep, `reqAllOpenOrders()` on connect. Tests: `tests/test_broker_reliability.py`, `tests/test_broker_price_aware_resubmit.py`.
- **Reliability**: transient failures retry (`broker_submit_retries` 2 × 5 s); auto-reconnect (60 s cooldown); `IB.RequestTimeout` 45 s; the 600 s sync watchdog. Gateway auto-recovery (`broker_gateway_auto_restart`, paper only) is armed by the wedge detector: 5 consecutive request timeouts force a recycle, and 3 recycles within `broker_wedge_recycle_window_seconds` (3600) restart the gateway; `get_account()` (served from the local cache) never counts as an answer; the recycle history persists in `cache/broker_wedge_recycles.json`. A gateway with no API listener that is younger than `broker_gateway_boot_grace_seconds` (120; a relaunch opens its port ~25–45 s after start) is BOOTING — the recovery waits for its port instead of killing it, without consuming the cooldown (2026-09-29 03:02: a 22-s-old gateway was killed and relaunched); older and still no port = stuck → restarted. The relaunch (`gateway_recovery._relaunch`) waits for the killed gateway's `IBC Gateway` task instance to END before `schtasks /Run` — the task's IgnoreNew policy silently drops a run while StartGateway.bat is still closing (4 of 5 recoveries 2026-09-29..10-05 came back only at its 10-minute keep-alive) — ends one stuck past 20 s, and keeps a gateway the keep-alive already started. Tests: `tests/test_broker_reconnect.py`, `tests/test_gateway_recovery.py`.
- **Orders**: a short entry under Rule 201 is offered one tick above the bid and rests until the next tick (above, `broker_ssr`); otherwise marketable `LMT` at the model price ± the session cap — `broker_limit_cap_bps` 45 in RTH (spread-aware up to 400 with a live book), 80 extended, 150 overnight; off-RTH forces LMT + `outsideRth`; class shares normalise `BRK-B` ↔ `BRK B`.
- **IBKR's statement** (`src/broker/flex.py`, user directive 2026-10-06): the EOD chain fetches, in its own thread (IBKR can take hours to generate a statement; one still generating is collected first on the next run, `data/ibkr_flex/pending.json`), the Activity Flex Query `ibkr_flex_query_id` with the Flex Web Service token `ibkr_flex_token` (both from `.env`; skipped while empty) — its Borrow Fees Details section is every fee IBKR charged the account, per short position per value date (quantity, price, value, rate, fee) → `broker_borrow_fees` (each statement period replaced whole, so a re-fetch never doubles a day) + the raw XML in `data/ibkr_flex/` (never delete). The ledger's borrow schedule takes these charges over its formula. `python -m src.broker.flex --borrow-fees`. Tests: `tests/test_borrow_fees.py`.
- **Measurement**: slippage and commissions per sync to `broker_orders` / `broker_reconciles`, the account NAV and IBKR's `reqPnL`, and `bid_at_submit` / `ask_at_submit` (the Polygon book behind the cap). ib_async logs bridge into loguru at WARNING+ (`ibkr._install_ib_log_bridge`).
- **Sizing** (`sizing.py`, `reconcile._entry_qty`): `notional` — `broker_base_notional` 2,000 CAD → USD at the live FX rate — × the ledger's `position_size_multiplier`; a selection short the simulated account funded orders exactly its `sel_account_shares`, a dip long its `dip_account_shares`, whatever price it is resent at; `BROKER_MAX_POSITIONS` 200 (CRITICAL logged once per sync when it refuses an entry — the ledger itself has no cap) and `broker_max_gross_exposure_pct`.
- **Idempotency**: `recommendation_id` is the IBKR `orderRef` (a duplicate is `DUPLICATE_REF_NOT_SUBMITTED`); broker-health and price-provenance verdicts raise a CRITICAL log, an email banner and a 🔔 subject tag.
- **The gateway's scheduled daily restart** (user, 2026-09-29: "The production needs to be reliable"): IBC restarts the gateway every day at its `AutoRestartTime` (11:50 PM ET, read from `ibc_config_path` — only that line; `broker_gateway_restart_et` overrides). From one minute before it to `broker_gateway_restart_window_minutes` (5) after, `IBKRBroker.connect` WAITS for the gateway (`gateway_recovery.wait_for_gateway`) instead of failing, and the gateway auto-recovery never intervenes (it would kill the gateway IBC is restarting). Every `connect()` probes an apparently-live session (`reqCurrentTime`, 5 s — no event loop runs between calls, so a socket the gateway closed while idle still reads connected) and redials quietly; a dropped P&L subscription is never cancelled; ib_async's socket-reset messages log as WARNING (INFO while probing) — a redial that fails still raises the broker alert. Tests: `tests/test_gateway_scheduled_restart.py`.
- **Gateway logged out of IBKR** (user directive 2026-09-28): a gateway whose IBKR login failed keeps its API port open, so connects succeed and an idle sync reads healthy. Each sync stamps `gateway_session` from IBC's last login outcome (`gateway_recovery.ibc_login_state`, `ibc_log_dir`) or IBKR's own codes (1100 lost without 1101/1102 restored, `IBKRBroker.ibkr_link_lost_since`) → the broker health goes DOWN (banner + 🔔 BROKER). Two causes, told apart in IBC's log: IBKR's own re-login demand (its nightly session reset, ~00:15–00:45 ET; IBC's re-login was refused 9 of 9 times since August, a FULL restart logs in) → the sync RESTARTS the gateway (`broker_gateway_relogin_restart`, 2026-09-29: paper-only, the 30-min cooldown, never inside the scheduled-restart window), waits for IBC's `Login has completed` (`gateway_recovery.wait_for_login`, 90 s) and redials — `report["gateway_relogin_restart"]`, a note in the email's green broker line; a refusal ≤ 10 min after "Existing session detected" (a manual login to this paper account elsewhere — TWS, Client Portal, mobile) stays ALERT-ONLY (`existing_session`; a restart would throw that session out) — close it, then restart the `IBC Gateway` task. Tests: `tests/test_gateway_session_alert.py`.

### Configuration

All settings live in `config/settings.py` as a `pydantic-settings` `BaseSettings` class; every field maps to an env var (uppercase). Add new fields with defaults there. **Never read `.env` directly — always go through `settings`.** `config.settings.directional(name, direction)` resolves `{name}_long` / `{name}_short` overrides. **Inert-config guard** (`tests/test_inert_settings.py`): fails on any new setting that is defined but read nowhere; a knowingly-inert setting must be listed in `KNOWN_INERT`. **Delete a retired knob rather than pinning it to a no-op value** — a pinned knob reads as live.

## Standing rules

- **Evaluation** (`.claude/skills/evaluate/SKILL.md`, `/evaluate`; `src/analysis/eval_metrics.py`): the label is the next H/L pivot on 30-minute bars from the row's own tick (unresolved rows at the last visible close); the population is simulated / panel rows, never the trade ledger. MODELS: per-day Spearman IC, its day-clustered t, and the top / bottom 5 / 3 / 1% next-pivot returns (+ the selection objective per side where a model is trained on it). DECIDERS: the mean oriented return per decision against a matched counterfactual. The live strategy: its implementable exit net of real costs beside a volatility-matched control, judged on TWO metrics, both reported every time (user directive 2026-10-04: "growth per year and return per day are the new metrics to follow"): GROWTH PER YEAR = a $10,000 account, no deposits (user directive 2026-10-07: "Change the $5000+$1000/14days to $10000. We'll use this number from now on."), compounding through the audited replay engine — each short sized from the account's current value at a stated share, IBKR's borrow formula, IBKR's margin (the larger of Reg T's tiers and IBKR's house rate; the engine `cap5k7`) with forced buy-backs, the FINRA $2,000 minimum, shorts ≤ 100% of the account and ≤ 1% of the stock's daily dollar volume — without deposits money-weighted = time-weighted: the account's yearly growth (drawdowns on its NAV); RETURN PER DAY = (1 + average net trade)^(1 / average 24-hour hold) − 1. They can disagree (the vol arm's 100% give-back: growth up, return per day down); say so and let the user choose. Engine and conventions: `memory/metrics-growth-and-return-per-day.md`; THE ENGINE is `src/backtest/` (runbook `docs/BACKTEST.md`): one account for any mix of long and short arms (`account.simulate`, bit-identical to the audited engine on the vol book), the arms' trades from adapters (`strategies/vol.py`, `strategies/dip.py`), weekly joint re-tunes of several arms through `study.py`. House bar = paired t ≥ 2 AND same-sign halves, pre-registered. PARAMETER SEARCHES (Optuna) run as a WEEKLY walk-forward (user directives 2026-10-07: "Optuna studies should always run on the weekly window", "tune on Sunday before the first evening session"): re-tuned every Sunday at 19:00 ET on the previous 3, 6 and 12 months (bars through Friday's close), the chosen rule trading the following week, one chained account against the fixed live rule; inside each window the objective IS the expected yearly growth — the window account's annualised growth with every restriction inside (IBKR lendability and the fallback, Rule 201, IBKR's daily borrow, house margin with intrabar margin calls, slices, FINRA $2,000, the dollar-volume cap, spreads and commissions, the exits); never a single tune / test split (`memory/optuna-weekly-walkforward-rule.md`). TWO test sets, reported separately, never pooled: set 1 = history, signal dates 2026-06-17 → 09-27 (news from the per-source rebuild); set 2 = the live all-source-news pipeline from 2026-09-28. SURVIVORSHIP-FREE (user directive 2026-10-01: "Always consider delisted names starting from now on"): every backtest of a strategy, filter or model includes the names delisted since 2021 (the vol engine's `VOL_TAG=_d` universe, bars from `cache/ml/deep/bars30m_delisted`), with its assumptions stated (no IBKR borrow file for them — assumed borrowable at the median fee; their FINRA days to cover come by symbol from `cache/ml/deep_delisted/short_interest_by_symbol.parquet`, the model arm's per-ticker deep features from the delisted company store `cache/ml/deep_delisted` — yfinance's earnings and analyst inputs stay unserved); a today's-names-only number is context, never the result (`memory/always-include-delisted-names.md`). The VOL arm's backtests also include every other common stock / ADR outside the deep store (user directive 2026-10-05: "Add them to live and backtest": the vol engine's `VOL_TAG=_dx`, their FINRA days to cover by symbol from `cache/ml/deep_x/short_interest_by_symbol.parquet`) with the live scorer's 400-bar floor (`OPTVOL_MINBARS=400`; `memory/vol-arm-every-stock-2026-10.md`), the corporate-action gap exclusion (`OPTVOL_CAGAP=1`, store `store_xmc`) Rule 201's passive entries (the evaluator's `rule201`, inputs `ssr.npz` from `ssr_store.py`; `memory/sel-short-gap-ssr-allarms-2026-10.md`), and IBKR's house margin on the live account rules (`cap5k7`, every short at 2.00 / 2.86 or the measured mix, 24 slices; `memory/ibkr-house-margin-2026-10.md`).
- **The pivot label** — ONE label, the next H/L pivot on 30-minute RTH bars (`pivot_label_basis="hl"`, `pivot_min_move_pct` 1.0; `pivot_basis()` = `hl1@30m`), for every decision surface and every ML model. The bar containing the tick is excluded; a date-only row anchors at its session's 16:00 close; the as-of cutoff applies per row through the pivot's CONFIRMING bar (never by rescanning a truncated series — `pivot_rows.pivot_fwd_row` memoises one scan per ticker); no 30-minute history → no label; unresolved rows never reach a training label. Fixed horizons remain for monitoring and holding periods. Tests: `tests/test_pivot_intraday.py`, `tests/test_pivot_target.py`.
- **A calibration may only fit data the CURRENT code produced.** Scorer epochs (`src/signals/method_epochs.py`: register CATEGORICAL changes only, at the ACTUAL restart instant) mask superseded scores in `signal_panel.build_panel`, `simulated_trades.load_sim_trades` and `compute_macro_eval`; they fail open, a freshly epoched method keeps full weight ("unproven"), and an epoch breaks test fixtures that borrowed the method's name. Replay (`src/analysis/replay.py`) regenerates the OHLCV-derived methods run-exact and time-aware (`--validate` after any scorer change); walk-forward (`analysis_asof`, `weight_history`) recalibrates per date; the tier-2 backtest (`signals_backtest`) tracks the CURRENT architecture with as-of shape curves (`shape_history`). Replaying DERIVED values (combine, confidence, gates) with today's weights is a backtest, never a calibration input. The auto-refactor (`refactor.py`: DATA → EPOCHS → WEIGHTS → DERIVED) is held off.
- **No look-ahead, ever** (user directive 2026-09-28): any new feature, filter or exit input on the live path gets a guard in `tests/test_no_lookahead.py` (truncation equality + later-bars rewrite), checked to FAIL against an injected leak before it is trusted.
- **Significance tests are dependency-free** (`src/analysis/stats.py`): scipy is not a dependency, and an optional import guarding a verdict the system acts on is an invisible off switch.
- **Tests run against a pinned baseline, not production** (`tests/conftest.py`): an isolated DuckDB in a temp dir, spread-only costs, no network (Polygon quotes, the borrow download, gateway restarts off), every background pass off (the sentiment / synthesis shadows, catalyst repair, live feature capture, passing-mention abstention; the selection short off with its own temp dir), and LLM-era settings pinned (`method_score_basis="absolute"`, hosted engines on, the local LLM off, the hold review on). A test of production behaviour must set the production flags itself.
- **Silent channels**: use loguru — `logging.getLogger(__name__)` in `src/` is a handler-less sink (`tests/test_inert_settings.py::test_no_module_logs_into_a_silent_channel`). A mechanism whose failure looks like normal operation (an unread setting, an unreachable branch, a value computed but never stored, a constant duplicated across two sites) must be verified mechanically, never by review.
