## Running the pipeline

```bash
python main.py                # Run once, console output only
python main.py --email        # Run once and send email report
python main.py --schedule     # Poll-loop runner
python main.py --supervise    # PRODUCTION (scripts/run_scheduler.bat): --schedule under an auto-restart supervisor
python main.py --dashboard    # Read-only monitoring dashboard (Plotly Dash via waitress)
python main.py --backfill     # Pre-warm OHLCV caches for the whole universe, then exit
```

**Scheduler** ticks on NYSE market days: RTH every 30 min 9:30–16:00 ET, extended 4:00–19:50, overnight 20:30–03:30 hourly on the overnight venue's Sun–Thu-night calendar. Emails fire at `scheduler_email_times` (04:00/09:30/16:00/19:50 ET); `SCHEDULER_EMAIL_EVERY_TICK=true` is the live setting → every slot. `email_on_problem` (ON) forces an out-of-schedule email on any broker/LLM/price health problem. Once per market day at/after `eod_maintenance_time` (16:20 ET) EOD maintenance (`enable_eod_maintenance`) runs in a **background thread** (single-flight; `runner._eod_work`: cache warm → `simulated_trades` retention → replay materialisation → walk-forward calibration → shape-history append (`enable_eod_shape_history`) → tier-2 backtest tail (`enable_eod_backtest_refresh`) → IBKR BID_ASK spread-sweep subprocess (`enable_eod_spread_sweep`)). The auto-refactor is NOT in this chain — it runs on its own nightly 02:00 ET slot (`_maybe_start_nightly_rescore`; **HELD OFF since 2026-09-15 by `ENABLE_AUTO_REFACTOR=false` in `.env`** — a module edit re-triggered it, the walk-forward ran from June inside the scheduler and starved five ticks into watchdog kills, and every relaunch restarted it from scratch; run `python -m src.analysis.refactor --apply` in its own process on an idle box, then remove the line — `memory/refactor-rewalk-kill-loop-2026-09.md`), and the weekly ML retrain on its Saturday 08:00 ET slot (currently HELD — see Retrains). A still-running EOD at the next day's slot is warned and skipped; `eod_replay_refresh_days` (45) is the shared size knob for the replay and backtest tails.

**`--supervise`** relaunches the scheduler if the process dies (e.g. a watchdog's `os._exit(1)`). A HANG is not caught by `--supervise` or Task-Scheduler restart-on-failure — both need the process to exit; TWO watchdogs convert hangs into exits: the broker-sync watchdog (`broker_sync_watchdog_seconds` 600) and the **whole-tick watchdog** (`runner._run_tick_watchdogged`, `tick_watchdog_seconds` 2700 — added after a wedged yfinance socket in the Step-3 fetch pool froze the scheduler 4.5 h through the 2026-08-17 open; every tick-path yfinance call also carries `timeout=30` now). **To STOP a supervised scheduler: kill the `--supervise` parent FIRST (so it can't respawn), then the `--schedule` child.** To restart, use `scripts/restart_all.ps1` — never ad-hoc `python.exe`, which is how duplicate schedulers appear.

`--backfill` is additive (merges into `cache/ohlcv/`, never deletes); `--backfill-30m` also warms the 30-min cache. Standalone: `python -m src.data.backfill [--days 730] [--with-30m] [--skip-daily]`. The daily cache is full-depth (Polygon serves 2006+; ~5,000 bars for ~950 names). Weekly is resampled from daily on demand. **30-min bars are Polygon-fed (`get_intraday_bars` follows `next_url`; aggregates paginate back to at least 2021) and the TICK cache is depth-CAPPED at `intraday_30m_max_bars` (3,380 = 260 sessions × 13, applied in `cache.save_ohlcv`)** — the cache accumulates through `_merge_intraday`, and uncapped (the 2026-09-14 single-source rebuild left ~18k bars/name, 2.9 GB of JSON) every tick re-parsed ~3,400 multi-MB frames, thrashed `ohlcv_parse_cache_mb` and ran 30+ minutes into the watchdog (2026-09-15, `py-spy` caught it in `simulated_trades._intraday_series`). A year is more than every tick-path consumer needs (the pivot label's scan is trimmed to its window + 60 days); the deep 2021→ history that TRAINS `ml_ohlcv` on the pivot label is the **deep 30-minute store** `cache/ml/bars30m_deep/<TK>.pkl` (`src/data/intraday_store.py`: `python -m src.data.intraday_store --extend` fetches each name's missing bars; the trainer extends it itself), never the tick cache. The tick cache is warmed only for names a tick touches; `--with-30m` warms the panel universe.

Logs → `logs/llm_trader_YYYY-MM-DD.log` (7-day rotation). To force a fresh run ignoring caches, delete `cache/news_*.json` and/or `cache/snapshots_*.json`. **The OHLCV cache (`cache/ohlcv/`) and the DuckDB database (`data/llm_trader.db`) must never be deleted casually.**

**Trailing-NaN bar guard** (`cache.trim_trailing_nan_bars`, applied at PARSE time inside `load_ohlcv`). yfinance appends a NaN-Close row for the still-forming bar; an indicator handed one silently returns a different number. Only the trailing bar is trimmed and only on a missing Close. The guard lives at the market_data boundary — **scoring must never bypass `get_history`**. Tests: `tests/test_scorer_contract.py`.

**Intraday operation (no unclosed-bar look-ahead).** Marks and fills use **live** prices (`tracker._fetch_price`); the daily OHLCV feeding indicators is completed-bars-only (`market_data._drop_forming_bar` removes the forming bar until the 16:00 close). A **Hybrid** intraday overlay (`src/signals/intraday_timing.py`) affects entry/exit *timing* only: it defers an entry whose 30-min momentum strongly opposes it (`enable_intraday_timing`, ON) and can close on a hard intraday reversal (`enable_intraday_exit`, OFF). It never changes the daily-signal direction.

**Extended hours** (`extended_hours_mode` = `off | observe | trade`, live: **trade**). The runner ticks per `extended_windows` (`04:00-07:00@60,07:00-09:30,16:00-17:30,18:00-19:00@60,19:50-19:50` ET; `@MM` sets a per-window cadence). Extended slots are full trading ticks; `observe` mode runs analysis + persistence with zero ledger/broker mutation.

**Overnight session** (`overnight_hours_mode`, live: **trade**) on IBKR's overnight venue — Sun–Thu nights, 20:00–03:50 ET (`market_calendar.is_overnight_session_open`). Slots from `overnight_windows`. Overnight terms: modeled spread ×10, sizing ×`overnight_size_multiplier` (0.25), actionable threshold +10 pp (replaces, not stacks with, the extended +6 pp). Broker routes to the overnight venue (`broker_overnight_routing`, LMT-only, cap 150 bp); requires the gateway's API precaution bypasses in `C:\IBC\config.ini` (`BypassOrderPrecautions=yes` + `BypassRedirectOrderWarning=yes`). A refused overnight order counts as `overnight_deferred` and is resubmitted at the 04:00 pre-market open.

**Session classification** (`market_calendar.current_session` → `rth | extended | overnight`) is fixed once per run. `enable_extended_signal_profile` (**OFF**) governs whether the session changes the SCORE; with it off, scores are comparable across the day — one weight profile every session, `ext_gap` active in all sessions (reads 0.0 in RTH by design), no session-context prompt block. Independent of the flag: `extended_confidence_bump` (+6 pp) and `extended_size_multiplier` (×0.5).

**Extended trade lifecycle.** `_execution_iso()` returns *now* during RTH, extended-trade-mode and the live overnight session; closed venues, weekends and observe-mode snap to the next regular open. Every entry stamps `entry_session` (+ its sizing haircut); every close stamps `exit_session`. Costs are session-aware end to end (`spread._session_spread_multiplier`, `_pct_return`, daily-NAV anchors, `_normalize_closed_returns`, `_flip_trade`, live M2M). `reconcile.sync()` forces a marketable LMT outside RTH (IBKR rejects MKT there). Every perf surface accepts `session=`; the dashboard carries an RTH/Extended/Overnight toggle.

## Architecture

### Pipeline flow (`src/pipeline.py`)

`run_pipeline()` is the single entry point:

```
0.  Universe construction   — Static watchlist (always included) + dynamic discovery (trending, screener,
    macro→holdings, catalyst/analyst/earnings expansion, related-company peers). Discovery gate drops junk
    (is_valid_ticker), exotic security types (is_exotic_security), and microcaps below the OBSERVATION floor
    (discovery_min_price $1 / discovery_min_dollar_volume $1M — kept LOW so thin names keep accruing data).
1.  News & sentiment feeds  — RSS (CNBC/Seeking Alpha/Yahoo) + press wires + FDA/MedWatch + per-ticker Google
    News (symbol + company-name queries), all fetched FRESH every tick (the reactivity fast-lane) — plus NewsAPI, per-ticker yfinance news,
    Polygon (Benzinga), 8-K filings, Reddit, Quiver alt-data, analyst ratings, EPS surprises, short interest,
    Massive ticker events. All normalised to NewsArticle; merged pool URL-deduped. Per-ticker digests are
    cut from the pool by COMPANY-NAME relevance (`company_names.py`, primed for the universe up front).
2.  Market snapshots        — Polygon batch primary (real-time → price_source="live") → yfinance per-ticker →
    deterministic grouped-daily close (price_source="prev_close"). Indices/futures/OTC route through yfinance.
3.  Smart-money + macro     — Insider/congressional trades, options flow, SEC filings (13D/G, 144, 13F, Form 4),
    plus market-context fetchers (FRED, COT, VIX, MOVE, DIX, breadth, credit, bond/global macro, sector rotation).
3X. Regime & timing layers  — Macro Regime Filter, Market Mode, Catalyst Timing — gate BUYs, adjust thresholds/weights.
3#. Per-ticker scorers      — the 27 weighted methods + the panel-first set (below). Each returns [-1, +1].
3B. Broker advisor group    — src/signals/broker_advisor.py (enable_broker_advisor, currently OFF; needs broker_mode != off).
3M. Massive technicals      — server-side RSI+MACD composite scored as `massive`, run alongside our own `tech`.
3F. Fundamentals overlay    — Massive/Polygon ratios → <fundamentals_context> prompt overlay (§28) + directional
    factors f_value/f_quality/f_growth/f_short_squeeze (panel + small additive combine overlay).
3G. Corporate actions       — dividends + splits → §29 mechanics overlay + f_split / f_dividend factors.
4.  Signal aggregation      — aggregator.py combines per-ticker scores into a TickerSignal; sector_pairs.py finds opposites.
5.  Recommendations         — signals/rank_entry.py → BUY/SELL/HOLD/WATCH from the within-run
    combined-score RANK (no LLM in the trading path since 2026-09-04). claude_analyst.py still runs
    the same question as an unacted SHADOW arm (engine_recommendations); flip `enable_llm_synthesis` to restore it.
6.  Performance tracking    — tracker.py + daily_nav.py: paper trades, M2M updates, path-faithful daily compound.
7.  Charts + email          — charts/, email_sender.py.
```

**Two-tier liquidity.** A name clearing the observation floor but below the **TRADE floor** (`trade_min_price` **$5** / `trade_min_dollar_volume` **$5M**, `enable_trade_liquidity_gate`) is **OBSERVE-ONLY** — fully scored and persisted to the `signals` panel but gated out of actionable trades by **Gate 4** (`pipeline._is_tradeable`, fail-closed via `is_liquid`). The pinned watchlist bypasses the DISCOVERY gate only (`_protected`), **NOT Gate 4** — pinning a thin name gets it analysed, not traded.

**ONE dollar-volume definition** (`liquidity.dollar_volume`, 2026-09-03 audit): the trailing **MEAN of Close×Volume over the last 20 valid bars**, shared by the discovery gate, Gate 4, the rank pool, follow-through, the Tier-2 and NBBO-backfill pools, the screener and the short-horizon MR floors (`classic_anomalies._dollar_volume_ok`). Three formulas were live across seven sites and the LIVE GATE was the outlier — `mean(V[-20:]) × C[-1]` multiplies a 20-day volume average by a SINGLE price, so it admitted recent rallies and rejected recent declines (names admitted only by it had a median trailing 20d return of **+36.5%** vs **−22.7%** the other way — the chase direction Gate 5 exists to fight) and read HYMCW at 13.6M against a true 14.2k (**961×**). `spread.adv_of` deliberately stays on its median-60 basis: the cost liquidity classes were FITTED on it. Three companion fixes: the price floor is judged on the tick's **LIVE snapshot price AND the cached close** (the cached close alone is up to a session stale — 10 of 16 measured straddles were in the dangerous direction; a wrong snapshot can only defer a name, never admit one), `is_exotic_security` now runs at **Gate 4** as well as discovery (a warrant entering by a discovery-skipping path was tradeable — ARQQW traded 2026-06-17), and `is_liquid`'s catch-all except is logged. Because `is_liquid` fails CLOSED, a systematic breakage would gate out the whole universe and read as "no liquid names today", so the **rank-pool build carries a universe-wide CRITICAL guard** (< 25% of a ≥100-name scored universe clearing the floor) — that is the one place every name's verdict exists per run; the actionable cascade only ever sees `gate1_rank_cap` names. Tests: `tests/test_trade_liquidity_gate.py`. History: `memory/liquidity-price-volume-audit-2026-09.md`.

**Expected-liquidity / drift-risk forecast** (`src/performance/liquidity_forecast.py`, `enable_liquidity_forecast` ON, 2026-08-30). Right after the data fetch, every universe ticker gets an EX-ANTE expected one-way execution deviation (bp). Structural layer, in priority order: **(0) LIVE NBBO** (2026-08-31) — the Polygon batch snapshot's `lastQuote` rides the Step-2 response for the whole universe (verified real-time entitled, sub-second ages); the pipeline hands fresh (≤120 s) half-spreads to `set_live_spreads` before priming, authoritative for 90 min (`estimator="nbbo"`; a pre-market book quoting 30× its RTH width is exactly what the EOD layers can't see). **Measured against IBKR's own book (70 names, RTH): NBBO median abs error 0.39 bp, ratio 1.00 — effectively exact.** Then **(1) IBKR MEASURED half-spread** from the nightly BID_ASK sweep. **POINT-IN-TIME is the canonical basis** (2026-09-01): a live NBBO passes through unconverted, and the sweep — a whole-day TIME-AVERAGE running ~1.88× a point-in-time book — is divided DOWN onto it first (`_sweep_to_pit_scale`, prior 1/1.88, self-calibrating, registry `liquidity_sweep_to_pit`). Both then go through the **REFITTED POWER LAW `|deviation| ≈ a × spread^b`** (priors a **2.295** / b **0.647**, registry `liquidity_map_a`/`_b`, fitted per LEG by Theil-Sen in log space over `broker_orders.bid_at_submit` ∪ `broker_order_quotes`, shrunk + clamped, priors hold below 40 legs). **b < 1 is mechanistic**: the session LMT cap refuses the full touch on a wide book (60.6 bp quoted → 20.4 bp paid on 32+ bp books). Then **(2) Corwin–Schultz** on cached daily OHLCV (Spearman +0.374 vs realized |slippage|; UNDERSTATES wide names — LX measured 43 vs CS 20), Abdi–Ranaldo fallback, both ×`liquidity_level_factor` (prior 0.27, CS/AR rows only). **The per-ticker realized blend (w=n/(n+6)) applies ONLY to the CS/AR/class path** — on a MEASURED spread it was validated HARMFUL (all four held-out folds; the fitted mapping already conditions on today's book, so blending drags toward a stale unconditional average). Class-table fallback, else None. Risk classes low/<10bp, medium/10–20, high/>20 (validated monotone on realized drift: 8.5/13/14 bp, cap-breach share 19/34/38%). Cache-only, memoised per (ticker, day, sweep-store version), fail-soft. Persists per run to `signals.exp_halfspread_bps` (memo-only read — NULL when the prime didn't run) and stamps `exp_halfspread_bps_at_entry`/`liq_risk_at_entry` on new trades. **The MAPPED deviation (`expected_halfspread_bps`) is still PANEL-FIRST — it predicts drift and gates/sizes nothing**; what DOES decide is the raw quoted book underneath it (`quoted_halfspread_bps`, live NBBO only, RTH basis), which feeds NBBO sizing and Gate 4b. Keep the two straight: a 20 bp quoted book maps to ~16 bp of expected deviation, so a threshold means something different on each. Session widening via `expected_halfspread_bps(tk, session=)`. Tests: `tests/test_liquidity_forecast.py`.

### Data flow design

**Two tiers of data.** Per-ticker signals scored `[-1, +1]` and combined into a `TickerSignal`; macro context (FRED, COT, …) passed as structured prompt blocks for the LLM to apply as regime overlays. News sentiment is the *level*, sentiment velocity the *rate of change*, trend strength the trend *quality* (distinct from momentum's return *size*). A continuous `coherence_factor` ∈ [0.45, 1.35] dampens confidence when methods disagree.

**Score-sign convention** (the invariant the combine, IC and inversion depend on — see the `aggregator.py` docstring): EVERY method's score sign is the predicted direction of the STOCK (`+` = up, `−` = down, position-independent); mean-reversion methods bake the reversal INTO the sign; `|score|` = confidence.

**Method set.** 28 weighted (`aggregator._BASE_WEIGHTS`): news 0.40, tech 0.30, insider 0.30, sector_momentum 0.20, pattern/momentum 0.18, massive/put_call/oi_skew/money_flow/trend_strength/pead/ext_gap/mom_12_1/hi52 0.15, iv_rank 0.13, sent_velocity/max_pain/vwap/iv_expr/coint/st_reversal/ml_ohlcv 0.12, broker_advisor/rsi2_rev/dloc_rev/**news_quiet** 0.10, market_momentum 0.08. **Every weighted method needs an `_raw_active` entry** as well as a base weight — `_normalised_weights` iterates that dict, so one missing there scores, persists, ranks and shows in the dashboard while contributing weight ZERO (`news_quiet` shipped that way on 2026-09-09 and the live weight log caught it; `tests/test_news_quiet.py::test_every_weighted_method_has_an_active_flag` now pins it). **SECURITY-TYPE TABLE** (`company_names.prime_security_types` / `security_type` / `type_is_fund`, 2026-09-11). Polygon's ticker LIST endpoint carries `type` (CS/ETF/ETN/FUND/ETV/ETS) for the whole market in one paginated sweep — measured **13,174 tickers in 14 pages in 5.9 s**, covering **97.2%** of this universe, warm reload 6 ms — so the FUND verdict becomes a statement about the INSTRUMENT instead of an inference from a name. It does NOT carry `sic_code`, which is why the per-ticker detail call survives for operating companies. It is a FIRST tier, not a replacement: Polygon types closed-end funds as `CS` (CCD/CHI/CHY/CSQ — the ONLY 4 disagreements across 617 covered tickers), so `industry_is_fund` and the name heuristic still run behind it. Primed in Step 1 beside the names; `industry_of` skips the detail call entirely for a wrapper type. **Honest sizing: the speed win is the smaller half** — only ~6% of this universe are wrapper types, so a cold industry prime still makes a detail call for nearly every name; the authoritative fund flag is the real gain. Fail-soft: a failed sweep leaves the previous table and every caller falls back to the path that predates it. Tests: `tests/test_company_names.py`.

**A WEIGHTED method that is not a stacker feature reaches NOTHING** (2026-09-11). With `ml_combine_arm_share` at 1.0 the stackers ARE the combine — `combine_source` reads `ml` on **100%** of live rows, zero fail-soft — so a base weight only reaches the per-side fail-soft that never fires. `news_quiet` shipped weighted 0.10 and was the ONE news-family method missing from `STACKER_SIGNED_FEATURES`, so its direction vote decided nothing; it still reached coherence, `sources_agreeing` and the Sentiment family vote, which feed confidence and therefore position SIZE, but not which names are picked. **Buy/sell split combine.** Each weighted method's inversion-corrected view (`eff`) decomposes into a BUY component `max(0, eff)` and a SELL component `max(0, −eff)`; each side is weight-averaged over the methods HOLDING that view only (its own camp — abstainers and the opposing camp don't dilute a side). `combined_buy_score` / `combined_sell_score` are the two camps' convictions and **`combined_score` = their DIFFERENCE**. Camp SIZE is judged by the machinery built for it (coherence, family agreement; Gate 1b did too until it was switched off 2026-08-17), not by re-diluting the score. **Method inversion** (`inverted_methods`, `aggregator._inverted_methods`). A method whose RAW score is reliably anti-predictive net of beta is sign-flipped in the combine and lifted off the IC floor to base weight; the panel keeps the RAW score so the inversion stays re-validatable. **Automatic inversion** (`enable_auto_inversion` ON) requires TWO bars: the gross solo win rate significantly below 50% by a one-sided exact binomial at `inversion_alpha` (0.05) AND replication on the independent panel arm, and the FLIPPED view itself clearing `winrate_filter_threshold`. **Automatic database refactor** (`src/analysis/code_version.py` + `refactor.py`, `enable_auto_refactor`). **STANDING RULE — a calibration may only fit data the CURRENT code produced.** Panel side: `build_panel` masks superseded scores and confidence to NaN. Ledger side: calibrations reading trade fields gate explicitly (`score_is_comparable`, `confidence_is_comparable`). Both fail OPEN. Satisfy the rule by RESTRICTING each calibration to comparable data, never by rescoring history onto the current formula. The Bayesian shrinkage every calibration carries makes the smaller clean sample safe.

**Evaluation standard** (`.claude/skills/evaluate/SKILL.md`, invoked as `/evaluate`). One house standard for judging any signal, model, gate or exit here: label = the H/L pivot target with the running leg extreme (live-price-extended) standing in for unresolved pivots; population = the simulated/panel surfaces, never the trade ledger (a gate's dropped cohort does not exist there, and per-method power is ~11 attributed trades vs ~9,176 panel views); metric = **per-day Spearman IC vs the signed pivot label** for RANKERS and **mean oriented pivot return per decision vs a matched counterfactual** for DECIDERS (gates, exits, sizing, whole-algorithm A/Bs), both with day-clustered t; always split LONG/SHORT; house bar = paired t ≥ 2 AND same-sign halves, pre-registered before the run. Provisional labels are evaluation-only and must never reach a calibration or a training label. History: `memory/evaluation-metric-foundations-2026-08.md`.

**Significance tests are dependency-free by rule** (`src/analysis/stats.py`). scipy is not a declared dependency, so a `try/except` around `scipy.stats` would make the except branch the only one that ever runs. Degenerate input returns NaN ("no verdict"), never 0.0. **General rule: an optional import guarding a verdict the system ACTS on is an invisible off switch, not a graceful fallback.**

**Sentiment JSON repair** (`sentiment._repair_score_number`, 2026-09-03). JSON forbids a leading `+` and requires a digit before the decimal point, but the rubric asks for a float "between −1.0 and +1.0" — and a model duly emits `"score": +0.15`. That raised, ALSO defeated the salvage regex (which allowed `-` but not `+`), and lost an otherwise perfect verdict to a **neutral 0.0 inside the 0.40-weight `news` method** — indistinguishable from the model abstaining. Measured on the local acceptance run: **5 of 25 tickers**, and it read as a bad model until the raw output was inspected (LLY 0.000 → +0.52, BAC → +0.439, DIS → −0.281, the first negative verdict of the run). The repair is anchored on `"score"` specifically, never on any `:`, so it cannot rewrite a `+` that legitimately appears in the rationale text ("revenue +12% yoy"), and it is inert on already-valid JSON — so no engine's output changes and this is a parser repair, not a scorer change. The reusable point: **a parse failure and an abstention are the same observable**, so a scorer's "no view" rate is not evidence about the model until the raw responses have been read.

**PARSER HARDENING — a malformed answer must not become a CONFIDENT one** (2026-09-11).
Two paths could turn unreadable input into a maximum-conviction signal, and both are now refused
rather than coerced. **(1) Non-finite scores** (`sentiment._finite_score`): `json.loads` accepts
bare `NaN` and `Infinity` by default, and every comparison against NaN is False — so the obvious
clamp `max(-1.0, min(1.0, nan))` returns **+1.0**, i.e. the strongest possible BULLISH verdict in
the 0.40-weight `news` method, which in a rank-consumed combine puts the ticker at the top of the
cross-section where it can open a trade. `Infinity` lands on +1.0 the same way. Both now raise, so
the ticker falls through to the next engine exactly as every other unreadable response does; an
ordinary out-of-range number (4.2) is still CLAMPED, not thrown away, and the salvage regex cannot
readmit a non-finite value because `[-+]?\d+` does not match `NaN`. The module's own standing
lesson is that a parse failure and an abstention are the same observable — a parse failure that
produces CONVICTION is worse than either. **(2) Naive timestamps** (`news_fetcher._parse_iso`): it
only handled a trailing `Z`, so an offset-LESS ISO string came back NAIVE, and every consumer
subtracts `published_at` from an aware "now" — `_recency_weight` on every article of every digest,
the clustering time partition, `news_quiet`'s age. A naive/aware subtraction raises TypeError, which
inside `analyse_sentiment` reads as the ticker simply failing to score: a silent 0.0 in the
0.40-weight method. It now always returns an aware UTC datetime, the idiom `_parse_news_time` three
lines below already used. LATENT rather than live — that subtraction has run every tick for months
without raising, which is good evidence naive timestamps do not currently occur — but the failure
mode is silent and the fix is one line. Tests: `tests/test_sentiment_parse.py`,
`tests/test_news_archive.py`.

**WHY THE PRICED-IN FAMILY IS CLOSED — the CLAIM is not a MEASUREMENT** (2026-09-11). The standing defect read "priced-in ignored: the model makes the strong claim and half of those still score MINOR+". It is not a defect. Findings: the claim fires on **44.4%** of rationales under a detector requiring an intensifier bound to the phrase (a bare mention fires on 53.4% — v6's rubric MANDATES the check, which is what made three earlier regex detectors over-fire, and is why 14% and 44% are both true of different detectors); claim rows score **HIGHER, not lower** (mean |raw| 0.351 vs 0.294, MINOR+ 65.4% vs 54.9%) because they are the bigger, better-covered stories; the claim barely tracks the move (z(claim) − z(no claim) **+0.096σ**, +0.082 stratified by digest size); and **per engine it points OPPOSITE ways — local qwen +0.164, DeepSeek −0.108** — so any uniform rule averages a roughly-right response on half the rows with a backwards one on the other half, which is what four measured failures look like from the inside. So the claim is a noisy, engine-inconsistent, partly anti-correlated estimator of a quantity the pipeline measures directly, and acting on the text can only add noise on top of the measurement. **What ships instead is the measured version, per SIDE and fitted rather than hand-signed**: `news_bear_fresh` (an un-fallen tape guards a bear read) and `news_bull_fresh` **inverted** (an un-moved tape is anti-signal for a bull read), with `news_unpriced`/`news_unpriced_all` riding the stacker feature set for the model to sign. **NOT done, deliberately:** the prompt's PRICED-IN CHECK block stays — and it was MEASURED on 2026-09-11 rather than left on assumption. ### Performance calculation

Two engines side by side, both rooted in the *real* observed prices stored on each trade.

**Per-trade `return_pct` (buy-and-hold, cost-aware) — `tracker._pct_return()`**

```
cost_in  = _one_side_cost(entry_price, asset_type)            # half-spread + commission
cost_out = _one_side_cost(exit_or_current_price, asset_type)
BUY  : eff_entry = entry × (1 + cost_in);   eff_exit = exit × (1 − cost_out)
       return_pct = (eff_exit − eff_entry) / eff_entry × 100
SELL : eff_entry = entry × (1 − cost_in);   eff_exit = exit × (1 + cost_out)
       return_pct = (eff_entry − eff_exit) / eff_entry × 100
```

**Per-trade cost attribution** (`sim_per_trade_cost_attribution`, ON; liquidity classes 2026-08-25 — user directive "decommission the in-house model"). Each leg is charged the best-fitting REALIZED cost by a six-tier hierarchy (`spread.resolve_leg_cost`): the leg's OWN realized cost if it FILLED ("never approximate a filled trade") → the SAME-TICK average of fills in the leg's **LIQUIDITY CLASS** (price band {<20, 20–100, ≥100} × trailing-median dollar-volume band {<20M, ≥20M}; edges are module constants) → the plain tick average → the time-of-day PERIOD average in its class (Bayesian-shrunk toward the session mean by `sim_cost_bucket_prior_n` 8, clamped 0.25–4× it) → the plain period average → `_one_side_cost`, which itself prefers the calibrated session/flat real-fill overrides — **the hand-built spread formula is now reachable only on a fills-free DB (cold-start prior) and for sub-min-price penny legs (deliberate guard)**. ADV via `spread.adv_of` (cache-only, day-memoised). Built each tick by `calibrate_sim_costs` from the same sanity-banded LMT fills (registry row `sim_cost_buckets`; live 2026-08-25: 18 session-class buckets, RTH 0.14–0.18%/leg, overnight 0.39–0.44%). Ledger purity is preserved — every sim trade still assumes it fills; only the COST is sourced more precisely. Both return engines share `resolve_trade_leg_cost`. Tests: `tests/test_cost_buckets.py`.

**Short borrow carry** (`enable_short_borrow_cost`, `short_borrow_annual_pct` 3.0%): a direction-asymmetric HOLDING cost (SELL legs only) charged per **calendar** day, subtracted in `_pct_return` and per-day in the daily-NAV walk. Prefers the broker's real fee over the setting.

**One-way cost** (`spread._one_side_cost`) = half-spread + commission. The commission term is a deliberate **fee ceiling, not a best estimate** (`ibkr_fixed` default: max($1.00, $0.005/share)), capped at 1% of trade value, × `commission_buffer` (1.5). **Real-fill calibration** (`sim_use_real_fill_costs`, ON): once ≥10 actual **LMT** fills exist, `calibrate_sim_costs()` measures the average all-in one-way cost and installs it via `spread.set_real_cost_override()`. A sanity band (±2%) discards legs with a stale `model_price`. Residual bias: the sample is only filled legs (~13% fill rate), so it understates the intended-trade cost. Called before the tick's normalize/M2M/entry steps so a run uses one cost basis throughout.

**Path-faithful daily compound — `daily_nav.compute_compound_return(trades)`.** Per trade: load OHLCV closes → build chronological marks `(entry_date, eff_entry)` → every cached close strictly between → `(exit_date or today, eff_exit)` → per adjacent pair `r_d = sign × (mark_d − mark_{d−1}) / mark_{d−1}`. Portfolio: group `(date, daily_return, weight)` by date → `Σ(r·w)/Σ(w)` → compound sequentially. **Deterministic given the database.** Time-window variants filter by `entry_date` before aggregating; the cost basis is always from the full ledger.

**Summary statistics — `tracker._compute_segment_stats()`** (any slice): `trades`, `win_rate` (GROSS — see below), `compound_return` (daily walk), `avg_return` (equal-weighted), `wtd_avg_return` (capital-weighted), `best`/`worst`. Open trades' `return_pct` is the live M2M so they contribute to every metric.

**THE WIN-RATE CONVENTION (standing directive): every win rate in the system is GROSS; costs are measured by the RETURN metrics only.** A win rate asks one question — did the position move the way it was supposed to, on raw prices. A cost-adjusted win rate silently answers *two* ("was the direction right?" and "was the move bigger than the round trip?"), and the second is an execution property that moves with the spread model, the venue and the session — so the same signal would score worse for being traded in wide markets, and every cost recalibration would rewrite the win rate of history that did not change. Canonical helpers: `tracker.gross_return_pct(trade)`, `is_gross_win(trade)` (`None` when prices are unusable — such trades leave BOTH numerator and denominator, so a data gap can't masquerade as a bad signal), `gross_win_rate(trades)`. Applies to every breakdown, eval row, sizing calibration, `broker_view`, `source_performance`, `pattern_registry`, `confidence_calibration`, `regime_performance`, `policy_eval` and the equity chart. Panel/simulated surfaces were already gross by construction. Pinned by `tests/test_gross_winrate_convention.py`, whose decisive case is a right-direction trade whose move was smaller than the round trip: a WIN with a negative return, both in the same stats dict.

**Hypothetical solo & eval stats.** If a method's sign matches the actual action → use the trade verbatim; if it disagrees → `_flip_trade()` returns a same-ticker/same-dates dict with action inverted and `return_pct` re-derived. Conviction bands (`_eval_stats`): Low 0.10–0.35 / Medium 0.35–0.65 / High 0.65+ on `|method_score|`.

**Self-calibrating parameters.** Frozen constants are replaced by values learned from the system's own tables through one idiom (documented prior → evidence → Bayesian shrinkage → clamps → fail-soft to the static setting), all reported to the calibration registry (`src/performance/calibration.py` → `gate_diag["calibrations"]` → the Data Quality tab): per-session real-fill costs, the derived horizon cost hurdle, the engine-relative actionable threshold, the calibrated exit-confidence floor, breadth sizing, the expected-edge sizing blend, the predictability sizing tilt, and the edge-decay time-stop window. Risk guardrails (liquidity floors, exposure caps, wipe guards, order-cap ceilings) and the calibrations' own meta-parameters stay fixed.

**Direction-scoped parameters** (`config.settings.directional(name, direction)`): resolves `{name}_long` / `{name}_short` when set, else the shared `{name}`. Every override defaults to None (inert). Splits are justified where the asymmetry is STRUCTURAL or a threshold SWEEP is stable across a wide band — never a single point estimate. Two are MEASURED per side rather than pinned:

- **Per-side actionable threshold** (`tracker.calibrate_side_threshold`, `enable_side_threshold_calibration`). Gate 1 is the highest-leverage parameter, so this is the most conservative split: Bayesian-shrunk by `side_threshold_prior_n` (40), capped at `side_threshold_max_adjust` (+0.04), and it can only TIGHTEN. Evidence is whether confidence DISCRIMINATES on that side (per-direction Spearman of entry confidence vs realised return). Surfaced in `gate_diag.threshold_adj_buy/sell`; pin with `actionable_threshold_adj_{long,short}`.
- **Per-side horizon ramp** (`tracker.calibrate_horizon_ramp`, `enable_horizon_ramp_calibration`). `horizon_expiry_floor_mult` resolved per DIRECTION from the gap between what `horizon_expired` trades returned and that side's other exits (negative → tighten, positive → loosen). Bayesian-shrunk by `horizon_ramp_prior_n` (30), clamped ±30%, floored at 1.0. Tests: `tests/test_directional_params.py`.

**Sizing chain (`record_new_trades`).** compressed confidence ramp (`confidence_size_span` 0.5 → max 1.5×) × **agreement-breadth tilt** (self-calibrating, set-size-normalized — breadth was the strongest entry-time discriminator) × **expected-edge blend** (`performance/edge_sizing.py`, ridge model whose say grows with closed-trade evidence, inert below 20 closes; since 2026-08-22 the FIT is comparability-gated — `_row_is_comparable` excludes rows whose entry predates `CONFIDENCE_EPOCH` or the news/momentum scorer epochs (it was the one decision-feeding confidence consumer without the gate, fitting across two scales: 489 mixed rows → 51 comparable, blend weight 0.75 → 0.25 until clean history accrues), and the combined feature rides the ABSOLUTE twin per the `ex_combine` convention) × **predictability tilt** (`performance/predictability_sizing.py`, sizes up forecastable-direction names, never a gate) × **NBBO liquidity tilt** (`performance/nbbo_sizing.py`, `enable_nbbo_sizing` ON, 2026-09-02) → **regime size haircut** (RISK_OFF ×0.5) → correlation-aware haircut (scale-down vs same-direction open peers, hard skip at the correlated-exposure cap) → `extended_size_multiplier` (×0.5 extended / ×0.25 overnight).

**NBBO liquidity sizing** (`src/performance/nbbo_sizing.py`, `enable_nbbo_sizing` ON, 2026-09-02, user directive). Sizes each entry by the QUOTED point-in-time half-spread of the book it must cross, **per side, because 30 days of the live ledger measured the two sides improving for different reasons**: LONG only its COST (day-clustered keep-minus-drop *pivot* excess ~0 at every threshold, while the *net* excess rises to **+1.38 pp/day, t +2.08, at a 20 bp cut**), SHORT its DIRECTION (pivot win rate 58.8% ungated → 76.7% under 4 bp, p .003; **+31 pp inside RTH alone**, so not a session artifact). Curves: LONG full size to `nbbo_size_long_wide_bps` (20) then a 4 bp ramp down to `nbbo_size_long_wide_mult` (0.35); SHORT `nbbo_size_short_tight_mult` (1.5) below `nbbo_size_short_knee_bps` (5, 1 bp ramp) then monotonically decreasing `1/(1+(bps−knee)/nbbo_size_short_decay_bps)` to `nbbo_size_floor_mult` (0.20). Each ramp sits on the LENIENT side of its boundary (same reason as `enable_continuous_regime_threshold`) so quote noise at 19.9 vs 20.1 bp can't move a position 3×. **Input is `liquidity_forecast.quoted_halfspread_bps` — the LIVE NBBO only, RTH basis.** Three refusals are load-bearing: it is NOT `exp_halfspread_bps` (that is the spread already mapped through the power law — a 20 bp book maps to ~16 bp of deviation, so the thresholds would mean something else); the session's own widening is divided back out (already charged by `extended/overnight_size_multiplier`); and the **IBKR sweep is refused as a fallback** — like-for-like against 769 tickers' RTH NBBO medians its rank correlation is 0.913 but its LEVEL is **0.78×** the real book, disagreeing about the 4/5 bp side for 15–17% of names, which would over-boost shorts and under-cut longs invisibly. No live book ⇒ multiplier exactly 1.0 (the prime covers 99.9% of panel rows in an RTH tick and correctly abstains off-hours). Applies to the follow-through path too. **Interaction with Gate 4b (2026-09-03):** the 12 bp cap now removes wide-book LLM-path candidates BEFORE sizing, so on that path the LONG wide-ramp (≥ 20 bp) is unreachable and the SHORT decay only operates between the 5 bp knee and 12 bp — the full curves still govern follow-through entries (ungated by design). The curves are deliberately left at their measured shape rather than re-fitted to the surviving range: the cap is a setting, and a curve fitted to one cap's shadow would silently mis-size the day it moves. Audited per trade (`nbbo_size_multiplier`, `nbbo_half_bps_at_entry`, `nbbo_estimator_at_entry`). Tests: `tests/test_nbbo_sizing.py`.

Both sides land in **`engine_recommendations`** (run, engine, model, `prompt_variant`, a `live` flag, ticker, action/direction/confidence/horizon/rationale, the snapshot price, `rule_filled`, latency, n_signals/n_recs) — one row per engine per ticker per run, which is what makes them comparable as DECIDERS later. Rule-filled rows are excluded on either side: a fill is not a decision. Agreement is not skill — the house bar stays t ≥ 2 AND same-sign halves (`.claude/skills/evaluate`).

**The local SYNTHESIS arm is configured but records NOTHING today, and the two jobs are configured SEPARATELY.** `enable_local_llm` is the master switch for both routes; `local_sentiment_*` (`base_url` / `model` / `api_key` / `timeout_seconds` / `extra_body` / `context_tokens`) configures the sentiment route and `local_synthesis_*` the synthesis one (same six names plus `max_prompt_tokens` / `max_output_tokens`), each synthesis knob **inheriting** its sentiment twin while blank/0 — the single-server default in force, since one Ollama serves both and its `OLLAMA_CONTEXT_LENGTH` / `_NUM_PARALLEL` / `_KV_CACHE_TYPE` are **server-wide** (per-request `num_ctx` is ignored on the OpenAI-compatible endpoint, so the only way to tune the two jobs apart is a second endpoint or a second model name). The full synthesis prompt (p50 **60k** input tokens) does not fit this box's 8 GB of VRAM at any context setting, so the local arm takes a **COMPACT prompt** (`claude_analyst._compact_synthesis_prompt`: the same decision framing and the same ranked per-ticker blocks, minus the macro / fundamentals / per-method instruction blocks) — **an ENGINE difference and a PROMPT difference together**, which `synthesis_shadow_extra="deepseek:compact"` exists to decompose; `prompt_variant` (`auto` | `full` | `compact`) is part of the `engine_recommendations` key, so a variant arm rides BESIDE the live row instead of the shadow drain deleting it. Two truncation guards fail CLOSED (`src/analysis/local_llm.py`, shared with the sentiment route so the constants cannot drift): a PRE-FLIGHT refuses a prompt over `local_synthesis_context_tokens` (inheriting `local_sentiment_context_tokens` **8192** — keep it in step with `scripts/run_ollama.bat`), and a server-reported `prompt_tokens` below 60% of the estimate refuses the ANSWER, because Ollama truncates the OLDEST tokens — the persona and the process block — with no error, and a decision made without its instructions is not that engine's decision. ⚠ **At the live `OLLAMA_CONTEXT_LENGTH=8192` every local synthesis is refused by the pre-flight, so `synthesis_local_share` is 0.0 and the local arm records NOTHING, at no GPU cost**; raising it (proposed `NUM_PARALLEL=1` + `CONTEXT_LENGTH=32768` + `KV_CACHE_TYPE=q4_0`) costs sentiment its parallel slot — a hardware/scheduling decision, not a code one, and restarting Ollama takes the sentiment engine down with it. `_LOCAL_CHARS_PER_TOKEN` (3.2) stays an uncalibrated estimate until a local synthesis is actually benched. History: `memory/synthesis-engine-pairing-2026-09.md`.

**The same truncation exposure exists on the SENTIMENT route and now reports itself.** Both guards (`src/analysis/local_llm.py`, shared by the two call sites so the constants cannot drift) run on the sentiment call as well: over-context prompts are refused before the call, and a server-reported `prompt_tokens` below 60% of the estimate refuses the answer after it — both falling through to the next engine, because a verdict scored without its rubric is not an abstention, it is noise entering the 0.40-weight `news` method, and it parses exactly like a real one. **The context is NOT divided across slots** (settled 2026-09-05 from the child process's own arguments: `llama-server … -c 16384 -np 2` — Ollama allocates `OLLAMA_CONTEXT_LENGTH × OLLAMA_NUM_PARALLEL`, so each request gets the full **8192** and `run_ollama.bat`'s comment was right). Corroborated by 2,263 local verdicts on 2026-09-04 with zero refusals, 20-article digests included. Both guard constants were **recalibrated the same day**: `CHARS_PER_TOKEN` 3.2 → **4.0** (measured 4.38 on the 9,528-char prefix DeepSeek counts at 2,176 tok) and `TRUNCATION_RATIO` 0.6 → **0.85** — at the old pair a truncation to 4,096 tok reported 0.66 of the estimate while a healthy call reported 0.73, so the guard could not have fired on the largest digests, which are the ones that truncate. Move the two together or not at all. A ratio alone still cannot close the window (truncation begins when the REAL count passes the context, a ratio only sees it once the ESTIMATE passes context/ratio), so `check_reported` now runs an EXACT test beside it: a prompt that FIT reports strictly fewer tokens than the context it fit in, so a count landing AT the configured context is truncation — no estimate involved, hence undefeatable by a wrong `CHARS_PER_TOKEN`. The ratio covers the case that one cannot see, an EFFECTIVE context below the configured one.

**Operationally the shadow arm is off the critical path, exactly like the sentiment one.** `engine_shadow.maybe_start` queues the LIVE rows synchronously (they exist already, so they land on this tick's drain) and runs the arms on a daemon thread; `_persist_run` drains **non-blocking**, so a still-running arm carries its rows onto the next tick's write — hence the per-`(run_id, engine, prompt_variant, ticker)` write with no run-wide DELETE. `synthesis_shadow_engine` "auto" pairs whichever engine was not live; an arm identical to the live one is dropped, and a local arm is dropped while `enable_local_llm` is off or waits (bounded, 600 s) for the sentiment shadow pass to release the server. `synthesis_shadow_max_pending` (2) is the single-flight cap — a local synthesis runs minutes, and without it a slow box would pile up one branch per tick. A failed or empty arm records NOTHING rather than a fabricated call. Tests: `tests/test_engine_shadow.py` (and `tests/conftest.py` switches the pass OFF for every other test).

**Confidence PLACEMENT rubric** (`claude_analyst._CONFIDENCE_PLACEMENT`, v2026-08-19). The conviction rules used to state the bands as bare thresholds, and **the threshold values became the answers** — the same anchoring pathology as sentiment v2: distinct confidence values collapsed 28 → 8, 20–35% of BUY/SELL calls came back at exactly 1.00, and because that bucket IS the cohort clearing Gate 1 the inflation alone roughly **doubled the trading rate** (confidence also drives the sizing ramp, which saturates at 1.00). The fix is **band-then-placement**, mirroring the sentiment v3 repair: the bands still choose the ACTION (so Gate 1's level is preserved) and a named-modifier procedure chooses the NUMBER inside the band, landing on two decimals. It **plants no numeric example** — any value written into a prompt is a candidate modal output, so the modifiers are named and their size described in words. ONE constant shared by all three arm variants (three copies is how the original drifted). The JSON schema emits **`rationale` before `confidence`** (thinking is off, so field order is generation order — free chain-of-thought; the parser reads by key) and forbids 1.00. `_warn_on_degenerate_confidence` logs a WARNING when a run's actionable grid collapses again (>10% at exactly 1.00, or <10 distinct values, ≥25 calls) — thresholds are module constants, not settings. Tests: `tests/test_confidence_placement.py`. History: `memory/confidence-anchoring-2026-08.md`.

### ML methods

Trained models as signal methods. The convention (matching the buy/sell split) is that a method emits a **bullish score ∈ [0,1] AND a bearish score ∈ [0,1]** — a classifier's `P(up)`/`P(down)`, both low = a genuine no-view. Requires **lightgbm**; models use lightgbm's **native Booster API, NOT `LGBMClassifier`** (which would need scikit-learn even to unpickle — the artifact must stay sklearn-free). History: `memory/ml-methods-plan-2026-07.md`.

**Harness (offline):** `src/analysis/ml_dataset.py` builds one row per (ticker, session_date) from the deep OHLCV cache (**76** causal features — raw + expanding within-ticker z-scores + 6 cross-sectional ranks; labels `fwd_ret_{raw,rel}_<h>d`; causality by construction, leakage-probed). The 9 pivot **leg-state features** live in `src/analysis/pivot_target.py`. The full-universe training set materialises to `cache/ml/dataset_full.parquet` (~9M rows). `ml_train.py` = `SoftmaxLogistic` (pure-numpy baseline) + `LightGBMModel` + **`LightGBMRankRegressor` (the production v2 model)** + `walk_forward_predict` (trains only on rows whose label printed) + `evaluate()`. Leakage guarded by three adversarial tests in `tests/test_ml_dataset.py`.

**`ml_ohlcv` — OHLCV base signal, WEIGHTED 0.12.** A `LightGBMRankRegressor` on the within-day rank of the **signed pivot target** — since 2026-09-16 the next H/L pivot on 30-MINUTE bars after each training row's session close (`pivot_target.session_close_labels` over the deep 30-minute store, so labelled rows start in 2021; `ml_model.train_and_persist_pivot` streams features and labels per ticker into preallocated arrays — the dict-per-row frame OOM'd on this box) — 85 features (76 causal OHLCV + 9 DAILY leg-state: daily features, intraday label), full universe, no conditioning, uniform day-equal weights. Score = `clip(2·pred, −1, 1)`, meaningful relative to same-day scores. Promotion gate: `python -m src.analysis.ml_validate --target pivot` (train-on-deep / judge-on-panel, point-in-time) — **but pass `--from-parquet cache/ml/dataset_full.parquet`**: the CLI default is the small offline set (`dataset_multi`, ~388k rows) while production trains on `dataset_full` (~9M), so the default run validates a model production does not serve (found 2026-08-18: gate predictions correlated with live `ml_ohlcv` at only +0.04/+0.60/day; a MISMATCH banner now prints beside the VERDICT). The gate's pre-registered t ≥ 2 bar also predates the 2026-08-12 H/L pivot redefinition, which alone moved the same statistic +0.064 → +0.244 — ICs across that date are different quantities and the bar needs re-setting before it can gate a promotion again (the full-parquet run is also ~32 GB RSS; don't run it casually beside the live scheduler). Tests: `tests/test_ml_validate_training_set.py`. The artifact stamps `pivot_basis` (`hl1@30m`) and serving **ABSTAINS on a mismatch** (`BASIS_STALE`) — a model fitted to a retired label (the daily H/L one, another threshold or marks basis) takes the method to 0.0 until the retrain lands. Retrains weekly (currently HELD — see Retrains); `ml_ohlcv_target=classic` reverts the trainer to the v1 classifier (serving always dispatches on the artifact's own config). **Serving scores the PREVIOUS session's completed bar at any intraday tick** (`ticker_feature_frame(...).iloc[-1]` with the forming bar dropped) **with the 6 cross-sectional ranks absent** — an offline re-score must reproduce exactly that (previous row, `_XRANK_SOURCES` NaN; rank corr with the persisted column 0.996, against −0.006 for the same-day row), or it reports an IC the served model never had (measured 2026-09-15: +0.05 served vs +0.17–0.27 same-day). Measured 2026-09-15 before the switch: retrained on the 30-minute H/L @1% label it is no better and no worse than the daily-trained model on any yardstick (paired |t| < 1), so the 2026-09-16 retrain onto it is a consistency change, not an edge claim (`memory/pivot-label-verdict-2026-09.md`). Fail-soft everywhere. **Two models now CONSUME this score as a feature** (`STACKER_LIVE_FEATURES` since 2026-08-24, hence `ml_exit` too) — so a change here propagates to the stackers and the exit timer at their next retrains, and its ABSTENTION (`BASIS_STALE`, or the epoch mask) shows up there as a NaN column, not as an error. Tests: `tests/test_ml_model_pivot.py`.

**`ml_buy` / `ml_sell` — the FULL STACKERS as combined_buy/sell_score (`ml_combine_arm_share` **1.0** since 2026-09-05 — the A/B is OVER and the stackers ARE the combine on every run; the weighted camps survive only as the per-side fail-soft, recorded in `combine_source`).** `src/analysis/ml_stacker.py`. **The divisor is a SATURATION control, not a Gate-1 formula.** It does not reach Gate 1 mechanically — the LLM restates its own confidence. It reaches Gate 1 because every row with `|combined| ≥ divisor` clips to `raw_confidence` 1.0 and is rendered in the prompt as `combined_confidence=100%`. Measured on ml-source candidates, that anchor bin passes Gate 1 at **67.2%** vs 6–17% for every lower bin, and the LLM tracks the ML anchor closely (**Spearman +0.68**) *because it varies* — on weighted runs nearly every top-40 slot reads 100% (mean 0.997), so the anchor carries no information and the model falls back to its own ~0.86 prior (Spearman +0.015). A 100% anchor only persuades when its neighbours aren't also at 100%. At 0.0658 saturation hit 60–77% of ml-source candidates and the arm traded **~2.1× the weighted arm** (replicated every post-fix day: 2.15×/1.81×/2.40×). The divisor also feeds sizing through the confidence ramp. **The reusable tell: an A/B arm that silently stops ACTING looks identical to an arm that is losing — always check each arm's exposure before reading its P&L.** Second tell: **`combine_source` resolves PER TICKER, so an "ML run" contains weighted fail-soft rows too — grouping by run mixes the treatment with its own control.**

**The divisor is SELF-CALIBRATING** (`src/signals/ml_scale.py`, `enable_ml_scale_calibration` ON, 2026-08-18). A constant cannot hold a saturation control when the stackers retrain **weekly** onto a new conviction scale (all-row saturation moved 16.3% → ~26% across the 08-15 retrain), so what is pinned is the **saturation SHARE**, not the number: each refresh measures the WEIGHTED arm's own clip rate (shrunk toward `ml_saturation_target` 0.09, clamped 3–25%), then solves the divisor as the matching quantile of the ml-source `|combined_score|` distribution over `ml_scale_window_days` (5). Shrunk toward the static `ml_raw_confidence_scale` (**0.12**, still the documented prior and the fail-soft value) by `ml_scale_prior_n`, clamped to ⅓–3× it (module constants, not settings), reported to the calibration registry as `ml_confidence_scale`, TTL 3 h + single-flight, asof-registered. **Two properties make re-deriving it from the panel sound rather than circular:** `combined_score` is persisted UNCLIPPED (so the quantile isn't censored by the divisor in force — reading `raw_confidence` instead would let the calibration only ever confirm itself), and the ML divisor never appears in its own inputs. Deliberately **no `CONFIDENCE_EPOCH`**: that instant is global and would discard the weighted majority's history, this is a refinement rather than a categorical change, and pinning the share is what keeps ML confidence *comparable* across artifacts. Inspect with `python -m src.signals.ml_scale`. Tests: `tests/test_ml_scale.py`.

**Retrains (mechanics).** All three artifacts retrain **weekly, Saturday 08:00 ET** when enabled (`runner._run_weekly_ml_train`, single-flight background thread). To retrain out of band, run them **in this order**:

```bash
python -m src.data.intraday_store --extend      # the deep 30-min store (the trainer also does this; ~3,400 Polygon calls — never beside an RTH tick)
python -m src.signals.ml_model                  # ml_ohlcv        (forced; --throttled honours ml_pivot_retrain_days)
python -m src.analysis.ml_stacker --train       # ml_buy + ml_sell (always as a PAIR)
python -m src.analysis.ml_exit_dataset --train  # ml_exit
```

**Why that order:** not a training-input dependency (all three train on already-persisted history), but each model's FUTURE training rows are manufactured by the upstream artifacts' live scores — `ml_ohlcv` feeds `combined_score`, the stackers REPLACE that combine's camps on arm runs, and `ml_exit` reads the resulting combine. Retraining downstream-first just means the downstream model spends the gap learning from an upstream you were about to fix. Fix the ABSTAINING artifact first.

Every step is fail-soft, so an ad-hoc retrain is **safe alongside the live scheduler** — it is CPU/RAM-heavy (the ml_ohlcv rebuild re-materialises the 5.4 GB parquet, ~8 GB RSS, 20–40 min), not lock-dangerous. A kill mid-rebuild is clean (parquet and pickle are written only at the very end). Four traps, each SILENT:

- **The throttle returns `None`, not an error** — `eod_train()` unforced skips whenever the artifact is younger than `ml_pivot_retrain_days` (7). The CLI therefore **forces by default**.
- **`python -m src.signals.ml_model` must dispatch through `eod_train`** — calling `train_and_persist()` directly trains v1 *classic* regardless of `ml_ohlcv_target`, silently downgrading a weighted method.
- **The replay step does NOT regenerate `ml_ohlcv`** — a model-derived score cannot join the replayable set (replaying it with a model trained through today is look-ahead). Its panel history is masked by the epoch and refills only FORWARD.
- **The stackers are downstream of the pivot LABEL first, and of `ml_ohlcv`'s scores only weakly** — `ml_ohlcv` HAS been a stacker feature since 2026-08-24, but at ~7–17% post-epoch coverage it measured a wash (paired −0.0008/day), so a fresh `ml_ohlcv` artifact does not by itself justify a stacker retrain. Retrain them after a `stacker_label_basis` change, a feature-set change, or once `ml_ohlcv`'s panel coverage is thick enough to matter.

**Retrain out of band whenever a CATEGORICAL change lands:** a pivot label change — marks basis, `pivot_min_move_pct`, resolution (serving abstains with `BASIS_STALE`, so a 0.12-weighted method reads 0.0 until the retrain — urgent, not cosmetic; the stackers and `ml_exit` carry no basis stamp and keep serving, but their next retrain fits the new label), a `stacker_label_basis` change, or a feature-set change.

**The actionable filter is extracted into `pipeline._apply_actionable_gates`** (Gates 1, 1c, 1b, 2, 3, 4, 4b, 5 — that order, per-gate counters, per-ticker `gate_outcomes` stamps; 1b is flag-disabled and passes everything). The cascade takes this tick's `live_prices` (Gate 4's live price floor) and `session` (Gate 4b's RTH basis). `gate_funnel.GATE_STAGES` and `tracker.compute_stage_eval`'s funnel rows carry Gate 4b as `wide_book`; like Gate 3 it is **declared not simulable** (`_SIM_UNSIMULATED`) rather than silently passed — a gate that always passes looks identical to one that never rejects. Tests: `tests/test_actionable_gates.py`, `tests/test_gate_funnel.py`, `tests/test_stage_eval.py`.

### Broker integration (paper-first live execution)

`src/broker/` adds a real **execution leg** alongside the internal NAV simulator — a "shadow & reconcile" design. Gated by `settings.broker_mode`; **`off` makes zero broker calls.** Live: **`ibkr_paper`** (port 4002).

- **Modes:** `off` | `dry_run` | `ibkr_paper` | `ibkr_live`. Paper vs live is the configured `ibkr_port`; the factory refuses to start `ibkr_paper` on a known live port.
- **Broker = Interactive Brokers** via `ib_async` → IB Gateway (the only API broker letting a Canadian resident paper + live trade US securities). `ib_async` is imported lazily.
- **Single hook point — `reconcile.sync()`** runs once per tick right after `record_new_trades`. Idempotent and self-healing, in order: **(0) fill refresh** — earlier-tick orders not yet terminal are repaired from today's executions (keyed by `orderRef`); **(0b) tick-scoped order lifetime** — an order lives exactly one tick; anything still unfilled is cancelled and its leg cleared so the entry/exit pass resubmits re-anchored. Entries resubmit only when the trade survived this tick's signal pass AND clear the **price-aware resubmit gate** (chase only when the fresh signal still wants it inside `broker_resubmit_max_adverse_bps` (100 bp), or at an equal-or-better price); EXITS are never gated. **(0c) cancel-on-close.** **(1)** internal OPEN trades without a `broker_order_id` → sized entry (sizes the GAP vs any same-side held position). **(2)** internal CLOSED trades still holding a position → close, sized from the actual position (sign-checked). **(3) drift** — positions the ledger can't explain: `broker_drift_action` **`"flatten"`** submits a price-capped marketable LMT (never adopted into the ledger), re-anchored each tick; `ibkr_live` always refuses auto-flatten. **(4) settle — fill fast or kill** (`broker_settle_seconds` 30): this tick's unfilled orders are watched, re-anchored at a fresh quote every ~6 s, and CANCELLED at the deadline so nothing rests across ticks. Every broker call is exception-safe.
- **Order-vs-ledger durability.** The invariant: **no order may work the book unless a ledger leg points at it.** `_persist_legs` flushes the ledger immediately after every submission. `cancel_order` cancels EVERY order matching a ref (IBKR does not dedupe `orderRef`). `_working_order_for_ref` is a pre-submit duplicate guard. `_sweep_orphan_orders` cancels working orders no ledger leg owns (drift-flatten refs and hand-placed TWS orders are exempt). `IBKRBroker.connect()` calls `reqAllOpenOrders()` so a relaunched scheduler sees prior sessions' orders. Tests: `tests/test_broker_reliability.py`, `test_broker_price_aware_resubmit.py`.
- **Submission reliability:** transient failures retry up to `broker_submit_retries` (2) × `broker_retry_wait_seconds` (5 s); hard rejects never retry. A duplicate guard checks whether the errored attempt reached the broker before retrying. Failures persist as `SUBMIT_FAILED`/`STALE_CANCEL`/`SETTLE_*` rows. **Auto-reconnect:** every method gates on `_ensure_connected()` (cooldown 60 s). **Request timeout + sync watchdog:** `IB.RequestTimeout` (45 s) bounds every request; a `threading.Timer` watchdog around `_broker_sync` (600 s) logs CRITICAL + `os._exit(1)` on expiry (recovered by `--supervise`). Tests: `tests/test_broker_reconnect.py`.
- **Order types:** `broker_order_type` **`LMT`** — a marketable limit at the model price ± the session's cap (20 bp RTH / 80 extended / 150 overnight). Off-RTH overrides MKT to marketable LMT with `outsideRth=True`. Class-share tickers normalise both ways (`BRK-B` ↔ `BRK B`).
- **Execution measurement (persisted):** slippage (cost-normalized bps) + actual commissions per `sync()` to `broker_reconciles`/`broker_orders`, plus account NAV and IBKR's own `reqPnL` snapshot. Since 2026-08-31 every order-event row also carries **`bid_at_submit`/`ask_at_submit`** — the two-sided book `_quote_for` fetched for the LMT cap (previously discarded; stashed per ticker ≤120 s, cleared per sync) — so slippage decomposes into spread-crossing vs adverse drift. **⚠ THIS ACCOUNT HAS NO API ENTITLEMENT FOR LIVE US TOP-OF-BOOK** (verified 2026-08-31: error 10089 "requires additional subscription for API" at 03:24 overnight AND 09:04 pre-market, every name incl. SPY/ARCA — the "free Cboe One+IEX feed" in the `get_market_price`/`get_quote` docstring history applies to TWS desktop, not the API). Consequences: `get_quote` has likely NEVER returned a live book → `broker_spread_aware_limits` is inert (caps stay mid-based) and `bid_at_submit` stays NULL; `get_market_price` never wins → the IBKR leg of `_fetch_price` always yields to yfinance (and costs ~0.25 s of failed round-trip per priced name). **DELAYED data (reqMarketDataType(3)) DOES serve two-sided books free in-session** (probed 09:04 ET: AAPL 1.1 bp, FUN 349 bp pre-market half-spreads) — usable for spread WIDTH, never for price level. Fix = subscribe the US data lines in Client Portal → everything self-heals, no code change. All of this is visible in the log since the **ib_async→loguru bridge** (`ibkr._install_ib_log_bridge`, WARNING+; ib_async logs through stdlib `logging`, which had no sink here). Tests: `tests/test_ib_log_bridge.py`.
- **Sizing** (`sizing.py`): `notional` (default: `broker_base_notional` 2000 CAD → USD via live FX) or `equity_pct`, × the ledger's `position_size_multiplier`, with max-positions and max-gross-exposure caps (`BROKER_MAX_POSITIONS` 100 since 2026-08-19 — the SIM ledger has no position cap at all, so the broker cap is the binding one and hitting it silently diverges sim from broker; `broker_max_gross_exposure_pct` stays the real risk stop).
- **Idempotency:** `recommendation_id` is the IBKR `orderRef`; one broker order per client_ref (a duplicate is marked `DUPLICATE_REF_NOT_SUBMITTED`). A broker-health verdict and a price-provenance verdict each mirror `_assess_llm_health` → CRITICAL log + email banner + `🔔` subject tag.
- **Ops:** IB Gateway must run alongside the scheduler and needs a ~daily re-login (IBC). Before changing modes: `python -m src.broker.smoketest`, then `--order` for a 1-share round trip. **Gateway auto-recovery** (`broker_gateway_auto_restart` ON): when the gateway itself is wedged-but-alive or down, `maybe_restart_gateway` kills the java process owning `ibkr_port` and fires the `'IBC Gateway'` scheduled task. PAPER-ONLY (`ibkr_live` downgrades to a CRITICAL log); cooldown 30 min; fail-soft. It is armed by the WEDGE detector: `_note_request` counts consecutive request timeouts, `is_wedged()` trips at `broker_wedge_timeout_threshold` (5), `_ensure_connected` force-recycles the connection, and the auto-restart fires once `broker_wedge_recycle_limit` (3) recycles land inside `broker_wedge_recycle_window_seconds` (**3600**). **Three fixes on 2026-09-03, after a gateway sat wedged ~9 h with the recovery never firing** — each was individually sufficient to disarm it: `get_account()` no longer counts as evidence the gateway answered (it is served from the local ib_async cache, so it "succeeded" against a dead gateway and reset the counter every tick); a successful request no longer CLEARS the recycle history (only the consecutive-timeout counter); and the history is persisted to `cache/broker_wedge_recycles.json` (`ibkr.WEDGE_HISTORY_PATH`, atomic replace, stamps outside the window pruned on load) so it survives the process restarts the watchdog itself causes. Tests: `tests/test_broker_reconnect.py`, `tests/test_gateway_recovery.py`.

### Configuration

All settings live in `config/settings.py` as a `pydantic-settings` `BaseSettings` class. Every field maps to an env var (uppercase). Add new fields with defaults there; they become `settings.field_name` everywhere. **Never read `.env` directly — always go through `settings`.**

**Inert-config guard** (`tests/test_inert_settings.py`): fails on any NEW setting that is defined and documented but read nowhere (flipping it appears to work and changes nothing). A knowingly-inert setting must be listed in `KNOWN_INERT` and say so at its definition. Currently listed: `enable_combined_score_gate` / `min_combined_score_for_entry` (deliberately not wired — the ledger says a combined-score gate would block the LLM's best cohort) and `schedule_daily` (a legacy cron string). The guard exempts `*_long`/`*_short` names (resolved at runtime by `settings.directional`) and counts consumption by a `@property` on Settings. **Delete a retired knob rather than pinning it to a no-op value** — a pinned knob reads as live.
