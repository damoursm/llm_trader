## THE LIVE STRATEGY — the SELECTION SHORT makes every trade (from 2026-09-28)

User directive 2026-09-26: "Deploy the model with the half give-back with max hold of 15 days with all borrowable. Use it to make all trades and put all other models as shadow." Code `src/signals/sel_short.py` (`enable_sel_short`, settings `sel_short_*`), runbook `docs/SEL_SHORT.md`, tests `tests/test_sel_short.py`, evidence `memory/selection-model-exits-2026-09.md`.

- **Signal.** The intraday tail-regression selection model (`sel_models` `tailreg_long_400`: LightGBM fit on sessions ≤ 2026-04-30; 146 features = 85 base OHLCV/pivot-leg features of the 30-minute bar + 61 per-ticker deep features) ranks the universe — the 3,430 deep-store names with price ≥ $5 and a 20-session mean regular-hours dollar volume ≥ $5M (~2,150 a day, fixed at `--prepare`) — on EVERY regular-hours 30-minute bar. The bar's TOP-1 is taken when FRESH (a new high against its own scores over the previous 30 sessions, or fewer than 10 of them) and it is the name's first fresh pick of the day — `eval_metrics.selection_entries`' rule, pinned by a parity test.
- **Trade.** SHORT the pick only when it ROSE over the 5 sessions before (close vs the close at the same bar 5 sessions earlier), its live price is still above the target (`target_reached` otherwise), and IBKR can LEND it (≥ $10k available at ANY fee — `ibkr_borrow.short_block(max_fee_pct=None)`). Flat size: `sel_short_size_multiplier` (1.0) × the base order. No gate cascade, no sizing chain.
- **Exit.** Cover when HALF the run-up has been given back (target = close − 0.5 × (close − close 5 sessions before)), judged at each tick 10:00–16:10 ET (`sel_target`); otherwise at the same bar 15 sessions later (`sel_time`). No stop, no trail, no model exit.
- **Evidence.** 156 out-of-sample borrowable risers ≥ $5, net of the real NBBO spread on both legs, IBKR commissions and borrow: +11.3% per trade over 7.7 days, +1.40% per day. A May–September result (January to mid-May ~0 for every exit), ~200 trades, borrow priced at today's fees.
- **How it runs.** On every non-observe market-day tick `pipeline` launches the scorer as a SUBPROCESS (`sel_short.launch`): `--run --day D --bar k` for the latest completed regular-hours bar not yet run, or `--prepare` once from 09:00 ET (extends the deep 30-minute store through the previous session, fixes the day's universe, checks the session snapshot). A run fetches the day's bars for the universe from Polygon (from the store's last session when it is behind), rebuilds each series, computes the training features (`ml_model.features_30m_from_hlc` + `deep_features.serving_vector` from the pre-open snapshot; `ensure_snapshot` first rebuilds a missing or DEFECTIVE one — < 80% of the universe carrying a previous close), scores (~3 min, 6 processes), appends every score to the day's score file and journals the decision. The tick `wait`s (≤ `sel_short_wait_seconds` 480) before its trade step; `tracker.record_sel_short_trades` opens journaled picks ≤ 75 min old and `monitor_sel_short_positions` covers them. `busy.lock` (touched every 30 s, stale after 180 s) keeps one scorer at a time; a run never extends the store inline. Live scores equal the evaluation arrays' construction exactly.
- **Broker.** A sel_short entry the settle pass killed unfilled is re-anchored and resent every tick while its ledger row is open (the price-aware resubmit gate reads the legacy rank map and would strand it). Entry fill rates on SELLs: 69% RTH, 25% extended, 9% overnight.
- **Files** (`cache/ml/sel_short/`): `model.txt` / `model.json`, `universe/`, `prepare/`, `scores/` (the freshness history — never delete), `picks/<day>.jsonl` + `.consumed.json`, `runs/<day>_<bar>.json`, `busy.lock`; log `logs/sel_short.log`.
- **The legacy book** is flattened ONCE at the first regular-hours tick at/after `legacy_flatten_after` (2026-09-28 09:30 ET; marker `cache/legacy_flatten_done.json`); until then legacy positions keep the legacy exits (Performance, below). Legacy exits and signal reversal skip `entry_mechanism="sel_short"`.
- **Known gaps.** Entries execute at the tick's trade step, ~10–40 min after the bar (a 1–3 bar delay measured harmless); bar-12 picks (the 16:00 close) enter in the post-market; a bar whose tick never ran is never scored (its pick is lost, its scores missing from the history); the evaluation grouped runs by the bar's POSITION in the session, live groups by the CLOCK bar (they differ only for a name that did not trade in an earlier bar that session).

## Running the pipeline

```bash
python main.py                # Run once, console output only
python main.py --email        # Run once and send email report
python main.py --schedule     # Poll-loop runner
python main.py --supervise    # PRODUCTION (scripts/run_scheduler.bat): --schedule under an auto-restart supervisor
python main.py --dashboard    # Read-only monitoring dashboard (Plotly Dash via waitress)
python main.py --backfill     # Pre-warm OHLCV caches for the whole universe, then exit
```

**Slots** (NYSE market days): RTH every 30 min 09:30–16:00 ET; extended per `extended_windows` (`04:00-07:00@60,07:00-09:30,16:00-17:30,18:00-19:00@60,19:50-19:50`); overnight on the overnight venue's Sun–Thu nights (20:30, 21:30, 22:30, 23:30, 01:00, 02:00, 03:00, 03:30). Every slot is a full trading tick (`extended_hours_mode` / `overnight_hours_mode` = trade). An email goes out every slot (`SCHEDULER_EMAIL_EVERY_TICK=true`), plus `email_on_problem` on any broker/LLM/price health problem.

**Background slots.** EOD maintenance at/after 16:20 ET on market days, in a single-flight background thread (`runner._eod_work`: cache warm → `simulated_trades` retention → replay materialisation → walk-forward calibration → shape-history append → tier-2 backtest tail → IBKR BID_ASK spread-sweep subprocess; `eod_replay_refresh_days` 45; a still-running EOD at the next day's slot is skipped). The deep history refresh at 23:45 ET EVERY night incl. weekends (subprocess `python -m src.data.deep.refresh`, budget 14,400 s). The deep pre-open run at 08:30 ET on market days (`--profile preopen`, budget 2,700 s: the fast families, the 30-minute store through the previous session, the session snapshot). The auto-refactor (02:00) and the weekly ML retrain (Saturday 08:00) are HELD.

**Supervisor and watchdogs.** `--supervise` relaunches the scheduler when it exits; a HANG becomes an exit through the broker-sync watchdog (`broker_sync_watchdog_seconds` 600) or the whole-tick watchdog (`tick_watchdog_seconds` 2700); every tick-path yfinance call carries `timeout=30`. **To STOP a supervised scheduler, kill the `--supervise` parent FIRST, then the `--schedule` child. To restart, use `scripts/restart_all.ps1`** — never an ad-hoc `python.exe` (that is how duplicate schedulers appear). The scheduler's subprocesses (the sel_short scorer, the pre-open run, the deep refresh, the spread sweep) survive a scheduler kill by design: file logs and OS/heartbeat locks, never pipes.

**OHLCV caches.** `--backfill` is additive into `cache/ohlcv/` (daily, full depth from Polygon; weekly is resampled on demand). `--backfill-30m` warms the 30-minute TICK cache `cache/ohlcv_30m/`, capped at save time to `intraday_30m_max_bars` 3,380 (260 sessions × 13) — uncapped frames stalled ticks into the watchdog. The deep 2021→ 30-minute history is a separate store, `cache/ml/bars30m_deep/` (`python -m src.data.intraday_store --extend`; extended daily by the pre-open run and the sel_short prepare).

Logs → `logs/llm_trader_YYYY-MM-DD.log` (7-day rotation). To force a fresh run, delete `cache/news_*.json` / `cache/snapshots_*.json`. **Never delete casually:** `cache/ohlcv/`, `data/llm_trader.db`, `data/live_features/`, `data/ibkr_borrow/`, `cache/ml/sel_short/scores/`.

**Bars and prices.** The trailing NaN-Close bar yfinance appends is trimmed at parse time (`cache.trim_trailing_nan_bars` inside `load_ohlcv`) — scoring must never bypass `get_history` (`tests/test_scorer_contract.py`). Daily OHLCV feeding indicators is completed-bars-only (`market_data._drop_forming_bar`); marks and fills use LIVE prices (`tracker._fetch_price`).

**Sessions.** `market_calendar.current_session` → `rth | extended | overnight`, fixed per run; `enable_extended_signal_profile` is OFF (one weight profile in every session). `_execution_iso()` returns now in RTH, extended and the live overnight session and snaps closed venues to the next regular open; every entry stamps `entry_session`, every close `exit_session`, and costs are session-aware end to end. Overnight orders route to IBKR's overnight venue (`broker_overnight_routing`, LMT only, cap 150 bp; needs `BypassOrderPrecautions=yes` + `BypassRedirectOrderWarning=yes` in `C:\IBC\config.ini`); a refused overnight order is resubmitted at the 04:00 pre-market open.

## Architecture

### Pipeline flow (`src/pipeline.py`, `run_pipeline()`)

```
0.  Universe        — static watchlist + discovery (trending, screener, macro→holdings, catalyst/analyst/earnings,
                      related peers); the discovery gate drops junk, exotic types and names below the OBSERVATION floor ($1 / $1M).
1.  News            — RSS + press wires + FDA + per-ticker Google News (fresh every tick), NewsAPI, yfinance, Polygon (Benzinga),
                      Finnhub (background refresher), 8-K, Reddit, Quiver, analyst ratings, EPS, short interest, ticker events
                      → NewsArticle; the merged pool is URL-deduped and archived; per-ticker digests are cut by COMPANY-NAME
                      relevance and scored by the local Qwen. The IBKR borrow file is downloaded in the same pool.
2.  Snapshots       — Polygon batch (live + NBBO) → yfinance → grouped-daily close.
3.  Smart money     — insider / congressional trades, options flow, SEC filings; macro context (FRED, COT, VIX, MOVE, DIX,
    + macro           breadth, credit, bond / global macro, sector rotation).
3X. Regime & timing — Macro Regime Filter, Market Mode, Catalyst Timing.
3#. Scorers         — the weighted methods + the panel-first set, each in [-1, +1]; Massive technicals, fundamentals
                      (f_* factors), corporate actions.
4.  Aggregation     — the ML-stacker combine → TickerSignal (SHADOW).
5.  Recommendations — the rank rule (SHADOW: computed, gated, persisted, never opened).
5S. SELECTION SHORT — the ONE strategy that trades (subprocess launched at tick start; entries opened before the broker sync).
6.  Tracking        — ledger marks, the sel_short monitor, the one-shot legacy flatten, the legacy exits, the broker sync.
7.  Charts + email.
```

**Liquidity.** The OBSERVATION floor ($1 / $1M) admits names to scoring; the TRADE floor (Gate 4: `trade_min_price` $5 / `trade_min_dollar_volume` $5M, `pipeline._is_tradeable`, fail-closed via `is_liquid`) screens the shadow recommendations and defines the rank pool. The selection short applies its own floors (price ≥ $5, 20-session mean RTH $-volume ≥ $5M from the deep store). ONE dollar-volume definition everywhere else: `liquidity.dollar_volume` = the mean Close×Volume of the last 20 valid bars (`spread.adv_of` keeps its median-60 basis — the cost classes were fitted on it). The price floor reads the LIVE snapshot price AND the cached close; `is_exotic_security` runs at discovery and at Gate 4; the rank-pool build logs CRITICAL when < 25% of a ≥ 100-name universe clears the floor. Tests: `tests/test_trade_liquidity_gate.py`.

**Liquidity forecast** (`src/performance/liquidity_forecast.py`, ON): each universe name's ex-ante one-way execution deviation (bp) — the live Polygon NBBO (≤ 120 s, authoritative 90 min) → the IBKR BID_ASK sweep (scaled to point-in-time) → Corwin–Schultz / Abdi–Ranaldo → the class table — mapped through the fitted power law `a × spread^b`. Panel-first: persisted to `signals.exp_halfspread_bps`. Keep the two quantities apart: the MAPPED deviation (`expected_halfspread_bps`) is not the raw quoted book (`quoted_halfspread_bps`, live NBBO only, RTH basis — what Gate 4b reads). Tests: `tests/test_liquidity_forecast.py`. **IBKR BID_ASK spread sweep** (`src/performance/spread_sweep.py`): an EOD subprocess (clientId `ibkr_client_id`+50) → `cache/ibkr_spread.json`, rotating stalest first under a 900 s budget; works without paid market-data lines. `python -m src.performance.spread_sweep [--probe]`.

### Signals and the combine (SHADOW)

Everything in this section runs every tick and is persisted to the `signals` panel; it drives only the shadow rank rule.

- **Score-sign convention** (the invariant the combine, IC and inversion depend on): every method's sign is the predicted direction of the STOCK (+ up, − down); mean-reversion methods bake the reversal into the sign; |score| is confidence.
- **Weighted methods** (`aggregator._BASE_WEIGHTS`): news 0.40; tech, insider 0.30; sector_momentum 0.20; pattern, momentum 0.18; massive, put_call, oi_skew, money_flow, trend_strength, pead, ext_gap, mom_12_1, hi52 0.15; iv_rank 0.13; sent_velocity, max_pain, vwap, iv_expr, coint, st_reversal, ml_ohlcv 0.12; news_quiet, rsi2_rev, dloc_rev 0.10; news_bull_fresh, market_momentum 0.08; news_bear_fresh, catalyst_tilt 0.06; news_shock 0.04 (`broker_advisor` keeps a 0.10 weight but is OFF). **A weighted method needs FOUR registrations**: the base weight, an `_raw_active` entry (without it `_normalised_weights` gives it weight 0 while it scores, persists and ranks — `tests/test_news_quiet.py` pins it), `agreement.METHOD_FAMILIES`, and — to reach DIRECTION — `ml_stacker.STACKER_SIGNED_FEATURES`: the stackers are the combine, so a base weight alone reaches only coherence, `sources_agreeing` and the family votes.
- **The ML stackers ARE the combine** (`src/analysis/ml_stacker.py`, `ml_combine_arm_share` 1.0; the weighted camps are the per-side fail-soft, recorded per ticker in `combine_source`). Frozen 2026-08-24 logistic artifacts (`stacker_model_class`). 54 features: 31 SIGNED (the weighted method scores incl. `ml_ohlcv`, `tape_score`, the news family and `news_raw_score`) + 23 unsigned context (news mass / count, `atr_pct` / `bb_width_pct` / `vol_ratio`, an 18-class catalyst one-hot). Confidence and its factors are EXCLUDED (computed downstream of the combine; a test pins it). News features enter as the within-run centered rank over the Gate-4 pool (`stacker_news_basis="rank"`; `centered_rank_pooled` mirrors the aggregator's transform minus shaping), but serving dispatches on the ARTIFACT's `news_basis` stamp — the frozen artifacts stamp `absolute`. The news columns the panel mask cannot reach are masked at the news epoch (`enable_stacker_news_epoch_mask`). ⚠ `ml_ohlcv` (30-minute rows since 2026-09-19) reaches the frozen stackers at ~2.1× their training scale — retrain the stackers and `ml_exit` first when retrains resume. ML combine bands `ml_diff_threshold_long` / `_short` 0.0463 / 0.0374; `ml_raw_confidence_scale` 0.12 is self-calibrated as a SATURATION share (`src/signals/ml_scale.py`).
- **Rank basis** (`method_score_basis="rank"`): the combine consumes each method's CENTERED WITHIN-RUN RANK. Zeros abstain; a method with fewer than `method_rank_min_views` (5) non-zero views on tradeable names gets weight 0 for the run (override `news_quiet=3` — abstention is its mechanism — logged as `rank-thin this run`); ranks are over the Gate-4 pool with observe-only names interpolated; each method's percentile is payoff-shaped (`src/signals/rank_shaping.py`); bands `rank_diff_threshold_long` / `_short` 0.324 / 0.346, `rank_raw_confidence_scale` 0.642 — resolved ONLY in `aggregator._direction_bands` / `_raw_confidence_scale`. Consumption-time only: every persisted surface keeps the RAW score. An absolute-basis twin (`combined_score_abs` + buy/sell) rides every row.
- **Buy/sell split**: each method's effective view splits into BUY / SELL components averaged within its own camp; `combined_score` = buy − sell. The `f_*` factors and the 4 trend-predictability methods are additive overlays (`f_short_squeeze` excluded).
- **Agreement**: `METHOD_FAMILIES` rolls the methods into 7 information families; family votes and tape confirmation fold into confidence (`src/signals/agreement.py`).
- **Weighting and filters** (weights and confidence only): base → market-mode profile → win-rate adaptive → IC-informed (only methods with a pivot-basis IC t ≥ 2) → the OpEx max-pain boost. The win-rate hard filter (< 50% gross over ≥ 10 trades) and the per-SIDE filter and weights, which reach coherence, `sources_agreeing` and the family votes as well. Auto-inversion is on but `INVERTED_METHODS` is empty and the detector selects nothing. The market-relative hard filter drops only a significantly negative market-neutral ICIR. Per-method horizon states: PROVEN / DISPROVEN (dropped) / UNPROVEN (×0.5).
- **Multi-timeframe**: the 8 OHLCV methods on 30-minute, daily and weekly bars, blended 0.20 / 0.60 / 0.20 (`tf_blend_*`); the daily score stays in `*_score`, the others ride `timeframe_scores`.
- **Regime layers**: the Macro Regime Filter (PANIC blocks BUYs; RISK_OFF takes a ×0.5 size haircut; fails CAUTIOUS below 3 inputs), Market Mode (TRENDING / CHOPPY weight profiles), Catalyst Timing (earnings blackout, OpEx max-pain amplifier, 8-K + insider WATCH).
- **Panel-first (weight 0)**: `news_unpriced` / `news_unpriced_all` (measured harmful twice — accruing columns, not candidates), `squeeze`, `iv_term`, `avwap`, `resid_mom`, `vol_profile`, plus the `f_*` factors as overlays.

**The rank rule and the gate cascade** (shadow; `src/signals/rank_entry.py`, `enable_llm_synthesis` false): per run and per side, the direction band decides IF and the within-run rank of `combined_score` over the Gate-4 pool decides WHICH, capped at `gate1_rank_cap` (3) per side; provenance `rank` / `rank-v1`. `pipeline._apply_actionable_gates` then applies, attributing each drop to the first rejecting gate: Gate 2 (the PANIC BUY block), Gate 3 (the earnings blackout), Gate 4 (the trade floor), Gate 4b (live-book half-spread ≥ 12 bp → DEFERRED; no live book → pass), Gate 5 (BUY-only anti-chase: a 5-bar run-up > 12% → DEFERRED). Gates 1 / 1c read an LLM confidence and do not apply in rank mode (`gate_diag["gate1_mode"]="rank"`). Gates 3 and 4b are declared not simulable in the funnel. Tests: `tests/test_rank_entry.py`, `tests/test_actionable_gates.py`, `tests/test_gate_funnel.py`.

Truncation guards (`src/analysis/local_llm.py`): a pre-flight refuses an over-context prompt, and `check_reported` refuses an answer whose `prompt_tokens` lands at the context or below 0.85 of the estimate (`CHARS_PER_TOKEN` 4.0 — move the two constants together). Throughput ~0.5 calls/s. After any model swap run `python scripts/bench_local_sentiment.py --n 120` (parse / salvage rate, latency, modal collapse over NONZERO verdicts, INCONCLUSIVE below 30); the model id salts the verdict cache. Tests: `tests/test_local_llm.py`.

**The verdict.** Prompt **v7dir-2026-09-10** (`enable_direction_field`): rationale → catalyst → `direction` (UP | DOWN | NONE) → score; `sentiment.apply_direction` makes NONE abstain and gives a disagreeing number the stated direction's sign. A LEAN band (±0.01–0.10) keeps soft reads non-zero; 0.0 is reserved for nothing-connects or a nil remaining move. Each call carries a target header (name, industry, FUND flag), salted into the cache key. **Logprob expectation** (`src/analysis/logprob_score.py`, `enable_logprob_expected_score`, top-5): the expectation over the score's digit tokens REPLACES the argmax (refused past `MAX_SHIFT` 0.25; the argmax survives as `signals.news_argmax_score`). **Catalyst-class cap** (`apply_catalyst_cap`, `catalyst_cap_classes` analyst, `catalyst_cap_limit` 0.03; the sign is never touched) is applied ONCE in `analyse_sentiment`, after the direction, the logprob replacement and `fund_catalyst_override`; the cache stores the UNCAPPED verdict (the engine loop parses with `_parse_response_uncapped`). **Passing-mention abstention** (`passing_mention_abstain_share` 0.75): abstain when ≥ 75% of a digest names the target only in article bodies; `_passing_mention_share` returns None for names whose registrant name does not resolve (ARM, ADT…). **Parser hardening**: `"score": +0.15` is repaired (anchored on `"score"`); NaN / Infinity are refused, never clamped to ±1; `news_fetcher._parse_iso` always returns aware UTC. A parse failure and an abstention are the same observable — read raw responses before judging a "no view" rate. Tests: `tests/test_direction_field.py`, `tests/test_logprob_score.py`, `tests/test_catalyst_cap.py`, `tests/test_sentiment_parse.py`.

**Relevance and scaling.** Digests are cut from the pool by COMPANY-NAME relevance (`company_names.mention_evidence` tiers `symbol_explicit` > `name_phrase` > `symbol_word` > `name_token`, the last only to confirm a feed's own tag; search feeds' tags are confirmed at fetch by `news_fetcher._confirmed_tags`; `news_relevance_min_articles` 1; no evidence → `[]`, never the whole pool). Names come from the SEC list with a Polygon fallback; security types from the bulk Polygon sweep (`prime_security_types`); a REIT is not a fund (`industry_is_operating_trust`). `news` = the verdict × evidence MASS × source diversity, persisted at 6 decimals because the rank transform orders on it (an AST test pins it); residual ties are genuine evidence ties. ### Performance and the ledger

- **Per-trade return** (`tracker._pct_return`): cost-aware buy-and-hold (`cost_in` / `cost_out` = half-spread + commission; SELL mirrors BUY); open trades are marked live.
- **Costs per leg** (`spread.resolve_leg_cost`, `sim_per_trade_cost_attribution`): the leg's own fill → the same-tick average of fills in its liquidity class → the tick average → the time-of-day period average in its class (shrunk) → the period average → `_one_side_cost` (the calibrated real-fill overrides; the hand-built spread formula only on a fills-free database or for sub-minimum-price legs). Commission is a fee CEILING (`ibkr_fixed` max($1, $0.005/share), ×1.5). `calibrate_sim_costs` runs before each tick's mark and entry steps. Tests: `tests/test_cost_buckets.py`.
- **Short borrow carry** (`enable_short_borrow_cost`): SELL legs pay per CALENDAR day the fee IBKR quoted at entry (`borrow_fee_pct`), else `short_borrow_annual_pct` 3%.
- **IBKR borrow book** (`src/data/ibkr_borrow.py`): IBKR's public short-stock file (`ftp2.interactivebrokers.com`, user `shortstock`; shares available + annual fee for ~19,750 symbols) is downloaded in every tick's Step-1 pool and archived RAW in `data/ibkr_borrow/<ET date>/<HHMMSS>.txt.gz` (never delete — IBKR keeps no history); `borrow_at(ticker, when)` reads the file in force at any instant. Every NEW equity short is checked when opened (`enable_short_borrow_gate`): the selection short needs ≥ $10k available at any fee; the legacy entry paths also refuse a fee above `short_borrow_max_fee_pct` 50%/yr. No snapshot within 120 min → not checked (warned); futures / indices / FX / crypto are never judged. Tests: `tests/test_ibkr_borrow.py`.
- **Daily NAV** (`daily_nav.compute_compound_return`): a path-faithful daily walk over cached closes, capital-weighted per day and compounded; deterministic given the database.
- **Win rates are GROSS** (standing directive): a win is the right direction on raw prices (`tracker.gross_return_pct`, `is_gross_win`, `gross_win_rate`); costs live in the RETURN metrics only. Pinned by `tests/test_gross_winrate_convention.py`.
- **Self-calibrating parameters** share one idiom — prior → evidence → Bayesian shrinkage → clamps → fail-soft to the static setting — and report to the calibration registry (`src/performance/calibration.py` → the Data Quality tab).
- **Email performance** (`get_performance_for_email`): segment stats, the solo-method simulation and the method evaluation; `sel_short` trades carry no method scores, so they appear in no method row.

| Function | When | What it does |
|---|---|---|

**Legacy exits** (legacy positions only, until the 2026-09-28 09:30 flatten): `macro_regime_exit` (long in PANIC) → `confidence_loss` (the aggregator confidence below max(0.45, 0.55 × the entry confidence)) → `trailing_stop` (arms at 3% MFE, closes on a 50% give-back) → `adverse_stop` (long 8% / short 20% of the cost-adjusted mark) → `ml_exit` (every position, hold-conviction ≤ −0.35) → `close_trades_on_signal_reversal`. `signal_flipped` / `signal_decay` are SHADOW-ONLY (`signal_decay_exits_shadow_only`: stamped, never close). ### ML models

The installed artifact (2026-09-19) is trained on 30-MINUTE rows (11.6M rows, train_max 2026-06-01, label `hl1@30m`) and served at the last completed 30-minute bar through `_score_30m`: serving dispatches on the artifact's own `feature_bars` stamp and ABSTAINS (`BASIS_STALE`) when its `pivot_basis` differs from the one in force. Tests: `tests/test_follow_through.py`.

### Deep history store (`src/data/deep/`) and deep features

**The store** holds point-in-time external history: SEC filings + XBRL facts + Form 3/4/5 + 13F roll-ups + fails-to-deliver; Polygon extended-hours bars / short interest / short volume / dividends / splits / news + provider sentiment / delisted names / IPOs / ticker details; ALFRED macro vintages; yfinance indices / earnings / analyst actions / shares; Fama-French; DIX; COT; Wikipedia pageviews; Quiver congress / lobbying / contracts / dark pool. Layout: `cache/ml/deep/<family>/manifest.json` + `parts/<KEY>.parquet` + the consolidated `<family>.parquet`; `universe.json` (3,430 names). Parquet goes through duckdb (no pyarrow in the venv), with atomic replace everywhere. Every row carries its point-in-time key named for what it is (`acceptance`, `filed`, `filing_date`, `settlement_date`, `realtime_start`, `event_ts`, `grade_date`, `date`, …); feature builders filter `key <= as-of` first, because future-dated rows exist by design. CLI `python -m src.data.deep [family ...] [--status] ...`. Tests: `tests/test_deep_history.py`.

**Refresh** (`src/data/deep/refresh.py`). The nightly run extends each family's TAIL: per-ticker parts from their own newest key with an overlap, APPENDING only identities the part does not hold (stored rows are never rewritten); refetched series are UPSERTED — the store never loses a row it holds; only the current-state lists and the authoritative bulk files are overwritten (XBRL facts guarded against a > 10% shrink). Cadence per family in `refresh_state.json` (everything a feature reads is DAILY; a failed or budget-cut family is not stamped); Wikipedia runs last. The pre-open run re-fetches `PREOPEN_FAMILIES` FORCED, extends the 30-minute store (`extend_bars_30m`), then builds the snapshot; it fires only within the hour after its slot. Both hold an OS-level exclusive `cache/ml/deep/refresh.lock` and write stdout to a FILE (`logs/deep_refresh_console.log` / `logs/deep_preopen_console.log`), never a pipe — the refresh is routinely orphaned by broker-watchdog kills. `form345_live` never fetches TODAY (a partial day would freeze). `--sec-rate` 0.2 s nightly / 0.3 s pre-open under SEC's shared 10 req/s. `python -m src.data.deep.refresh --status`. Tests: `tests/test_deep_refresh.py`.

**Live Form 4** (`src/data/deep/form4_live.py`): the EDGAR daily index + submission files reproduce the bulk rows (`round2` = 2 decimals HALF-UP) and add the acceptance instant; a rate-limit 403 is backed off, never dropped. Tests: `tests/test_form4_live.py`.

**Deep features** (`src/analysis/deep_features.py`): 73 features in 17 groups under three rules — ONE knowledge cutoff per session (08:30 ET); every row's KNOWN-AT sized to when OUR store reliably holds it (`LAG_DAYS`); slow data enters as state + age + change, with an anchor price the bar features measure the move from. Fama-French is absent (the live value would always be missing). Served from `build_session_snapshot` → `cache/ml/deep/snapshot/<date>.parquet` (~150 s, 2.7 GB peak at 6 workers; `python -m src.analysis.deep_features --snapshot <date>`). The selection short reads it through `serving_vector`; `ml_model._score_30m` feeds it only to an artifact that lists deep features (the installed `ml_ohlcv` does not), abstaining `DEEP_PENDING` / `DEEP_STALE` with single-flight builds for today or the previous session only. A PRE-OPEN build gets its own session's position from `RTH.with_session` (appended bar-less when it is the session right after the grid's last; a grid that is BEHIND is left alone) — a fixture holding the session's own bars once hid that it was missing. Tests: `tests/test_deep_features.py`, `tests/test_ml30.py`.

### Key constraints

- **Polygon** (`src/data/polygon_client.py`) is the PRIMARY equity price source: snapshots with the live NBBO, bars, news, reference data. `_get` retries once on a transport error or 5xx (never on 403 / 404 / 429); a 403 is logged once per endpoint family. `to_polygon_symbol()` maps `BRK-B` → `BRK.B` at every per-ticker call site (the hyphen form silently returns nothing).
- **yfinance is structurally required** for what Polygon does not serve: indices (^VIX / ^MOVE / ^TICK — the Macro Regime Filter), futures, options chains, fundamentals / analyst / earnings. On a 429 it backs off 60 → 120 → 240 s and stops after 3 failures. `ENABLE_IBKR_PRICE_FEED=false`: this account has no API entitlement for live US quotes.
- **Two price paths.** The bulk snapshot feeds analysis, scoring and the price-provenance check (its NBBO comes from `lastQuote`). Execution prices come from `tracker._fetch_price` (RTH: Polygon last trade → yfinance; off-RTH: yfinance 1-min prepost → Polygon). Order books come from `reconcile._quote_for` (IBKR `get_quote`, which never answers here, → Polygon `/v2/last/nbbo`, refused past 120 s). The analysis / NAV anchor is the completed daily close.
- **Silent-default health monitors** (FX sizing rate, correlation sizing, regime / mode input coverage) surface as source-health rows.
- **SEC EDGAR**: 10 req/s shared (`_REQUEST_DELAY` 0.12–0.15 s; the ticker/CIK maps are populated once per process). **CFTC** COT ZIPs are 5–10 MB — check the cache first.

### Broker integration

`src/broker/` is the real execution leg beside the internal ledger ("shadow & reconcile"). Modes `off | dry_run | ibkr_paper | ibkr_live` (`broker_mode`, live: `ibkr_paper`, port 4002; the factory refuses paper on a known live port). Interactive Brokers through `ib_async` (imported lazily) → IB Gateway under IBC (`docs/DEPLOYMENT.md`).

- **`reconcile.sync()`** runs once per tick right after the entry steps, idempotent: **(0)** fill refresh by `orderRef`; **(0b)** tick-scoped order lifetime — unfilled orders are cancelled and their legs cleared; entries are resubmitted re-anchored through the price-aware gate (`broker_resubmit_max_adverse_bps` 100) EXCEPT `sel_short` entries, which are resent while their row is open; unfilled legacy entries are never sent while the selection short is live (`LEGACY_ENTRY_SHADOWED`); exits are never gated; **(0c)** cancel-on-close; **(1)** entries size the GAP against any same-side holding; **(2)** closed trades still holding a position are closed from the actual position; **(3)** drift → `broker_drift_action="flatten"` (never adopted into the ledger; `ibkr_live` always refuses auto-flatten); **(4)** settle — fill fast or kill (`broker_settle_seconds` 30, re-anchored every ~6 s).
- **Invariant**: no order works the book unless a ledger leg points at it — `_persist_legs` flushes after every submission, `cancel_order` cancels every order with a ref, a pre-submit duplicate guard, an orphan sweep, `reqAllOpenOrders()` on connect. Tests: `tests/test_broker_reliability.py`, `tests/test_broker_price_aware_resubmit.py`.
- **Reliability**: transient failures retry (`broker_submit_retries` 2 × 5 s); auto-reconnect (60 s cooldown); `IB.RequestTimeout` 45 s; the 600 s sync watchdog. Gateway auto-recovery (`broker_gateway_auto_restart`, paper only) is armed by the wedge detector: 5 consecutive request timeouts force a recycle, and 3 recycles within `broker_wedge_recycle_window_seconds` (3600) restart the gateway; `get_account()` (served from the local cache) never counts as an answer; the recycle history persists in `cache/broker_wedge_recycles.json`. Tests: `tests/test_broker_reconnect.py`, `tests/test_gateway_recovery.py`.
- **Orders**: marketable `LMT` at the model price ± the session cap — `broker_limit_cap_bps` 45 in RTH (spread-aware up to 400 with a live book), 80 extended, 150 overnight; off-RTH forces LMT + `outsideRth`; class shares normalise `BRK-B` ↔ `BRK B`.
- **Measurement**: slippage and commissions per sync to `broker_orders` / `broker_reconciles`, the account NAV and IBKR's `reqPnL`, and `bid_at_submit` / `ask_at_submit` (the Polygon book behind the cap). ib_async logs bridge into loguru at WARNING+ (`ibkr._install_ib_log_bridge`).
- **Sizing** (`sizing.py`): `notional` — `broker_base_notional` 2,000 CAD → USD at the live FX rate — × the ledger's `position_size_multiplier`; `BROKER_MAX_POSITIONS` 200 (CRITICAL logged once per sync when it refuses an entry — the ledger itself has no cap) and `broker_max_gross_exposure_pct`.
- **Idempotency**: `recommendation_id` is the IBKR `orderRef` (a duplicate is `DUPLICATE_REF_NOT_SUBMITTED`); broker-health and price-provenance verdicts raise a CRITICAL log, an email banner and a 🔔 subject tag.
- **Ops**: `python -m src.broker.smoketest [--order]` before changing modes.

### Configuration

All settings live in `config/settings.py` as a `pydantic-settings` `BaseSettings` class; every field maps to an env var (uppercase). Add new fields with defaults there. **Never read `.env` directly — always go through `settings`.** `config.settings.directional(name, direction)` resolves `{name}_long` / `{name}_short` overrides. **Inert-config guard** (`tests/test_inert_settings.py`): fails on any new setting that is defined but read nowhere; a knowingly-inert setting must be listed in `KNOWN_INERT`. **Delete a retired knob rather than pinning it to a no-op value** — a pinned knob reads as live.

## Standing rules

- **Evaluation** (`.claude/skills/evaluate/SKILL.md`, `/evaluate`; `src/analysis/eval_metrics.py`): the label is the next H/L pivot on 30-minute bars from the row's own tick (unresolved rows at the last visible close); the population is simulated / panel rows, never the trade ledger. MODELS: per-day Spearman IC, its day-clustered t, and the top / bottom 5 / 3 / 1% next-pivot returns (+ the selection objective per side where a model is trained on it). DECIDERS: the mean oriented return per decision against a matched counterfactual. The live strategy: its implementable exit net of real costs beside a volatility-matched control. House bar = paired t ≥ 2 AND same-sign halves, pre-registered. TWO test sets, reported separately, never pooled: set 1 = history, signal dates 2026-06-17 → 09-27 (news from the per-source rebuild); set 2 = the live all-source-news pipeline from 2026-09-28.
- **The pivot label** — ONE label, the next H/L pivot on 30-minute RTH bars (`pivot_label_basis="hl"`, `pivot_min_move_pct` 1.0; `pivot_basis()` = `hl1@30m`), for every decision surface and every ML model. The bar containing the tick is excluded; a date-only row anchors at its session's 16:00 close; the as-of cutoff applies per row through the pivot's CONFIRMING bar (never by rescanning a truncated series — `pivot_rows.pivot_fwd_row` memoises one scan per ticker); no 30-minute history → no label; unresolved rows never reach a training label. Fixed horizons remain for monitoring and holding periods. Tests: `tests/test_pivot_intraday.py`, `tests/test_pivot_target.py`.
- **A calibration may only fit data the CURRENT code produced.** Scorer epochs (`src/signals/method_epochs.py`: register CATEGORICAL changes only, at the ACTUAL restart instant) mask superseded scores in `signal_panel.build_panel`, `simulated_trades.load_sim_trades` and `compute_macro_eval`; they fail open, a freshly epoched method keeps full weight ("unproven"), and an epoch breaks test fixtures that borrowed the method's name. Replay (`src/analysis/replay.py`) regenerates the OHLCV-derived methods run-exact and time-aware (`--validate` after any scorer change); walk-forward (`analysis_asof`, `weight_history`) recalibrates per date; the tier-2 backtest (`signals_backtest`) tracks the CURRENT architecture with as-of shape curves (`shape_history`). Replaying DERIVED values (combine, confidence, gates) with today's weights is a backtest, never a calibration input. The auto-refactor (`refactor.py`: DATA → EPOCHS → WEIGHTS → DERIVED) is held off.
- **Significance tests are dependency-free** (`src/analysis/stats.py`): scipy is not a dependency, and an optional import guarding a verdict the system acts on is an invisible off switch.
- **Tests run against a pinned baseline, not production** (`tests/conftest.py`): an isolated DuckDB in a temp dir, spread-only costs, no network (Polygon quotes, the borrow download, gateway restarts off), every background pass off (the sentiment / synthesis shadows, catalyst repair, live feature capture, passing-mention abstention; the selection short off with its own temp dir), and LLM-era settings pinned (`method_score_basis="absolute"`, hosted engines on, the local LLM off, the hold review on). A test of production behaviour must set the production flags itself.
- **Silent channels**: use loguru — `logging.getLogger(__name__)` in `src/` is a handler-less sink (`tests/test_inert_settings.py::test_no_module_logs_into_a_silent_channel`). A mechanism whose failure looks like normal operation (an unread setting, an unreachable branch, a value computed but never stored, a constant duplicated across two sites) must be verified mechanically, never by review.
